Give your AI coding tool the few rules, hooks, and skills it actually needs — and nothing it doesn't.

Keep only the structure that helps you build better with an AI coding tool: a direction, a definition of done, and hard limits — not a script for work it can already decide how to do. One wizard installs a vetted set for your stack, scoped to your project.

npx -y @uzysjung/agent-harness

Node 20.12 or newer. Run it in your project folder; the wizard asks five things. Then open your tool in the same folder — claude, codex, opencode, or agy — and the rules and skills are live from the first session. No terminal? install --track <name> is the only required flag.

Why uzys-agent-harness

North star: keep only the structure that helps you build better with an AI coding tool. Every always-loaded instruction costs context in every session, so each one has to earn its place. Four beliefs follow from that; under each is what makes it real here.

1

As models improve, the harness should improve with them — usually by asking for less.

Here: an instruction stays always-loaded only while there is an observation that the agent is slower or wrong without it; otherwise it becomes an on-demand skill or is retired. audit-harness-fit runs that check on your project — needless questions, repeated checks, conflicting decisions, procedures a better model no longer needs — and proposes the edit.

2

An agent needs a destination and guardrails, not a prompt for every step.

Here: three skills on every track — north-star, objective-brief, gh-issue-workflow. The guardrails are few and mechanical: on Claude Code a hook blocks edits to .env, lock files, and certificates; a bundled script you run once applies a GitHub ruleset to your default branch; the anchor requires your approval for destructive or privileged actions, deployment, and shared-state writes. Inside those lines the agent decides.

3

Always-loaded context is a budget, so the harness keeps cleaning itself.

Here: step 4 of the wizard shows how much context your selection adds per session before you confirm. update refreshes what the harness installed, adds what a newer release introduced, removes rules and hooks a release retired, and names retired skills and agents still on disk rather than deleting them.

4

Different perspectives and different agents make better speed · cost · quality trade-offs.

Here: rules and skills render for all four CLIs from one source, so switching tools keeps the vocabulary. implementer (dev tracks) builds and reviewer verifies — an agent that did not write the code runs it and decides. multi-persona-review (dev tracks) critiques one artifact from several user perspectives. Opt-in: model-orchestration and external-model-consult, each via --with.

Compared with the alternatives

If you would otherwise…What is different here
Write your own CLAUDE.md or AGENTS.md Keep it — the harness adds one marked block and never touches the rest. Around it, the harness packages what a file alone does not enforce or maintain: hooks that actually block, a reviewer agent separate from the one that builds, and an install record so update and uninstall touch only what the harness put there.
Pick skills from a marketplace If one skill is all you need, take just that one: every skill here installs on its own with npx skills add. The wizard is for the set a skill list does not carry — standing rules, hooks, agents, and the record that keeps them current across releases.
Use a harness with many rules Fewer standing instructions, and step 4 shows their per-session cost before you confirm. The hard blocks are a hook on .env, lock files, and certificates (Claude Code) and the branch ruleset; everything else is the agent's call inside the anchor's approval boundary. For a fixed process, add openspec or bmad-method — both opt-in, compared in WORKFLOWS.md.

Evidence

What is measured so far comes from this repository, which is the harness's own dogfood and its only measured sample. In the last audit, none of the 44 sentences in our rules was observed to change an agent's behaviour — gates, tests, and the independent reviewer caught the recorded incidents — so protection against irreversible damage lives in hooks and rulesets, not in sentences, and the same audit retired four skills and three agents that had no observation behind them (ADR-090).

Treat this as dogfood evidence, not a cross-project benchmark: it does not yet show faster development, lower model cost, or better results in other projects.

Safe on an existing project

  • Your project only. Nothing goes to ~/.opencode/, ~/.gemini/, or global npm. Two opt-in exceptions write outside the project: Claude Code plugins (the claude CLI keeps its plugin cache under ~/.claude/plugins/), and --with-codex-trust, which adds one trust entry to ~/.codex/config.toml so Codex reads its project config.
  • Your CLAUDE.md stays yours. The harness adds one marked import block and never touches the rest.
  • Backups beside your files. Before replacing a file you edited, the harness writes a timestamped backup next to it and prints the path. Nothing you wrote or edited is deleted without a backup beside it, and your existing .mcp.json servers are merged, not replaced.
  • An install record, not guesswork. The harness keeps its own record at .uzys-agent-harness/, so update and uninstall touch only what the harness put there. uninstall never deletes .claude/, .codex/, or .opencode/: each is moved aside as <dir>.backup-<ts>.
  • Teammates do nothing. Cloned a repo a teammate set up with the harness? The install record is committed with the files. list shows it; update and uninstall work as on their machine.

The full list of what gets written where: USAGE.md.

What "vetted" means

An external asset is vetted when it has at least 1,000 GitHub stars, is not archived, and its install command has been run and checked in an isolated environment. Two monthly CI jobs re-check the stars and the install path. Vetting is not a line-by-line security audit and does not scan asset contents for prompt injection. npm and npx assets are pinned to a version; plugin and skill assets resolve to upstream HEAD.

At step 3, ★ official marks Anthropic-official marketplaces and this harness's own assets, and ⚠ experimental marks assets under 1,000 stars — never pre-checked, added only by you. Vetted assets carry no badge. Tiers inform; they never block. Treat installed assets like any other third-party dependency: SECURITY.md.
