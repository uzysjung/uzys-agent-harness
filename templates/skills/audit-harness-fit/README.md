# audit-harness-fit

현재 합의와 리포의 근거를 기준으로 에이전트 지침·스킬을 정비하고,
`AGENTS.md` / `CLAUDE.md`의 프로젝트 맥락을 채우는 스킬입니다.
후보 수를 제한하지 않고, 같은 원인을 묶어 영향도순으로 보고합니다.

## 디렉터리

```text
audit-harness-fit/
├── SKILL.md
├── README.md
├── references/
│   ├── audit.md
│   ├── verification.md
│   ├── apply.md
│   └── populate.md
└── evals/
    └── scenarios.yaml
```

`SKILL.md`는 진입점입니다. 감사, 검증 설계, 승인된 적용, 맥락 채우기별로
필요한 참조만 읽도록 구성했습니다. 이 README와 evals는 관리·검토용이며
일반 실행의 필수 컨텍스트가 아닙니다. 별도 실행 스크립트·모델 API 키·훅은 없습니다.

## 하는 일

| 영역 | 결과 |
|---|---|
| 불필요한 질문·반복 검증 | 실제 지연을 만드는 지시와 조건부 교체 문안, 유효한 근거 재사용 조건 |
| 지침 충돌 | 양쪽 원문, 충돌 상황, 확정된 현재 의도와 실제 구현, 수정안 |
| 과도한 원칙·불필요한 스킬 | 유지·수정·조건 축소·통합·이관·제거·보류 판단과 의존 관계 |
| 긴 결정 사유·히스토리 | 본문·메뉴에는 현재 지시만, 이력은 필요할 때 읽는 별도 문서로 참조 |
| 테스트·상위 모델 위임 | 사용자 사용 장면 → 구현 경로 → 충분한 검증, 필요한 판단만 조건부 위임 |
| 프로젝트 맥락 | 실제 리포로 기존 스캐폴드를 채우거나 갱신하고 미확정 정보는 그대로 표시 |

전체 감사는 다섯 감사 영역을 다룹니다. 특정 영역만 요청하면 범위를 확대하지
않습니다. 문제를 억지로 만들지 않으며, 결과가 많아도 임의의 상위 개수로 자르지
않습니다. 중요한 미확인 영역과 생략된 상세 내용은 따로 표시합니다.

## 사용

감사만 수행:

```text
audit-harness-fit으로 현재 적용되는 지침과 Skill을 전체 점검해줘.
후보 수를 제한하지 말고 중복을 묶어 영향도순으로 정리해줘.
원문·문제 상황·수정안과 확인/미확인 경로를 보여줘. 파일은 수정하지 마.
```

확인한 제안 적용:

```text
audit-harness-fit의 F-02, F-04 수정안을 해당 로컬 지침 파일에 반영해줘.
기존 승인 범위와 필수 보호장치를 유지하고, 추가 권한이 필요한 변경은 분리해줘.
```

프로젝트 맥락 채우기:

```text
audit-harness-fit으로 AGENTS.md와 CLAUDE.md의 미완성 프로젝트 맥락을
현재 리포 기준으로 채워줘. 공통 원칙·import·기존 사용자 내용은 보존하고,
핵심 사용 장면과 검증 기준을 연결해줘. 확인되지 않은 내용은 미확정으로 남겨줘.
```

기존 맥락을 갱신할 때는 "미완성 내용을 채워줘" 대신 "프로젝트 맥락을 최신
리포와 확정된 결정에 맞춰 갱신해줘"로 요청합니다. 일반 개발 요청마다 전체
감사를 실행하거나 스캐폴드를 자동으로 다시 채우는 방식은 사용하지 않습니다.

## 배치와 기존 저장소 반영

ZIP 최상위는 `audit-harness-fit/` 하나입니다. 전체 폴더를 사용하는 클라이언트가
인식하는 스킬 디렉터리에 배치합니다. 클라이언트별 로딩 경로는 실제 설정에서
확인하고, ZIP을 풀었다는 것만으로 등록·로딩이 완료됐다고 판단하지 않습니다.

사용자가 지정한 하네스 저장소의 배포 위치는 다음 형태로 반영할 수 있습니다.

```text
templates/skills/audit-harness-fit/SKILL.md
templates/skills/audit-harness-fit/references/...
```

기존 폴더와 먼저 비교하고 로컬 수정사항을 보존합니다. 덮어쓰기만으로 옛 파일이
삭제되는 것은 아닙니다. 예전 `references/official-criteria.md` 등의 기존 문서는
이 실행 경로에서 요구하지 않지만, 참조·테스트·이력 보존 필요를 확인하기 전에는
일괄 삭제하지 않습니다. 배포/로컬 사본이 있다면 저장소의 동기화 방식도 확인합니다.

기본 추천 설치는 기존 자산 ID로 유지하는 통합 작업입니다. 이 ZIP에는 설치기
코드 변경이 포함되지 않습니다. 설치 후 안내에는 스킬이 실제 설치된 경우에만
"이 스킬로 프로젝트 맥락을 채워 달라"는 문장을 연결하고, 기존 FILL 지시와의
충돌은 함께 정리합니다. 모든 요청에 붙는 자동 감사 훅은 추가하지 않습니다.

## 검토와 제한

[행동 시나리오](evals/scenarios.yaml)는 이 스킬을 개정하거나 특정 동작을 점검할
때 선택해 쓰는 합성 사례입니다. 별도의 자동 실행기나 실행 결과가 아닙니다.
일반 프로젝트 작업의 추가 테스트 게이트로 읽거나 실행하지 않습니다.

필수 테스트·독립 리뷰·보안·데이터 보호·배포 승인은 유지합니다. 감사는 읽기
전용이고, 명시된 범위의 수정만 적용합니다. 상위 모델 사용은 실제 도구·권한·
데이터·비용 조건이 허용할 때만 가능합니다. 모델의 판단은 테스트 실행 증거가
아니며, 사용 가능한 리뷰어가 없으면 필수 리뷰를 통과했다고 표시하지 않습니다.

폴더와 문서 형식 확인은 실제 클라이언트 로딩, 에이전트 행동, 설치기 연동 테스트를
대체하지 않습니다. 이 패키지만으로 GitHub 저장소나 사용자의 설치 환경을 바꾸지
않습니다.
