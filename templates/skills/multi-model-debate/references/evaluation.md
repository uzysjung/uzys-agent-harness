# 현행 모델에서 유용한지 확인하기

이 스킬은 모든 주제에서 단일 고성능 모델보다 낫다는 보장이 없다. 설치 시의 작은 동작 확인은
효과 크기를 검증한 실험이 아니다. 실제 사용 과제에서 품질과 총 비용을 함께 비교해 갱신한다.
매 요청에 벤치마크를 붙이지 않고, 방법 채택/큰 변경/모델 세대 변경 때 대표 작업으로 평가한다.

## 비교 설계

사용자에게 중요한 실제 과제를 고른다. 사실 판별, 제약이 있는 설계, 창작의 평가 기준을 섞어
단일 평균 점수로 덮지 않는다. 기법 튜닝에 사용한 과제와 최종 확인 과제는 가능하면 분리한다.

| 조건 | 의미 |
|---|---|
| A | 현재 접근 가능한 강한 단일 모델의 보통 수행 |
| B | 같은 강한 모델에 C와 비슷한 총 시간/토큰을 주어 자료 검증·수정까지 수행 |
| C | 실제로 서로 다른 2~3모델의 독립 제안 후, 교차 대화 없이 선택/통합 |
| D | 동일한 모델 구성을 독립 제안 → 쟁점 반박 → 실제 확인 → 필요한 수정으로 실행 |

A만 이겼다고 토론의 효과라고 결론내리지 않는다. B는 추가 계산량, C는 다양성/앙상블,
D는 교차 검토가 더한 가치를 구분하는 대조다. 자원이 제한되면 질문에 가장 가까운 비교부터
한다. 예를 들어 "토론이 필요한가"이면 C-D, "비용을 들일 가치가 있나"이면 B-D가 중요하다.
모든 조건을 매번 돌리는 것은 요구하지 않는다.

공통 brief·근거·도구 접근을 맞춘다. 모델명/날짜/추론 수준/문맥 길이/출력 제한/호출 수/지연을
기록한다. 웹에서 토큰·요금·백엔드 버전을 알 수 없으면 **근사 비교 또는 미확인**으로 남긴다.
숨은 계정 기억·검색 접근·자동 모델 라우팅이 다르면 통제 실험이라고 주장하지 않는다.

## 결과 평가

- 사실/코드: 외부 정답, 원문 대조, 실제 테스트, 중요한 결함과 회귀를 본다.
- 설계: 필수 제약 충족, 실행 가능성, 실패·복구, 근거 없는 가정, 사용자 목적을 본다.
- 글/창작: 실제 독자 또는 책임자의 익명 비교, 정확한 약속·톤·채택 가능성을 본다.
- 공통: 최초 답변 대비 해결한 문제와 **새로 만든 오류**, 미해결 위험, 비용·시간·사용자
  수정 부담을 함께 기록한다. 말이 길어지거나 동의율이 높아지는 것은 개선이 아니다.

평가자는 가능하면 조건/브랜드를 가린 결과를 본다. 모델 심판은 보조 수단이며 자기 계열
선호·순서 영향이 의심될 때만 순서 교환/다른 평가자로 확인한다. 심판이 충분히 강하다는
이유만으로 실제 테스트나 최종 사용자의 선호를 대체하지 않는다.

작업 변동이 크면 같은 조건을 몇 번 반복한다. 표본 수와 실패 사례를 공개하고 적은 사례의
승률을 보편 법칙으로 쓰지 않는다. 통계적 유의성/확률을 측정하지 않았다면 숫자로 꾸미지 않는다.
필요한 품질 개선·비용 허용폭은 사용 목적에 맞춰 미리 정한다.

## 범위 판정·복귀 동작 확인

주제 통제 절차를 바꿀 때는 지침에 특정 단어가 있는지만 검사하지 말고, 실제 brief와 응답을
주어 **무엇을 다음 모델에 보내고 최종 결론에 쓰는지** 확인한다. 독립 평가자에게 기대 판정은
주지 않는다. 관련성 판정과 사실 검증 결과를 따로 기록하고, 초기 원문과 판정 이유를 보존한다.

대표 사례에는 범위 밖 내용이 섞인 유효한 답, 제약 충족 불가능성을 지적한 소수 반례,
낯선 분야에서 온 관련 가설, 연결이 불명확한 제안, 발언마다 조금씩 목표가 바뀌는 대화,
복귀 뒤 반복 이탈, 예산 소진, 사용자의 실제 범위 변경을 포함한다. 최종 요약에 제외 내용이
다시 들어온 경우도 확인한다. 전부 매 사용마다 반복하는 체크리스트가 아니라 변경 시의 평가 범위다.

오류는 두 방향으로 본다: **무관한 주장을 전달·채택함**, **유용한 반례를 잘못 제거함**.
추가 호출의 필요성·예산 준수·미해결 상태의 정직한 보고도 확인한다. 복귀 1회는 실증된 최적값이
아니므로 비용과 복구 성공을 보고 조정할 수 있다. 작은 로컬 상황 검증을 실제 외부 모델의
장기 토론 성능이나 완전한 자동 차단의 증명으로 표현하지 않는다.

## 유지·축소·확대

D가 B/C보다 중요한 오류를 더 해결하거나 사용자 수정 부담을 충분히 줄이면 해당 작업군에
유지한다. 이득이 없으면 단일 모델 또는 독립 비교로 줄이고, 남은 어려운 쟁점만 토론한다.
효과가 큰 작업에서도 무조건 참가자/라운드를 늘리지 않고 추가 호출의 실제 기여를 확인한다.

최신 모델에서 더 단순한 지시만으로 충분한 결과가 나오면 절차를 줄인다. 과거 모델의 한계를
보완하던 역할극·고정 순서·긴 주의 문구를 관성으로 유지하지 않는다. 사용자 요구와 권한 경계,
실제 근거를 보존하는 조건에서 방법을 바꾼다.

## 간단한 기록 양식

```text
task / date / model labels / effort / tools:
comparison and controls:
required outcome and evaluation criterion:
initial result / final result / newly introduced errors:
actual checks / evaluator / unresolved limits:
calls / time / cost known-or-unknown:
decision: retain / simplify / targeted escalation / insufficient evidence
```
