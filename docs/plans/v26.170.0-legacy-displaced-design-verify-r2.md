## BLOCKER

### B3. N2 집단의 `AGENTS.md` 는 `recorded()` 가 `none` 이라 ④′ 쓰기가 첫 접촉(displaced) 으로 간다 — uninstall 이 옛 51절 파일을 "yours" 로 되살린다

**주장.** 설계 §4.3 는 ④′ 의 1회 백업 근거를 "기록이 `no-sha`(외부 기록 없음)라 … `owned-write.ts` 의 `owned()` 분기 그대로" 라 적었다(§11 ④ 도 같다). 이것은 **26.83~132 를 바로 update 하는 B 흐름에만 참**이다. N2 가 범위에 넣은 A 흐름(v26.169 로 한 번 update 해 `records: "writer"` · `externalFiles` 에 `.codex/*` · `portions` 에 `agents-md:*` 가 생긴 로그)에서는 `AGENTS.md` 가 **`none`** 이다.

**증거.** 프로브(`recorded(log, "AGENTS.md", { isTarget: () => true })`):
- fieldless 26.125 로그 → `no-sha` ✓(설계 §11 ④ 대로)
- 26.126~132 스캔 로그(`policyFiles` 있음 · `externalFiles` 없음) → `no-sha` ✓
- **N2 로그**(`records:"writer"` · `externalFiles: [.codex/config.toml, …]` · `portions: [AGENTS.md]`) → **`none`** · `recordedOwner(log)("AGENTS.md") === false`
  - 경로: `src/recorded.ts:191` `if (writer) return { state: "none" }` — writer 로그는 로그 수준 `no-sha` 를 내지 않는다(그 전에 `scanFieldOf` 가 `present` 라도 같은 결과).
- 그러면 `owned-write.ts:213` `firstContact = !baseline.has(rel) && !owned(rel)` 가 참 → 병합 결과 ≠ 디스크 → `backupFile` + `displace({ path: "AGENTS.md", change: "displaced", notes: [backup] })`(:230-236). 기록에 "설치자가 먼저 있던 파일" 이 적힌다 — 그 파일은 옛 하네스 31절 + `agents` 블록이다(`26.100.0-A/AGENTS-2.md`).
- 그 뒤 uninstall: `AGENTS.md` 는 `externalFiles` sha → 하네스 절 걷기 → ⓐ 설치자 절이 남으면 `restoreDisplaced` 가 `not put back — the spot is taken`(advise) ⓑ 남는 것이 없어 파일이 지워지면 **slot 이 비어 백업(옛 51절 파일)을 제자리로 되돌린다** — §0 둘째 행 "uninstall 뒤에는 설치자 절만 남거나 파일이 사라진다" 가 N2 집단에서 거짓이 되고, update 화면은 하네스가 쓴 파일을 `had a file with this name — … put back on uninstall` 이라 부른다.
- 설계 §7.1 테스트 ⑦ 은 "`AGENTS-2.md` update → 절 모델 · uninstall → 설치자 절만" 이라 ⓐ 변형만 보고 초록이 난다(advise 줄은 단언 밖) — ⓑ 변형(설치자 절 없음)이 없어 되살아남을 못 잡는다.

**고칠 문장(§4.3 `agentsMdModel` 행 · §11 ④).** "④′ · ②′ 가 참이면 `writeAgentsMd` 가 owned-writer 에 넘기는 `owned` 술어를 `recordedOwner(log)(p) || (p === AGENTS_MD && isLegacyHarnessAgentsMd(disk))` 로 넓힌다 — 머리 지문이 하네스가 쓴 파일이라 말하므로 첫 접촉이 아니라 `no-sha` 경로(`backup+overwrite` · "no checksum — saved a copy once" · 기록 = sha)로 간다. `rootFiles` 에 `displaced` 가 생기지 않는다." 테스트 ⑦ 에 두 단언을 더한다: "`rootFiles` 에 `AGENTS.md` displaced 없음" · "설치자 절이 없는 변형은 uninstall 뒤 파일이 **없고 되살아나지 않는다**(백업 1 만 남는다)". 변이: `owned` 의 OR 를 빼면 ⑦ red.

### B4. §4.2 의 1 MiB 상한 — "들지 않고 화면에 말한다" 는 백업 없는 삭제 경로다 (개정이 새로 연 것 · 1차 N12 의 예시 문구가 원인)

**주장.** §4.2 `holdSkillSlots` 행: 루트 전체 폴백(`--skill` 없는 소스, 카탈로그 1종)에서 "파일당 1 MiB 를 넘는 것은 들지 않고 화면에 `not held (over 1 MiB)` 로 말한다". 드는 이유 자체가 "도구가 폴더를 새로 만들며 지운다"(770b 리뷰 S5 실측 · §1.5) 이므로, 들지 않은 설치자 파일은 **도구가 지우고 아무도 되돌리지 않는다**. §9.2 ⑦ · §7.1 테스트("1 MiB 넘는 설치자 파일은 들지 않고 화면 한 줄")도 같은 뜻이다. 리드 완료 기준 "개정이 설치자 파일을 백업 없이 지우는 경로를 새로 열지 않았다" 에 걸린다. 누가 만드나: 그 소스의 스킬과 같은 이름의 폴더에 1 MiB 넘는 자기 파일(데이터 · 바이너리)을 둔 사람 — 드물지만 #780 자체와 같은 희귀도이고, 설계가 #780 을 "한 원칙" 이유로 유지했으니 여기만 예외일 수 없다.

**고칠 문장.** 상한은 **메모리 상한이지 보호 상한이 아니다**: "1 MiB 를 넘는 설치자 파일은 메모리에 들지 않고 호출 **전**에 `backupContent` 로 `<file>.backup-<시각>` 를 디스크에 쓴다. 호출 뒤 원본이 지워졌으면 백업을 원래 이름으로 rename(제자리 · 백업 없음), 원본이 그대로면 백업을 지운다, 덮였으면 백업을 남기고 `displaced` 로 적는다 — 메모리 경로와 결과가 같다. 화면 줄은 `not held` 가 아니라 결과 동사로." 테스트: 1 MiB 초과 파일이 도구 호출 뒤 제자리(바이트 동일) · 변이 "상한 초과를 건너뜀" → red.
