### 1.4 #782 — displaced 자리를 떠나는 remove 중 되돌리지 않는 것 (코드 확인)

`judgeDisplaced` 를 부르는 곳은 `commands/uninstall.ts:1909 restoreDisplaced` 하나이고 호출은 전량 · `--cli`(:1617)뿐이다. 하네스가 자리를 **떠나는** 나머지 remove:

| 경로 | 함수 | 되돌리나 |

| update 은퇴 회수(룰 · 에이전트 · 커맨드 · 훅) | `update-mode.ts:2646 pruneOrphans`(호출 :618) | 아니오 |

| install(`add` · `--reinstall`) 트랙 밖 룰 회수 | `installer.ts:687 reclaimOutOfTrack` | 아니오 |
| `uninstall --only <자산>` | `uninstall.ts:343 executeReverse` → `removeToolFiles`(:2293) — `assetsOnly` 라 `removeHarnessFiles` 를 타지 않는다 | 아니오 |
| update 의 번들 밖 파일 prune(#477) | `syncSkills` :2377 뒤 | **대상 아님**(v26.169.0 설계 N1 — displaced 로 적지 않는 약한 약속, 그대로) |

누가 이 상태를 만드나: 하네스 룰 · 에이전트 · 스킬과 같은 이름의 자기 파일이 있던 프로젝트에 깔아 `displaced` 가 적힌 뒤 ⓐ 그 자산이 은퇴하거나(가장 최근 은퇴 = #492 · ADR-090, 실재) ⓑ `--reinstall` 뒤 트랙을 바꾸거나 ⓒ 외부 스킬을 `--only` 로 빼는 경우. 드물지만 ADR-097 결정 3 이 "모든 remove" 를 약속했고 지금 코드 주석(`judge.ts` ~L230)이 그 미완을 적고 있다. **폐기 권고 없음** — 되돌리기 함수가 이미 있어 비용이 작다.

### 1.5 #780 — 외부 스킬 첫 추가 때 같은 이름 폴더의 설치자 파일 (리뷰 실측 · 코드 확인)

`installer.ts:1336` 과 `external-installer.ts:503` 이 부르는 `holdSkillSlots(projectDir, assets)` 의 입력은 **`previousLog.assets` 에 있는 자산의 기록 파일**뿐이다(`holdSlotFiles` 가 `files` 에서 슬롯을 유도). 처음 더하는 자산은 기록이 없어 아무것도 들지 않고, `npx skills add --copy` 는 폴더를 새로 만든다(770b 리뷰 S5 실측 "mine.md 가 백업 없이 사라진다"). 누가 만드나: 외부 스킬과 같은 이름의 폴더를 손으로 쓰던 사람 — 이슈가 말하듯 드물다. 그러나 #761 이 번들 스킬에 대해 같은 장면을 `displaced` 로 닫았으므로 외부 스킬만 예외로 두면 "한 원칙" 이 아니다. **폐기 권고 없음** — 변경이 `holdSkillSlots` 의 입력 한 줄과 settle 의 분기 하나다.

### 1.6 폐기를 권하는 부분 — 없음. 범위를 **좁히는** 판단 둘

- #781 의 **update 쪽**은 바꾸지 않는다. update 가 은퇴 스킬 · 커맨드 · 옛 앵커를 "지워도 된다" 로 안내만 하는 것은 ADR-089 · ADR-090 의 결정(기준선 없이는 편집 여부를 모른다)이다. 지문이 그 기준선을 주지만, 이번 사이클의 약속은 "빼면 깨끗이 빠진다" 이고 uninstall 이 기록 모양과 무관하게 지문을 보면 update 를 몇 번 거쳤든 결과가 같다(§1.2 A 흐름). update 가 바이트 그대로인 은퇴 스킬을 조용히 지우는 것은 별도 결정으로 넘긴다(§9 후속 ①).
- `.codex/hooks/*.sh`(옛 codex 변환이 렌더한 스크립트 — 템플릿과 바이트가 다르다)와 기록 없는 외부 자산(`find-skills` · `frontend-design`)은 이번에도 "not on record" 로 남는다(§9 위험 ①②).

### 8.1 ADR — 새 ADR 하나(ADR-111), ADR-097 을 Amends

필요한 이유: 지금까지 하네스 소유의 근거는 **기록**(ADR-097 결정 1)이었고 ADR-096 D6 는 "디스크 존재는 근거가 아니다" 를 못 박았다. 이 설계는 기록 밖에서 **두 번째 근거 — 옛 게시판의 바이트 그대로(닫힌 지문)** 를 더한다. 존재가 아니라 바이트이지만 결정 1 의 "하나" 를 둘로 만드는 것이므로 결정으로 적어야 한다(변경 관리 룰: 데이터 모델 · 보안 경계에 준함). ADR-097 결정 3 의 "모든 remove" 완성(#782)은 **새 결정이 아니라 이행**이라 ADR-111 의 Consequences 한 줄과 ADR-097 Status 줄의 보강으로 족하다.

# ADR-111: 옛 판의 하네스 바이트는 닫힌 지문 목록으로 식별한다 — 기록 밖 회수의 유일한 근거
- Status: Proposed → (PR-C 머지 때 Accepted)
- Date: 2026-10-12
- PR: PR-C(#774) · PR-D(#781)
- Amends: ADR-097(결정 1 "소유 근거 = 기록" 에 "+ 옛 판 바이트 그대로(지문)" · 결정 3 "모든 remove 가 되돌린다" 이행 완료) · ADR-089 · ADR-090(은퇴 자산의 처리 — update 는 여전히 안내만, uninstall 은 지문 일치면 회수)

## 11. 검증자에게 — 갈릴 수 있는 자리 · 미심쩍은 것 전부 (심각도로 거르지 않았다)

1. **지문 일치 = 백업 없음**(가정 2)이 ADR-097 의 뜻 안인가. "기록 sha 그대로" 와 "옛 게시판 바이트 그대로" 는 둘 다 "하네스 내용 그대로" 이지만 전자는 설치자가 그 자리에 둔 적 없음을 기록이 말하고 후자는 말하지 않는다(§2 #9). 사용자 결정 7("같은 내용이면 그대로 둔다 — 하네스 것으로 삼지 않는다", displaced-same)과 **정반대 방향**이다. 내가 가른 근거는 "displaced-same 은 기록이 '설치자가 먼저 있었다' 고 말한다, 지문 자리는 기록이 아무 말도 않고 자리가 옛 하네스 자리다". 이 구분이 약하면 대안 = 지문 일치도 `backup+remove`(백업 노이즈 40개 복귀) 또는 `leave` + "left by an older harness version" 로 **말만 바꾸기**(그러면 #781 은 화면 수정으로 축소된다).
2. **update 를 바꾸지 않는 선택**(ADR-111 ③, §1.6) — 이슈 #781 본문은 uninstall 만 말하지만 밀스톤 제목 "깨끗이 빠지고" 는 update 를 거친 설치본도 포함하고, 그건 uninstall 이 기록과 무관하게 지문을 보는 것으로 만족된다. 다만 **옛 은퇴 스킬이 update 뒤에도 매 세션 상주**하는 비용(ADR-090 의 "관측 없음" 자산들)은 그대로다 — 리드가 반대로 정하면 PR-D 에 `staleSkillDirs` 자리에서 지문 일치 디렉터리 삭제 한 분기가 더해진다(판정 함수 재사용, 추가 ~40줄).
3. **`.codex/hooks/*.sh` 입력 제외**(§3.1) — 실측 3판 모두 불일치라 뺐다. 더 많은 판에서 일치하는 판이 있을 수 있다(변환이 없던 초기 판). 뺀 것이 손해는 아니다(안 걸리면 남는다).
4. `extraTopLevelSections` 의 지문 필터를 **모든 후보 절**로 넓힌 것(가정 5) — PR-A 는 `replacedSections` 에만 걸었다. 왜 PR-A 가 좁혔는지 기록이 없다(리뷰 r2 에 사유 없음). 넓혀서 생기는 오판 = 설치자가 `## Project Rules` 밖에 옛 앵커 절을 **바이트 그대로** 옮겨 둔 경우 — 하네스 글이라 손실로 치지 않았다.
5. `installerSectionsInHarnessArea` 에 지문 필터를 더하면 **26.133~150 을 v26.169 로 update 해 꼬리 절이 sha 안에 든 설치본**도 uninstall 때 그 절을 잃는다 — 하네스 글이지만 설치자는 두 사이클 동안 그것을 자기 절로 봐 왔을 수 있다. 되돌릴 길: 그 절은 백업하지 않는다(지문 = 바이트 동일). 리드 판단 자리.
6. 블록 모델 → 절 모델 전환 때 **Project Context 가 채워진 경우**의 보존은 `mergeAgentsMd` 의 기존 이어받기(`installerLines`)에 기댄다 — 옛 파일의 `## Project Context` 본문은 스캐폴드 하위 절(`## Identity & Purpose` …)이 `## ` 로 들어 있어 `sectionBody` 가 "다음 알려진 절 이름까지" 로 끊는다(코드 주석 `agents-md-merge.ts:17` 가 그 이유). 테스트 ②(§7.1)가 이것을 본다 — 설계 레인은 실행하지 않았다.
7. 옛 `AGENTS.md` 전환의 **1회 백업**(`owned-write` `no-sha` 경로) — `recordedOwner(log)(AGENTS.md)` 가 26.83~132 로그에서 `no-sha` 인지 확인했다(`recorded.ts` 마지막 분기: `isExternalOnly` ∧ `externalFiles` 없음 → `absent` → `no-sha`). 그러나 `agentsMdModel` 이 `sections` 를 내도 `writeAgentsMd` 가 `params.baseline.has(AGENTS_MD)` 를 넘기는 자리가 둘(`baseline` · `owned`)이라 둘 중 하나만 바꾸면 블록으로 떨어질 수 있다 — 구현자가 `shared-write.ts:354` 의 호출을 그대로 두고 ④′ 만 더하면 된다는 것이 내 읽기다.
8. `holdSkillSlots` 의 두 루트 폴백(가정 7)이 **메모리를 얼마나** 드는지 재지 않았다. 설치자 파일만이라 작다고 봤다.
9. `buildAssetEntries` 에 displaced 경로를 넣는 것(§4.2) — 그러면 그 파일은 **자산의 파일**이 돼 다음 update 의 `holdSkillSlots` 가 "기록된 하네스 파일" 로 본다(옳다 — 지금은 도구 바이트다). 반대로 넣지 않으면 uninstall 이 그 자리를 못 비운다. 둘 사이에 셋째 길(자산 파일로 넣되 `displaced` 도 남긴다)이 내가 고른 것이다.
10. `--only` 되돌리기의 범위 술어(§4.1 — 지운 자산 파일의 앞 3마디 `<root>/skills/<id>/`)가 두 자리 사본(`.claude/` · `.agents/`)을 둘 다 덮는지 — `asset.files` 가 두 루트를 다 적는다(`snapshotSkillRoots` 가 둘 다 훑는다)는 전제.
11. **지문 생성기의 머리(preamble) 추출**은 "첫 `## ` 앞 줄 중 `# ` 로 시작하지 않는 줄" 이다 — 옛 템플릿의 머리에 빈 줄이 끼어 있어 정규화(끝 공백 · 끝 빈 줄)로 충분한지 실측 6판은 통과했지만, 설치자가 머리에 빈 줄 하나를 더하면 불일치 → `block`(안전한 쪽).
12. `LEGACY_HOOK_REFS` 에 **현행 훅 이름**(`hooks/session-start.sh` · `hooks/protect-files.sh`)이 들어 있다. ⓑ″ 는 "스크립트 부재" 조건으로 설치자 스크립트를 지킨다지만, 현행 install 의 `settings.json` 몫은 `portions` 로 기록되므로 ⓑ″ 는 **몫 기록이 없을 때만** 돈다 — 두 조건 중 하나가 빠지면 현행 설치본의 훅 줄을 건드릴 수 있다. 음성 대조 필수(§7.1 ③).
13. 옛 판의 `statusLine` 값 집합에 **현행 값**도 들어 있다(2종). 몫 기록 없는 설치본에서 현행 값이 있을 수 있는가 — 26.161 까지 `@latest` 였고 고정판은 writer 판이므로 사실상 없다. 들어 있어도 "몫 기록 없음" 조건이 지킨다.
14. 컨테이너 실측은 **`--cli claude --cli codex`** 한 조합이다. opencode 가 마지막 writer 인 옛 설치본(`codex+opencode`)의 머리 지문은 템플릿에서만 확인했다(6 키에 opencode 판 포함) — 실설치 대조는 리뷰어 매트릭스에 넣었다(§7.3).
15. 26.153~26.159(꼬리 없음 · 마커 없음 · 앵커 = 현행) 설치본에 대한 이번 변경의 영향은 **없어야 한다** — `isLegacyHarnessAgentsMd` 는 참(머리 지문 있음)이지만 이미 `externalFiles` 기록 → `sections`(③) 이라 ④′ 전에 끝난다. uninstall 걷기 필터는 걷을 절이 없다. 회귀 테스트는 PR-A 의 26.164 픽스처 외에 26.153 픽스처 하나를 더하는 것이 좋다.
