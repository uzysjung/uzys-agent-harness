### 1.5 #780 — 외부 스킬 첫 추가 때 같은 이름 폴더의 설치자 파일 (리뷰 실측 · 코드 확인)

### 1.6 폐기를 권하는 부분 — 없음. 범위를 **좁히는** 판단 둘

- #781 의 **update 쪽**은 바꾸지 않는다. update 가 은퇴 스킬 · 커맨드 · 옛 앵커를 "지워도 된다" 로 안내만 하는 것은 ADR-089 · ADR-090 의 결정(기준선 없이는 편집 여부를 모른다)이다. 지문이 그 기준선을 주지만, 이번 사이클의 약속은 "빼면 깨끗이 빠진다" 이고 uninstall 이 기록 모양과 무관하게 지문을 보면 update 를 몇 번 거쳤든 결과가 같다(§1.2 A 흐름 — N1 의 displaced 2건 제외). update 가 바이트 그대로인 은퇴 스킬을 조용히 지우는 것은 별도 결정으로 넘긴다(§9 후속 ①).
- `.codex/hooks/*.sh`(옛 codex 변환이 렌더한 스크립트 — 템플릿과 바이트가 다르다)와 기록 없는 외부 자산(`find-skills` · `frontend-design`)은 이번에도 "not on record" 로 남는다(§9 위험 ①②).

- 판정 명령(각 흐름 끝): `grep -rl MINE . --exclude-dir=.git`(표식 전부 라이브 또는 `*.backup-*` 에) · `find . -name '*.backup-*' | wc -l`(A·B 에서 **번들 자리** 지문 파일의 백업이 0 이고 **번들 밖** 지문 파일은 전부 백업이 있는가 — §2 #6; 26.125-B 기대 = 58) · `jq '.hooks' .claude/settings.json` · `grep -c '^## ' AGENTS.md` · 잔존 목록을 `check-files-coverage.mjs` 로 분류해 **지문 일치인데 라이브에 남은 것 = 0** 인가(단 §1.2 N1 의 displaced 2건은 A 흐름에서 남는 것이 맞다).

## 8. ADR 과 상주 문서

### 8.1 ADR — 새 ADR 하나(ADR-111), ADR-097 을 Amends

필요한 이유: 하네스 소유의 근거는 **기록**(ADR-097 결정 1)이고 ADR-096 D6 는 "디스크 존재는 근거가 아니다" 를 못 박았다 — **둘 다 그대로다.** 이 설계는 기록 밖에서 옛 게시판의 바이트 그대로(닫힌 지문)를 알아보되 그것을 **소유 근거로 쓰지 않는다**: 지문은 "다시 깔면 돌아오는 자리에서 백업을 생략한다" 와 "기록 없는 옛 판 바이트는 백업하고 치운다" 두 동작의 근거다. 그래도 설치자 디스크의 삭제 조건을 새로 세우는 것이라 결정으로 적는다(변경 관리 룰: 데이터 모델 · 보안 경계에 준함). 1차 설계는 "지문 일치 = 하네스 것 = 백업 없이 삭제" 였고 1차 검증(B1)이 그것이 사용자 확정 문장(2026-09-27)을 바꾸는 결정임을 지적해 사용자에게 올렸다 — **사용자 확정 2026-10-12, 선택지 ⓓ(절충)**. ADR-097 결정 3 의 "모든 remove" 완성(#782)은 **새 결정이 아니라 이행**이라 ADR-111 의 Consequences 한 줄과 ADR-097 Status 줄의 보강으로 족하다.

```
# ADR-111: 옛 판의 하네스 바이트는 닫힌 지문으로 알아본다 — 소유 근거가 아니라 "백업 생략" 과 "백업 뒤 치우기" 의 근거
- Status: Proposed → (PR-C 머지 때 Accepted)
- Date: 2026-10-12
- PR: PR-C(#774) · PR-D(#781)
- Amends: ADR-097(결정 1 "소유 근거 = 기록" 은 그대로 · 결정 3 "모든 remove 가 되돌린다" 이행 완료 · 결정 4 RETIRED_PATHS backup+remove 그대로 — 문구만 지문이 보강) · ADR-089 · ADR-090(은퇴 자산의 처리 — update 는 여전히 안내만, uninstall 은 지문 일치면 백업 뒤 회수)
- Context: v26.83~v26.161 설치본은 기록이 하네스 파일을 다 열거하지 못한다(설계 §1.1 표). 그 판의 바이트는 git 태그에 고정돼 있고 게시판과 같다(실측). 기록 모양에 따라 결과가 갈리는 것은 "한 원칙" 이 아니다(§1.2). 설계 1차안은 지문 일치를 하네스 것으로 삼아 백업 없이 지웠는데, 1차 검증(2026-10-12 B1)이 ① 그것이 사용자 확정 문장 "하네스 몫은 설치 기록 하나가 정한다" 를 바꾸는 결정이고 ② update 가 "yours / 지워도 된다" 라 부른 파일을 uninstall 이 묻지 않고 지우며 ③ 은퇴 자산은 다시 깔아도 돌아오지 않음을 지적했다. 사용자가 네 선택지(ⓐ 설계대로 · ⓑ 전부 backup+remove · ⓒ leave+안내 · ⓓ 절충) 중 **ⓓ 를 확정했다(2026-10-12)**.
- Decision: ① 소유 근거는 여전히 기록 하나다(ADR-097 결정 1 불변). 지문은 소유를 주장하지 않고 두 가지 일만 한다 — ⓐ 기록이 하네스 자리라 말하는 `no-sha` 자리에서 **현행 번들에 있는 경로**(`isRecordedTrackTarget` — 다시 깔면 같은 바이트가 돌아온다)이고 바이트가 지문과 같으면 백업을 생략한다 ⓑ 기록이 없는 옛 판 바이트 그대로의 파일 · `AGENTS.md` 절, 그리고 기록 자리이되 현행 번들에 없는 것(은퇴 자리)은 **백업하고** 치운다(파일은 `<file>.backup-<시각>` · 절은 파일 1회). 지문 불일치 = 설치자 것 — 기록 밖이면 남긴다. ② 지문 회수의 범위 = 기록의 CLI 집합이 그 자리를 쓸 때만(`ownersOf ∩ installedClis ≠ ∅`) — 하네스가 쓴 적 없는 자리는 읽지 않는다. ③ 지문은 생성기 하나가 git 태그 v26.70.0~v26.169.0(양끝 고정)에서 만든 모듈 하나이고 손으로 고치지 않는다 — 새 판은 쓰는 순간 기록하므로 늘지 않는다. ④ update 는 옛 은퇴 스킬·커맨드·옛 앵커를 지우지 않고 안내한다(ADR-089·090 유지) — "갱신" 이 설치자 디렉터리를 비우는 동작이 되는 것은 별도 결정이다. ⑤ #782: ADR-097 결정 3 의 "모든 remove" 를 `src/displaced.ts` 하나로 이행 — uninstall(전량·--cli·--only)·update 은퇴 회수·트랙 밖 룰·옛 Antigravity 앵커·install/--reinstall 의 같은 회수.
- Alternatives: ⓐ 지문 일치 전부 백업 없이(설계 1차안) — 사용자 확정 문장 변경 · update 화면("yours" · "지워도 된다")과 uninstall 이 서로 반대 말 · 은퇴 바이트는 번들에 복구 경로 없음 → 사용자 기각 · ⓑ 지문 일치 전부 backup+remove — 손실 0 은 같으나 현행 자리의 "no checksum — saved a copy" 노이즈가 그대로 → 차선 · ⓒ leave + "safe to delete" 안내 — 원칙 불변이지만 밀스톤 "깨끗이 빠진다" 미달 → 기각 · 경로 목록만(sha 없음) — 설치자가 같은 이름으로 쓴 파일을 지운다, 기각 · 내용 유사도/정규화 비교 — "설치자가 고쳤다" 와 못 가른다, 기각(PR-A NOTE-C) · 지문을 update 에도 적용 — 결정 ④ 로 보류 · 기록 이관 명령 — ADR-096 D3 와 같은 사유로 기각.
- Consequences: 지문 모듈 40,715 B 가 번들에 상주(dist 7.4%) · `recorded()` · `RETIRED_PATHS` 는 바뀌지 않는다 · 백업 노이즈가 는다(26.125-B 실측 기준 백업 28 → 58 — 전부 현행 번들에 없어 다시 깔아도 돌아오지 않는 바이트 · 그 안에 설치자가 잃는 것은 없다) · 현행 자리의 "no checksum — saved a copy" 는 26 → 12 · 설치자 파일이 우연히 옛 하네스 바이트와 같으면 번들 자리에서는 백업 없이(다시 깔면 돌아온다), 번들 밖에서는 백업 뒤 치워진다 — 번들 밖은 백업으로 디스크에 남고, 번들 자리의 옛 바이트는 옛 판 tarball 에만 있다 · PR-A(v26.169)의 53 앵커 절 걷기에 `AGENTS.md.backup-<시각>` 1회가 더해진다(전에는 조용한 overwrite) · `.codex/hooks/*.sh` 렌더본은 식별 밖(§9) · 루트 CLAUDE.md §설치자 디스크의 "아직 되돌리지 않는다" 예외 문장이 사라지고 지문 보강 한 줄이 더해진다.
```

## 9. 비목표 · 감수하는 위험

### 9.1 비목표(이번 범위 밖 — 한 줄씩)

1. **update 가 옛 은퇴 스킬 · 커맨드 · 옛 앵커를 지우는 것**(ADR-111 결정 ④). 지문이 근거를 주므로 기술적으로 가능하다 — 사용자 결정으로 올린다(후속 ①).
2. `RETIRED_PATHS`(45) · `RETIRED_HOOK_WIRING_REFS`(2) 를 지문 모듈로 흡수하는 것 — 뜻이 다르고 PR-D r2·r3 가 이미 검증한 경로다(후속 ②).
3. `.codex/hooks/*.sh` · `.codex/config.toml`(구간 없음) · `.mcp.json`(몫 기록 없음)의 옛 하네스 몫 — 렌더본 · 설치자 값이 섞여 바이트 지문이 없다. 지금의 "not on record" · remnant 안내 그대로.
4. 기록 없는 외부 자산(`find-skills` · `frontend-design` 옛 설치) — `noReverseHints` 안내 그대로(#573 결정).
5. 번들 밖 파일(#477 prune)의 displaced 기록 — v26.169.0 N1 약한 약속 유지(§13 ⑧).
6. 마커 있는(≥v26.160) `AGENTS.md` 의 sha 다름 → 통째 `kept`(#516) 규칙 — 손대지 않는다.
7. **#769**(`--cli codex` 가 Claude 링크 너머 `.agents/skills` 본문 회수) — 되돌리기 함수 추출과 무관. **#777**(옛 supabase `.mcp.json` 항목) — 함께 쓰는 파일 몫 식별이라 지문 축이 아니다(`PRIOR_MCP_SERVERS` 쪽). **#543**(트랙 단위 uninstall) — `restoreDisplaced` 가 범위 술어 `has` 를 받으므로 후보 집합만 넣으면 되는 모양이 된다(한 줄 득). **#513** — 무관.
8. `[BACKUPS]` 백업의 자동 정리 · 폴더 단위 백업 — 백업 규약(파일 하나 `<file>.backup-<시각>`)을 바꾸지 않는다. 노이즈 완화는 화면 묶음 줄(§4.4)까지.
9. **머리 블록인용이 없는 v26.151~v26.159 설치본을 설치자 편집 뒤 바로 uninstall** — 기록 sha 가 달라 #516 대로 파일이 통째 남는다(하네스 절 포함, v26.169.0 과 같음 · 손실 없음). update 를 한 번 거치면 절 모델 병합이 정리한다. 머리 지문 밖의 옛 파일 식별은 범위 밖이다(PR #789 손실 탐색 MEDIUM).

## 10. 가정(모호해서 정한 것 — 전부 뒤집을 수 있다)

1. 지문 입력 하한을 **v26.70.0**(PR-A 와 같은 하한)으로 — npm 게시 전 `npx github:` 배포판도 설치본이 있을 수 있다. 26.83 으로 좁히면 PR-A 53 앵커 중 4개가 빠진다(`check-anchor-compose` 실측) — 하한은 26.70 이어야 PR-A 와 합성된다.
2. **사용자 결정 ⓓ 의 "현행 번들에 있는 경로" 를 `isRecordedTrackTarget(log, alias(path))` 로 읽었다** — 기록 트랙의 manifest 가 그 경로를 쓰는가 = 다시 깔면 같은 바이트가 돌아오는가. 이 읽기에서 **`RETIRED_PATHS` 의 `no-sha` 자리(26.125-B 의 12건)는 번들 밖**이라 지금처럼 백업을 남긴다(ADR-097 결정 4 불변). 리드 브리프의 예시 "the recorded `no-sha` slot ⓑ" 를 **글자 그대로 "기록 자리면 전부 백업 없이"** 로 읽는 다른 읽기(R2)에서는 그 12건도 백업 없이 빠져 26.125-B 백업이 28 → 46 이 된다. 결정 문장의 기준("reinstall brings it back")에 맞는 쪽을 골랐다 — §11 ①.
3. `.agents/skills/<rel>` 의 `inBundle` 은 alias `.claude/skills/<rel>` 로 판정한다(현행 codex 설치가 같은 자리를 링크 슬롯으로 다시 채운다) — 26.125-B 의 현행 스킬 사본 3건이 백업 없이 빠지는 근거.
4. update 는 지문으로 지우지 않는다(ADR-111 결정 ④).
5. `AGENTS.md` 의 옛 하네스 파일 술어는 **머리 블록인용 지문 하나**다(절 비율 등 휴리스틱 없음). 머리를 지운 설치본은 지금처럼 `block`. 블록이 있는 파일은 블록을 걷은 본문으로 판정한다(N2).
6. 지문 필터를 `replacedSections` 만이 아니라 모든 설치자 후보 절에 건다(§4.3).
7. 옛 훅 줄은 "닫힌 목록 ∧ 스크립트 부재" 로만 걷는다(`RETIRED_HOOK_WIRING_REFS` 의 `evenIfScriptExists:true` 와 다르다 — 그쪽은 은퇴 스킬 폴더의 스크립트가 **계속 실행되는** 문제였고, 이쪽 8종은 현행 훅 이름이 섞여 있어 설치자가 같은 이름으로 자기 스크립트를 둘 수 있다).
8. `.mcp-allowlist` 는 전량 uninstall 에서만 회수(update 와 같은 백업 뒤 삭제).
9. `--only` 되돌리기는 PR-B 에 둔다(외부 자산 displaced 가 그 PR 에서 처음 생긴다).
10. 테스트는 생성기를 돌리지 않고 생성물의 알려진 양성·음성 · 집합 크기 · 머리 주석 범위만 본다.
11. 절을 떨어뜨린 `AGENTS.md` 쓰기의 백업은 **파일 1회**(절마다가 아니다) — 백업 규약이 파일 단위라서.

## 11. 검증자에게 — 갈릴 수 있는 자리 · 미심쩍은 것 (1차 검증으로 닫힌 것은 뺐다)

1. **ⓓ 의 "현행 번들" 읽기(가정 2)** — `RETIRED_PATHS` 의 `no-sha` 자리를 번들 밖으로 둬 백업을 유지했다(26.125-B 백업 58). R2 읽기(기록 자리면 전부 백업 없이, 46)로 바꾸려면 리드/사용자 한 줄이면 되고 코드는 `legacyFingerprintOf` 의 `inBundle` 분기 하나다. 어느 쪽이든 설치자가 잃는 바이트는 없다 — 갈리는 것은 노이즈 12건.
2. **update 를 바꾸지 않는 선택**(ADR-111 ④, §1.6) — 밀스톤 제목 "깨끗이 빠지고" 는 uninstall 이 기록과 무관하게 지문을 보는 것으로 만족된다(1차 검증 PASS). 다만 **옛 은퇴 스킬이 update 뒤에도 매 세션 상주**하는 비용은 그대로다 — 리드가 반대로 정하면 PR-D 에 `staleSkillDirs` 자리에서 지문 일치 디렉터리 백업 뒤 삭제 한 분기가 더해진다(판정 함수 재사용, 추가 ~40줄).
3. `extraTopLevelSections` 의 지문 필터를 **모든 후보 절**로 넓힌 것(가정 6) — PR-A 는 `replacedSections` 에만 걸었다. 왜 PR-A 가 좁혔는지 기록이 없다(리뷰 r2 에 사유 없음). 넓혀서 생기는 오판 = 설치자가 `## Project Rules` 밖에 옛 앵커 절을 **바이트 그대로** 옮겨 둔 경우 — 이제는 백업 1회가 남으니 손실은 아니다.
4. 옛 `AGENTS.md` 전환의 **1회 백업**(`owned-write` `no-sha` 경로) — `recordedOwner(log)(AGENTS.md)` 가 26.83~132 로그에서 `no-sha` 인지 확인했다(`recorded.ts` 마지막 분기: `isExternalOnly` ∧ `externalFiles` 없음 → `absent` → `no-sha`). `agentsMdModel` 이 `sections` 를 내도 `writeAgentsMd` 가 `params.baseline.has(AGENTS_MD)` 를 넘기는 자리가 둘(`baseline` · `owned`)이라 둘 중 하나만 바꾸면 블록으로 떨어질 수 있다 — 구현자가 `shared-write.ts:354` 의 호출을 그대로 두고 ②′ · ④′ 만 더하면 된다는 것이 내 읽기다. **N2 로 ② 를 좁히면서 블록을 걷은 본문을 병합 입력으로 넘기는 자리가 하나 더 생긴다** — 블록 안 내용(현행 렌더)은 `assemble` 이 렌더 골격을 다시 쓰므로 잃는 것이 없다는 것이 전제. 테스트 ⑦ 이 본다.
5. `buildAssetEntries` 에 displaced 경로를 넣는 것(§4.2) — 그러면 그 파일은 **자산의 파일**이 돼 다음 update 의 `holdSkillSlots` 가 "기록된 하네스 파일" 로 본다(옳다 — 지금은 도구 바이트다). 반대로 넣지 않으면 uninstall 이 그 자리를 못 비운다. 둘 사이에 셋째 길(자산 파일로 넣되 `displaced` 도 남긴다)이 내가 고른 것이다.
6. `--only` 되돌리기의 범위 술어(§4.1 — 지운 자산 파일의 앞 3마디 `<root>/skills/<id>/`)가 두 자리 사본(`.claude/` · `.agents/`)을 둘 다 덮는지 — `asset.files` 가 두 루트를 다 적는다(`snapshotSkillRoots` 가 둘 다 훑는다)는 전제.
