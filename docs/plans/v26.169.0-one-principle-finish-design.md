## 0. 설치자에게 무엇이 달라지나

| 누구 | 전 (v26.168.0) | 후 (v26.169.0) |
|---|---|---|
| **Claude Code 설치자 — `update` 를 돌릴 때** | 실행마다 `.claude/` 전체가 `.claude.backup-<시각>/` 로 복사된다. 아무것도 안 바뀐 실행은 사본을 지우지만(#556), 룰 하나라도 갱신되면 사본이 남는다 — 설치자의 `settings.local.json` · 자기 커맨드까지 실린 폴더가 쌓인다 | 폴더 사본이 **생기지 않는다**. 고친 하네스 파일만 `<file>.backup-<시각>` 으로 옆에 남는다(지금도 그렇게 하고 있다 — `update-backups.json` 이 그 목록이다). 화면의 `BACKUP` · `ROLLBACK` 행이 사라진다 |

| **`uninstall --cli claude` 를 돌리는 설치자** | `.claude/` 통째 이동 | 전량과 같은 규칙 — Claude 몫 파일만 하나씩 |
| **`--keep-templates` 를 스크립트에 쓰던 설치자** | 외부 자산만 빼고 폴더를 남긴다 | 플래그를 거절하고 **같은 일을 하는 명령**(`uninstall --only <이 기록의 자산 id 들>`)을 찍는다(ADR-097 §8 결정 6). 폴더가 더는 통째로 사라지지 않으므로 "남겨 달라" 는 요구 자체가 없어졌다 |
| **손으로 만든 스킬 폴더가 있는데 그 이름의 번들 스킬이 새 판 기본이 된 설치자**(#761 — #729 첨부를 손으로 복사해 쓰던 사람) | `update` 가 `SKILL.md.backup-<시각>` 을 남기고 하네스 판으로 덮는다. 화면은 "edited files … backed up" — 고친 적 없는 파일을 고쳤다고 한다. `uninstall` 은 하네스 판을 지우고 **원래 파일은 백업 이름으로 남는다**(찾아서 이름을 되돌려야 한다) | 같은 백업이 남고 하네스 판이 자리를 잡는 것은 **같다**(사용자 결정 7 — "업데이트된 버전은 덮어써야 된다"). 달라지는 것 둘: 화면이 `had a file with this name — saved as …`(편집이라 부르지 않는다)로 말하고, `uninstall`(· `--cli`)이 하네스 판을 지운 뒤 **원래 파일을 원래 이름으로 되돌려 놓는다** |
| **손으로 만든 스킬 폴더의 이름이 기본이 아닌(opt-in) 번들 스킬과 같은 설치자** | `update` 가 디스크에 있다는 이유로 그 폴더를 "깔린 것"으로 읽어 덮는다 | **건드리지 않는다** — 갱신 대상은 기록 + 이번 릴리즈의 기본(뺀 것 제외)이고 디스크 존재는 근거가 아니다(ADR-096 D6 · ADR-097 D1) |
| **v26.161 이하(몫 기록 전)로 깔고 `opencode.json` 의 다른 곳을 고친 OpenCode 설치자**(#747) | `update` 뒤에도 `mcp.chrome-devtools` 가 옛 값(통계 켜짐) 그대로이고 화면은 `kept yours` 라 한다 — 고친 적 없는 값을 설치자 것이라 부른다 | 하네스가 쓴 값 그대로인 서버는 **몫으로 알아보고** 새 값(`--no-usage-statistics`)으로 갈아 끼운다(`.mcp.json` 이 ADR-106 으로 이미 그렇게 한다). 그 서버 값을 **직접 고친** 설치자는 지금처럼 남되, 화면이 `usage statistics still on` 을 한 줄로 말한다 |
| **`AGENTS.md` 에 자기 절을 덧붙인 Codex · OpenCode · Antigravity 설치자**(#739) | 달라지는 것 없음(동작 불변) | 달라지는 것 없음 — "이 절이 설치자 것인가" 를 update 와 uninstall 이 **한 함수**로 판정하므로, 다음 수정이 한쪽만 바꿔 #736 같은 손실이 나는 길이 닫힌다 |
| **이미 `<dir>.backup-<시각>/` 이 있는 설치자** | `uninstall` 끝에 `[BACKUPS]` 로 나열 | 같다 — 지우지 않고 알린다(ADR-097 Consequences). `.claude/` · `.codex/` 안의 `<file>.backup-*` 도 같은 절에 나온다 |

**불변식(브리프)**: 설치자 파일은 어떤 경로에서도 백업 없이 사라지지 않는다 — §2.3 의 표가 항목 종류마다 이것을 보인다.

## 2. #746 — update 의 `.claude/` 복사 · uninstall 의 CLI 폴더 이동을 없앤다

### 2.1 누가 이 상태를 만드나 · ASIS → TOBE

- **장면 A(update)**: Claude Code 를 고른 설치본(`installedClis(log) ∋ claude`)에서 `update` 를 돌린다. 새 릴리즈가 룰 하나라도 바꿨으면 `.claude.backup-<ts>/` 가 남는다(#726 의 Docker D3 가 `[BACKUPS] .claude.backup-<ts>` 로 관측). 설치자가 한 일은 `update` 한 번뿐이다.
- **장면 B(uninstall)**: Claude Code 를 쓰는 설치자는 거의 다 `.claude/settings.local.json` 을 갖고 있다(권한을 한 번 승인하면 생긴다 — ADR-096 Alternatives 3). 전량 `uninstall` 또는 `uninstall --cli claude` 를 치면 그 파일이 `.claude.backup-<ts>/settings.local.json` 으로 옮겨져 **Claude Code 가 다음 세션에 권한을 다시 묻는다** — 설치자는 백업 폴더에서 자기 파일을 되찾아 와야 한다. Codex 설치자는 `.codex/config.toml` 에 더한 자기 MCP 서버를 같은 식으로 잃는다(라이브에서).

### 2.3 uninstall 쪽 — 항목 종류별 처리 (전량 · `--cli`)

## 5. #739 — `AGENTS.md` 의 "설치자 절인가" 를 update 와 uninstall 이 한 함수로

### 5.1 지금 두 판정이 어디에 사는가(확인)

| 경로 | 함수 | "하네스 것" 으로 보는 조건 | 그 밖 |
|---|---|---|---|
| update · install(병합) | `agents-md-merge.ts:311-358 extraTopLevelSections` | `names.has(name)`(템플릿 절 이름) ‖ `inHarnessRules && harnessRuleHeadings.has(bare)` ‖ `rendered.includes(bare)` ‖ `template.includes(bare)` ‖ `line === CONTINUOUS_SKILLS_HEADING` | 설치자 절 → 파일 끝에 되살린다(#643) |

두 함수가 **다른 입력으로 같은 답**을 낸다: 병합 쪽의 `rendered.includes` · `template.includes` · `CONTINUOUS` 조건은 "Project Context · Project Rules 안의 `## `(앵커 소제목 · 상시 스킬 안내)" 를 하네스 것으로 만들기 위한 것이고, 걷기 쪽은 그것을 **절(region)** 로 거른다. 지금 관측된 갈림은 없다(이슈 본문). 갈릴 수 있는 자리 하나 = `harnessRuleHeadings` 가 비었을 때(직접 호출 테스트 3파일 — `tests/agents-md-preserve.test.ts` · `agents-md-combined-update.test.ts` · `uninstall-agents-md-installer-sections.test.ts` 모두 그 인자 0건) 병합은 `rendered.includes` 로 룰 제목을 잡고 걷기는 못 잡는다.

### 5.2 바꾼다 — 동작 불변

- `agents-md-merge.ts` 에 **한 함수**: `headingOwner(bare: string, ctx: { region: string | null; names: ReadonlySet<string>; harnessHeadings: ReadonlySet<string> }): "harness" | "installer" | "body"` — `names.has` → `harness`(절 경계) · `region ∈ {Project Context, Project Rules}` → `body`(그 절 본문 — 소유는 `installerLines` 가 정한다) · `region === Harness Rules && harnessHeadings.has(bare)` → `harness` · 그 밖 → `installer`. `region` 은 호출부가 줄을 훑으며 넘긴다(두 함수 모두 이미 그렇게 훑는다).
- `extraTopLevelSections` · `installerSectionsInHarnessArea` 둘 다 자기 조건식을 버리고 이 함수를 부른다. 병합 쪽은 `harnessHeadings = harnessRuleHeadings ∪ headingsIn(rendered 의 Harness Rules 절)` 로 **지금과 같은 집합**을 넘긴다(`rendered.includes` 폴백 보존 — 테스트가 빈 집합으로 부른다) · 걷기 쪽은 `harnessRuleHeadings` 그대로. `template.includes` · `CONTINUOUS` 조건은 `body`/`names` 로 흡수된다(템플릿의 `## ` 는 전부 `names` 다 — `sectionNames:79-81`).
- 호출부(`shared-write.ts:357 mergeAgentsMd` · `uninstall.ts:1820-1832 agentsMdRemainder`)는 바뀌지 않는다.
- 테스트: #735(`tests/antigravity-anchor-retire.test.ts:317`) · #736(`tests/uninstall-agents-md-installer-sections.test.ts`) · #738(`tests/uninstall-cli-scope.test.ts` 해당 케이스) · `tests/agents-md-preserve.test.ts` · `agents-md-combined-update.test.ts` 전부 **그대로 green**. 새 테스트 1건: 같은 파일(설치자 절 셋 — Harness Rules 안 · Session Start 뒤 · 파일 끝)에 대해 병합이 되살리는 절 집합과 걷기가 남기는 절 집합이 같다(두 함수에 같은 `harnessRuleHeadings` 를 주고 비교). **음성 대조는 공용 함수가 아니라 호출부에 건다**(N2 — 리팩터 뒤 두 호출부가 같은 `headingOwner` 를 부르므로 그 안의 조건을 빼면 병합·걷기가 함께 바뀌어 두 집합은 여전히 같다): 걷기 호출부(`installerSectionsInHarnessArea`)가 `region` 을 넘기지 않게(항상 `null`) 바꾸면 #736 회귀 테스트(`tests/uninstall-agents-md-installer-sections.test.ts`)가 red 여야 하고, 동일성 테스트도 그 변이에서 red 인지 확인한다(두 호출부의 `harnessHeadings` 입력이 다르므로 Harness Rules 안 설치자 절에서 갈린다).

## 10. 가정 (모호해서 정한 것 — 전부 뒤집을 수 있다)

- **A1** `uninstall --cli X` 에서 외부 도구 산출물(`assets[].files`)은 `.claude/` 아래 것도 건드리지 않는다 — #528 "자산은 CLI 소속이 아니다" 를 `.agents/` 와 같게 `.claude/` 에도 적용(지금은 폴더에 실려 갔다). 설치자는 `--only <id>` 로 뺀다.
- **A2** `.opencode/` 는 어느 동작도 통째로 다루지 않고, 기록된 옛 커맨드 파일만 #1·#2 로 회수한다. `templates.opencodeDir` 는 더는 읽지 않는다(ADR-097 Consequences).
- **A3** `fs-ops.ts` 의 폴더 함수 넷을 **삭제**한다(남겨 두면 두 번째 사본). 되살릴 일이 있으면 git 에 있다.
- **A4** `.gitignore` 의 `.claude.backup-*/` 3줄은 이번 판에서 그대로다(이미 있는 백업 폴더를 계속 가린다 · 렌더 줄을 바꾸면 모든 설치본의 `portions` 가 흔들린다).
- **A5** `--keep-templates` 는 cac 옵션으로 **남겨 두고 거절**한다(모르는 플래그로 죽지 않게 · 대체 명령을 찍을 자리가 필요하다). 다음 마이너에서 옵션 자체를 뺀다(§13).
- **A6** uninstall 의 `judge(remove)` 에서 `.claude/` 정책·스킬의 `next` 는 `templates/` 의 같은 경로 바이트, `.claude/.installed-tracks` 의 `next` 는 `installedTracksText(log.spec.tracks)` 다(N5). 옛 로그 `no-sha` 판정은 그 바이트와 같으면 `remove`, 다르면 `backup+remove` — 설치자가 안 고쳤어도 릴리즈 사이 변경분이면 백업이 한 번 남는다(#557 의 "saved a copy once" 와 같은 뜻, 손실 없음).
- **A7** 엔진을 로그 없이 직접 부르는 테스트(`runUpdateMode(…)` with `logAtStart === null`)에서는 갱신 대상 선정을 지금의 디스크 판정으로 유지한다(CLI 경로로는 도달 불가 — #699). displaced 는 기록할 로그가 없으니 버린다.
- **A8** `.claude/.installed-tracks` 는 uninstall 이 `isTarget` 으로 알려 주어 옛 로그에서도 `no-sha` 로 회수한다(install 이 쓰는 방식과 같다, `installer.ts:1209`).
- **A9** `--cli X` 의 displaced 되돌리기는 X 의 소유 접두 아래 displaced 만 — 다른 CLI 자리의 displaced 는 그 CLI 가 떠날 때.
- **A10** #747 의 "하네스가 만든 파일" 판정은 `baseline.has("opencode.json")`(`externalFiles` 기록)이다 — `.mcp.json` 의 `rootFiles created` 에 대응하는 기록이 그것뿐이다.

## 11. 검증자에게 — 갈릴 수 있는 자리 · 미심쩍은 것 전부 (심각도로 거르지 않았다)

1. **ADR-097 §1.2 표의 `op: remove` 가 `kind: harness · rec none` 을 `leave` 로 낸다**(`judge.ts:182`). #477(번들 밖 스킬 파일 삭제)은 `none` 인 파일을 **지운다** — 표와 다르다. 이 설계는 #477 을 우선(원 설계 §2 행 4 가 그렇게 적었다)해 `syncSkills` 의 prune 분기를 judge 밖에 두었다. 검증 결과 **새 결정이 아니다**(원 설계 §2 행 4 · 사용자 결정 2026-09-20). 덧붙인 약속(N1 · 리드 결정): 번들 밖 파일(#477)의 백업은 `displaced` 로 적지 않는다 — 되돌리기 대상이 아니고, 화면 `pruned … saved as *.backup-<time>` 가 그 사실을 말한다(§3.1 표 행).
2. **update 의 갱신 대상에서 디스크 존재를 빼면**(§3.2 ⓐ) 옛 로그가 아니라 **writer 로그인데 기록이 빠진** 스킬(예: 기록 쓰기 실패 뒤 디스크에만 남은 하네스 스킬)은 더는 갱신되지 않는다. ADR-096 D6 · ADR-097 D1 의 귀결이고, `install` 한 번이 다시 적는다 — 화면에 그 길을 말할지(`⊘ .claude/skills/x present but not recorded — run install …`, ADR-096 Consequences 의 `.claude/` 안내와 같은 꼴) 는 정하지 않았다.
3. **A1**(`--cli claude` 가 `.claude/skills/<외부>` 를 남긴다) — 지금은 폴더에 실려 백업으로 가고 `assets[].files` 기록도 지워졌다(`settleCliLog:1151-1156`). 바뀐 뒤엔 남고 기록도 남아 `--only` 로 뺄 수 있다. 설치자에게는 "CLI 하나 뺐는데 그 CLI 자리에 스킬 사본이 남는다" 로 보일 수 있다 — 그래서 화면에 길을 둔다(§2.3 `--cli` 문단의 `left … remove with: uninstall --only <id>` 한 줄, N8).
4. **`.uzys-agent-harness/` 디렉터리째 삭제(A6 · #12)** 는 그대로 두었다 — "폴더 단위" 지만 하네스 전용이고 원 설계 A6 이 명시했다. 원칙 문장("폴더 통째 백업·이동은 하지 않는다")과의 관계를 검증자가 한 번 읽어 주면 좋다(이동·백업이 아니라 삭제이고, 설치자 파일이 들어 있으면 남긴다는 A6 조건은 아직 코드에 없다 — `settleLog:626` 은 무조건 `rm`).
5. **A7**(로그 없는 엔진 호출은 디스크 판정 유지) — 코드에 두 판정이 공존한다. 대안은 그 테스트들을 로그 있는 모양으로 고치는 것(범위 밖이라 하지 않았다).
6. **`updateDir` · `syncSkills` 의 `recorded()` 호출 비용** — 본문 구현 지시로 올렸다(§3.2 ⓑ · §2.3 `next` 문단, N4): 호출부가 `isTarget` 을 한 번 만들어 넘긴다.
7. **첫 접촉의 "같은 내용 → displaced(백업 없음) · 하네스 것으로 삼지 않는다"(Q3)** 를 `.agents/` writer 에 적용하면 `written` 에 넣지 않으므로 `externalFiles` 에 sha 가 안 실린다 — 그러면 다음 update 가 또 첫 접촉으로 읽고 `kept — already the same as the harness version` 줄이 **매 update 마다 반복된다**(N9 — ADR-097 Q3 대로라 결함이 아니다. 설치자가 그 파일을 지우면 다음 update 가 하네스 판을 만들고, 그대로 두면 매번 같은 줄. 구현 레인은 그 줄을 요약 행 하나로 묶어 반복이 화면을 늘리지 않게 한다 — 화면 규칙이지 결정이 아니다). 단 `.agents/skills/<id>/SKILL.md` 가 **그 CLI 가 깔렸다는 증거**로 쓰이는 자리(`writeBundledSkillDirs` — `SKILL.md` 를 담당했을 때만 형제를 쓴다)에서 `false` 를 돌려주면 형제 파일이 안 깔린다. 설계는 "같은 내용이면 `write` 가 `true` 를 돌려주되 기록만 안 한다" 로 읽어야 한다 — 구현 레인이 그 분기를 명시한다.
8. (삭제 — B5. PR-E 는 문턱 위로 확정, §8.)
9. **#747 의 "설치자가 만든 파일" 판정**(A10) — 옛 OpenCode 설치본에서 하네스가 `opencode.json` 을 만들지 않은 경우가 있는가? `opencode/transform.ts` 는 처음부터 이 파일을 썼고 `externalFiles` 는 v26.133 부터 기록됐다. v26.87~v26.132 사이 설치본은 기록이 없어 씨를 뿌리지 않는다(남긴다 — 안전한 쪽).
10. **`headingOwner` 의 입력 비대칭**(§5.2) — 병합은 `rendered` 의 룰 제목을 더 넘기고 걷기는 안 넘긴다. "한 함수" 는 맞지만 "한 입력" 은 아니다. 직접 호출 테스트 3파일에 `harnessRuleHeadings` 를 넘기고 폴백을 빼면 입력도 같아진다 — 동작 불변 조건 때문에 이번엔 안 했다.

## 13. 후속 (이번 범위 밖 — 한 줄씩)

1. update 의 은퇴 회수(`pruneOrphans` · 번들에서 사라진 스킬)가 displaced 자리를 떠날 때 되돌리기 — ADR-097 D3 "모든 remove" 의 나머지 반(`--reinstall` 의 기록 밖 회수 포함).
2. `.codex/config.toml` 옛 판(구간 없음 · 바뀜)의 통계 켜진 chrome 안내 한 줄(§4.4).
3. `collectPolicyHashes` · `collectSkillHashes` 삭제 — update 의 기준선을 "쓴 것만" 으로(원 설계 PR-5 잔여). #761 ⓑ 가 judge 로 쓰기를 옮기면 그 자리에서 sha 를 적을 수 있어 스캔이 불필요해진다.
4. `.gitignore` 렌더의 `.claude.backup-*/` 3줄 — 새 설치본에는 더는 필요 없다. 뺄 때는 `portions` 왕복(기록에 있는데 렌더에 없는 키 → 기록 sha 를 잇는다, ADR-099 R1)이 설치자 `.gitignore` 를 건드리지 않는지 먼저 본다.
5. `--keep-templates` 옵션 자체 제거(A5) — 한 마이너 뒤.
6. **#543(트랙 단위 uninstall)**: 이 설계로 uninstall 이 "기록 경로 집합 → `judge(remove)`" 한 함수가 되므로, 트랙 T 의 차집합을 **후보 집합**으로 넣기만 하면 된다 — 폴더 이동이 있던 동안은 불가능했던 모양이다.
7. `settleLog` 의 `.uzys-agent-harness/` 디렉터리째 삭제에 A6 조건(설치자 파일이 있으면 남기고 말한다) 코드화.
8. 번들 밖 파일(#477 prune)의 백업도 `displaced` 로 적어 되돌리기 — 이번엔 약한 약속으로 갔다(§3.1 표 · N1). 강한 약속이 필요해지면 그것이 결정 1건이다.
