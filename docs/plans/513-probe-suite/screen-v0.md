## 2. 하네스가 막지 못한 사고 — 없는 입력을 지어낸다

필수 입력 파일이 없는 함정에서 12회 중 **11회가 입력 파일을 지어내 결과를 만들고 완료로 보고**했다(두 등급 · 두 팔 모두).
멈추고 막혔다고 보고한 것은 GLM-5.3 A 1회뿐. 하네스 팔은 가정을 말한 시행이 있지만 결과 파일은 그대로 지어낸 값이다
(한 시행은 "실제 수치"라고 적었다). 배포 앵커 · 룰에는 "필수 입력이 없을 때 지어내지 말라"에 해당하는 문장이 없다
(`check-absence` 로 확인 — canary 통과, 매치 0). **하네스 개선 후보 1순위.**

## 4. B 재측정 (실행기 v1)

B 만 v1 으로 다시 돌렸다(66회, 무효 0, 고아 경고 0/66). A 는 v0 그대로(훅이 없는 팔이라 오탐과 무관) — 두 묶음은 실행 시각이
달라 시간 비교에는 서버 부하 차이가 섞인다.

| 등급 | 출력 토큰 B/A (중앙) v0 → v1 | 시간 B/A (중앙) v0 → v1 | 도구 호출 / 회 A · B v0 → v1 | 성공 A · B(v1) |
|---|---|---|---|---|
| GLM-5.3 | 4.01 → **2.04** | 2.86 → **1.43** | 8.0 · 13.2 → **10.5** | 31 · 30 / 33 |
| GLM-5.3-flash | 2.38 → **2.01** | 2.45 → **1.89** | 9.6 · 11.6 → **10.9** | 30 · 30 / 33 |

- v0 B 비용의 상당 부분(GLM-5.3 에서 출력 토큰 비율의 약 절반)이 측정 환경의 오탐이었다.
- 남은 B 추가분(회당): 점검 스크립트 0.5 · 하네스 파일 참조 0.3–0.4 · 스킬 열기 0.5–0.6(첫 3턴 안에 연 시행은 6–9% —
  슈퍼라이트 재분석의 6/6 첫 턴 개봉과 다르다. 작은 과제에서는 거의 안 열고, 연 것은 대부분 보고 단계) · 최종 보고 길이
  541 → 1,151자(GLM-5.3 중앙).
- **출력 증가의 대부분은 생각(thinking)이다**: 회당 생각 글자 수 중앙 A → B = GLM-5.3 1,458 → 7,482(5.1배) ·
  flash 2,412 → 7,605(3.2배). 본문 · 도구 입력은 1.1–2.6배. B 의 생각에는 하네스 용어가 거의 매 시행 나온다(31/33 · 33/33,
  A 17/33 · 21/33 — A 는 주로 과제의 `spec`) — 상위 빈도 `skill` · `delegat` · `model-orchestration` · `user-centered`.
  표본을 읽으면 4파일 이름 바꾸기에서도 "상시 스킬 목록의 model-orchestration 에 따라 위임할지"를 따지고, 테스트 범위 ·
  부재 확인 도구 사용을 숙고한다. **상시 스킬 안내가 작은 과제에서 위임 숙고를 매번 일으키는 것**이 첫 번째 토큰 개선 후보다.
