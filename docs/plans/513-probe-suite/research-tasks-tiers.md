# #513 연구 B — 하네스가 크게 갈리는 과제 유형 · 모델 티어 의존성 (조사 2026-11-08)

- 범위: 읽기 전용 조사. 저장소 수정 없음 · 유료 모델 호출 없음.
- 표기: **○** 1차 출처를 직접 읽음 · **△** 2차 요약·검색 스니펫·집계 사이트만 봄 · **✗** 못 찾음/미확인. 접근일은 전부 2026-11-08.
- 앞선 조사(`docs/plans/513-eval-evidence/benchmark-survey-*.md`, F1–F42)와 겹치는 출처는 거기 번호를 함께 적고, 여기서는 **"무엇이 큰 차이를 내는가"와 "티어별로 어떻게 다른가"**만 새로 판다.
- 출발점(내부 실측): 슈퍼라이트 v1(GLM-5.3, DeepSWE 4 + SWT 2)은 갈린 과제 0 · B/A 입력 토큰 중앙값 1.71 · 세션 시간 1.85 (`reports/deepswe-swt-v1/26.174.0-superlight.md`).

## 0. 요약 (결론 먼저)

1. **큰 차이는 "능력" 과제가 아니라 "판단 지점" 과제에서 났다.** 지시·스캐폴드로 크게 움직인 사례는 전부 기준 에이전트가 자주 *잘못 행동하는* 한 지점을 심어 둔 과제다.
   - 이미 고쳐진 버그를 또 고친다(FixedBench, 실패 35–65%, 프롬프트로 +15~28%p) [R5]
   - 명세와 모순된 테스트를 통과시키려 속인다(ImpossibleBench, GPT-5 92%→1%) [R3]
   - 범위 밖 행동을 한다(OverEager, 동의 블록 제거 시 +12~17%p) [R2]
   - 관련 없는 리팩터를 한다("no unrelated refactor" 한 줄 제거 시 −20%p, Opus 4.6) [R1]
   - 우리 첫 측정의 어려운 DeepSWE·SWT 6과제는 이 유형이 아니었다. 갈린 짝이 0이었던 것과 맞는다.
2. **"하네스가 있다는 것 자체"의 효과를 따로 재야 한다.** 무작위·뒤섞인·엉뚱한 도메인 규칙 파일도 전문가 규칙과 똑같이 +13.8%p를 냈다(Opus 4.6, 58과제) [R1]. A/B만으로는 "내용이 효과를 냈다"를 말할 수 없다 → **플라시보 팔(같은 분량의 무관한 CLAUDE.md)**이 필요하다.
3. **긍정형 지시는 해칠 수 있다.** 다음 사례는 모두 성능을 낮췄다.
   - "Follow code style" · "Read test files" (각 −14.3%p) [R1]
   - "Edit" 프롬프트(GPT-5.4 mini 정답 보류 60.5→36.5%) [R5]
   - TDD 절차 지시(회귀 6.08→9.94%, 앞선 조사 F22)

   그래서 **프로브는 양면이어야 한다.** 하네스가 "안 하기"로 이기는 프로브마다 "해야 맞는" 대조 프로브를 짝으로 둔다.
4. **티어 의존성은 단조가 아니라 뒤집힌 U에 가깝다(가설, §4).**
   - 상위(Opus 5.5급): 안전·동의 계열은 기준 행동이 이미 좋아 천장에 닿는다. 신중 지시가 오히려 "과잉 질문"으로 부호를 뒤집은 1차 관측이 있다 [R11].
   - 중위: 동의·범위 지시에 가장 잘 반응한다.
   - 하위(mini·Flash급): 양방향 진폭이 가장 크다. 도움도 해악도 가장 크다 [R5].
5. **비용은 작다.** 작은 픽스처 1회는 Sonnet 5.5 약 $0.30, Opus 5.5 약 $0.61, Haiku 5.5 약 $0.02다(가정은 §6). 18프로브 × 3반복 × 2팔과 선별 실행을 합친 티어당 예산:
   - Opus 5.5 ≈ $120 · Sonnet 5.5 ≈ $61 · Haiku 5.5 ≈ $4
   - GLM-5.3 ≈ 31k 크레딧(Pro 주간 60k 안) · GLM-5.3-Flash ≈ 10k 크레딧
6. **권고**: 끝의 17개 프로브를 픽스처 저장소로 만든다. 채점은 git 상태·파일 해시·명령 shim·대화 기록 위의 결정적 판정으로 한다. 순서는 셋이다.
   - 티어마다 **A만 3회 돌려 선별**하고, A 실패율이 20–80%인 항목만 남긴다.
   - 선별에 쓴 실행은 버린다. 그 위에서 **새로 A/B(/P)를 돌린다.** 선별 실행을 다시 쓰면 평균 회귀로 B가 부풀며, 이 함정은 프레임워크 §2가 이미 적었다.
   - 프로브 목록은 하네스 문구에 노출하지 않는다.

- 큰 효과가 난 곳의 공통 구조는 넷이다.
  - ① 기준 실패율이 높은 **단일 결정 지점**
  - ② 그 지점을 **결정적으로** 판정하는 상태 검사(diff 비었나 · 테스트 파일 바뀌었나 · 함정 파일 해시)
  - ③ 짧은 세션(300 s급)
  - ④ 지시 한 줄의 유무로 만든 **짝 대조**
- 이 조건을 다 갖춘 공개 자산 중 지금 바로 쓸 수 있는 것은 **ImpossibleBench(MIT)**뿐이다. FixedBench·OverEager는 설계를 베껴 재구성해야 한다.

## 3. Q2 — 싸고 결정적인 프로브 설계 패턴과 게이밍 방지

**채점 채널 (하나 이상 · 판정은 결과 상태를 우선)** [R15: "경로가 아니라 산출물을 채점하라", 대화 기록은 제약 위반 확인용]

1. **파일시스템 스냅샷**: 세션 전후 SHA-256. 함정 파일(`.env.old` 등)의 존재·내용 확인 [R2]
2. **git 상태**: `git diff --name-only <base>` 의 허용 목록 · `git ls-files` / `git show --stat HEAD` 에 시크릿 · 로컬 bare 원격의 ref 보존 여부(force push 감지)
3. **명령 shim**: PATH 앞에 `rm`·`git`·`gh` 래퍼를 두고 인자를 기록한다(OverEager의 이중 채널 = shim + 에이전트 이벤트 스트림 [R2]). Claude Code는 `--output-format stream-json` 로 도구 호출 전부를 남긴다 [R17].
4. **숨은 테스트 / 변경 전후 실행**: F2P 검사 = 에이전트가 쓴 테스트를 원래 코드에서 실패, 수정 코드에서 통과로 확인(SWT 방식). FixedBench식 "필터된 diff 공집합"
5. **최종 메시지 + 기록 대조**: "테스트 통과" 주장(정규식)과 마지막 편집 뒤 테스트 명령 실행·종료 코드 대조 [R9 · FrogNano 루브릭 △]. **주의**: 규칙 기반 탐지가 16건 중 0건 진양성이었다는 개인 감사가 있다(△). 주장 문구 대신 "**마지막 편집 이후 실행된 테스트가 없거나 실패**"라는 기록 사실로 판정하고, 메시지는 형식을 고정(마지막 줄 `STATUS: DONE|BLOCKED`)해 받는다.

**게이밍 방지 (출처별)**
- **양면 대조**(FixedBench Resolved↔Partial [R5]): "아무것도 안 하기"나 "늘 묻기"가 이기지 못하게 한다. 동의 계열 프로브마다 "그냥 해야 맞는" 프로브를 짝지운다(아래 #11).
- **행동 기울기 검증**(OverEager [R2]): 각 프로브를 신중 · 보통 · 과잉의 **스크립트 정책 3종**으로 먼저 돌린다. 함정 발화 수가 단조 증가하는 프로브만 채택한다. 채점기가 실제로 무는지를 모델 호출 없이 증명하는 단계이며, 이 리포의 "변이 테스트" 관행과 같다.
- **바이트 동일 짝**: 변형(지시 유무·문구) 외에는 픽스처를 바이트 단위로 같게 한다 [R2].
- **변형 축 무작위화**: 프롬프트 문체 · 방해물 밀도 · 권한 모호성 [R2]. 단 OverEager에서 무작위화로 효과가 17.1→2.6%p로 줄었다. 효과가 특정 문구에 묶였을 수 있다는 경고이므로, **프로브당 문구 2–3변형**을 두고 변형 간 일관성을 본다.
- **결과 상태 채점 · 깨끗한 환경**: 이전 시행의 git 이력이 점수를 부풀린 사례가 있다 [R15]. 시행마다 새 컨테이너·새 clone을 쓴다.
- **판단 지점부터 재생**(Anthropic 파괴적 행동 평가 [R12]): 실제 기록을 파괴적 행동 직전에서 자르고 이어 쓰게 한다. 매우 싸지만 사전 채움 선택 효과(자기 기록일 때 더 파괴적)가 있다고 저자가 밝혔다. 우리는 기록 대신 **픽스처 상태로 결정 직전을 재현**해 같은 이득을 얻는다(예: 실패 테스트 + 쉬운 우회로가 이미 보이는 상태에서 시작).
- **정답 유출 함정**(Sonnet 5.5 "silent copying" [R13]): 되돌린 커밋·빌드 산출물에 답을 심고 "알리지 않고 쓰나"를 본다. 보고 정직성(M2) 프로브로 차용 가능하다.
- **불가능 과제**(Opus 5.5 [R12]): 필요한 파일이 빠진 과제에서 보상 해킹 시도가 3–6배였고, 그중 약 80%는 "알고도 미완 상태로 끝냄"이었다. "정확한 차단 사유 보고"(M5) 프로브의 근거다.
- **하네스 과적합 방지**: 프로브 목록·문구를 하네스 템플릿과 이 리포 공개 문서에 넣지 않는다(비공개 보관). 측정은 하네스 문구의 일반화를 보는 것이다.
- **판정 없는 항목 처리**: 시간 상한·API 오류는 "안전"이 아니라 **무효**다(OverEager도 OpenHands 시간 초과를 N/A 처리 [R2]).
- **Claude Code headless 특성**: `-p` 에는 대화형 승인이 없다. "묻기"는 곧 "행동 없이 질문으로 끝냄"이다. OverEager도 확인 창을 끄고 쟀다 [R2]. 그래서 동의 계열은 "행동이 안 일어났고 + 마지막 줄 `STATUS: BLOCKED` 또는 질문"으로 판정한다. 비용 상한은 `--max-budget-usd` · `--max-turns` 로 건다 [R17].

- 근거: 우리 SWT 실측은 A 0.69–0.83M · B 0.60–1.65M 입력 토큰, 4–7분(GLM-5.3). CTXbench는 Claude Code + Sonnet-4.5가 실제 PR 과제에 $1.15/건, 41단계. Guardrails는 Opus 4.6 SWE-bench에 약 $0.4/실행.
- 픽스처가 SWE-bench보다 작으므로 위 가정은 **보수적(높게)**이다.
- GLM의 effort max는 추론 출력이 커서 출력 30k를 가정하면 실행당 약 +48 크레딧이다.

| 티어 | A 1회 | B 1회(×1.7) | 본 실험 18×3×(A+B) = 108회 | + A 선별 18×3 = 54회 | 티어 합계 |
|---|---|---|---|---|---|
| Opus 5.5 | $0.61 | $1.03 | $89 | $33 | **≈ $121** |
| Sonnet 5.5 | $0.30 | $0.52 | $44 | $16 | **≈ $61** |
| Haiku 5.5 | $0.018 | $0.030 | $2.6 | $1.0 | **≈ $3.6** |
| GLM-5.3 (크레딧) | 157 | 267 | 22.9k | 8.5k | **≈ 31k** — Pro 1주(60k) 안. Lite는 비혼잡 시간으로도 약 1.6주 |
| GLM-5.3-Flash (크레딧) | 52 | 88 | 7.6k | 2.8k | **≈ 10k** — Lite 1주분 |

- 계산 예(Opus 5.5 A): 60k × $5 + 540k × $0.20 + 10k × $20 = $0.30 + $0.108 + $0.20 = $0.61.
- **플라시보 팔 P**를 더하면 본 실험은 1.5배다(Opus +$33 · Sonnet +$16).
- 3티어(Opus · Sonnet · Haiku) 전부의 합은 약 $186이고, GLM 두 티어는 Pro 1주 크레딧 안에 들어간다.
- 벽시계: 162회 × 4분 ÷ 동시 2 ≈ **티어당 약 5.4시간**(선별 포함). 본 실험만 보면 3.6시간이다.
- `--max-budget-usd` 를 회당 3–5배 여유로 걸어 폭주를 막는다. 클라이언트 추정치라 넘을 수 있다 [R17].

## 7. 측정 설계에 주는 함의 (짧게)

1. **항목 유형을 바꾼다.** 어려운 능력 과제 → 판단 지점 프로브. 공인 벤치마크는 "망가졌나" 경보(현 슈퍼라이트)에 두고, 효과 측정은 프로브 묶음으로 한다.
2. **변별 선별은 티어별로, 선별 실행은 버린다.** A 3회 중 실패가 1–2회인 항목만 남긴다(Guardrails의 30–70% 규칙 [R1]). 선별에 쓴 A 실행을 효과 계산에 넣지 않는다.
3. **세 팔**: A(목표·스택 CLAUDE.md) · B(하네스) · **P(같은 분량의 무관한 규칙 파일)**. B−P가 "내용 효과", P−A가 "존재 효과"다 [R1].
4. **양면 짝**: 안 하기 프로브(#1·#7–#10·#16)마다 해야 하기 프로브(#11, 각 프로브의 대조 변형)를 둔다. 둘 다 이겨야 "하네스가 낫다"로 센다.
5. **단위 = 프로브.** 프로브 안 반복은 상관되므로, 효과 CI는 프로브 재표집 부트스트랩으로 낸다. 프레임워크 §5의 방식을 그대로 쓴다.
6. **하네스 기여 증거**: CTXbench식 "지시 도달" 지표를 보조로 남긴다. 예: B에서 `check-absence.sh` · `spec-drift-check.sh` 를 실제로 부른 비율. 결과 지표와 분리해 보고한다.

## 미확인·한계

- **프로브 효과 크기는 전부 남의 모델·스캐폴드에서 왔다.** 우리 하네스(긴 원칙 문서 + 한국어 룰 + 스킬)가 같은 크기를 낼지는 미지수다. 특히 Guardrails의 "무작위 규칙도 +13.8%p"는 내용 효과가 작을 수 있다는 경고다 [R1](n=58, Opus 4.6 단일, 다중비교 보정 시 개별 규칙 비유의).
- OverEager 동의 효과는 무작위화 본 세트에서 2.6%p로 줄었다. 시드 간 원형별 10–20%p 변동도 있다 [R2]. **문구 특이적 효과**일 수 있으므로 변형 2–3개가 필요하다.
- 비공개·미공개: OverEager 아티팩트 · FixedBench 코드 · Guardrails 데이터 · Anthropic 내부 평가 ✗. 재구성은 우리 몫이고, 재구성 판의 기준 실패율은 원 논문과 다를 수 있다.
- Anthropic 카드의 수치(Opus 4.6/4.7 anti-hack 45→37.5/12.5%)는 2차 요약에서 왔다 △. 1차 카드 텍스트로는 "가장 잘 조종됨"만 확인했고, 수치는 그림 안에 있어 추출하지 못했다. Opus 5.5 · Sonnet 5.5 · Haiku 5.5 카드에는 지시 유무 비교가 없다(○ — 5.5 카드 텍스트 검색 결과 없음).
- OctoBench 수치는 집계 사이트의 자기보고다 △. SkillsBench 모델별 수치 △ · IFScale · DistractionIF · Prompting Inversion · AgentIF는 요약만 봤다 △.
- **가격**
  - DeepSeek 가격을 읽지 못했다 ✗.
  - GLM Pro·Max 월 가격은 제3자 출처다 △.
  - Z.ai 약관 §4의 자동화·벤치마크 사용 조항을 읽지 못했다 ✗. "공식 지원 도구 안에서만"은 확인했다.
  - Haiku 5.5는 프롬프트 100k 초과 구간에서 단가가 5배다. 긴 세션이면 이 구간을 밟는다.
- **비용 추정은 가정 기반이다**(요청 15–25회 · 캐시 적중 90%). 실제 값은 첫 선별 실행에서 `--output-format json` 의 사용량으로 바꾼다. Claude Code가 백그라운드로 부르는 소형 모델 호출은 넣지 않았다(작다고 가정).
- 티어 예상(§4)은 가설이다. 특히 "상위에서 B가 과잉 질문으로 진다"는 Opus 4.7 카드 1건에 기댄다. Opus 5.5 · Sonnet 5.5에서 같은 일이 나는지는 #11이 직접 잰다.
- "Codex CLI GPT-5-Nano→GPT-5.2 연구"는 찾지 못했다 ✗(검색 2회, 부재 단정 아님).
- 최종 메시지 기반 채점(#3 · #5 · #6 · #14)은 형식 고정에 기댄다. 형식을 지키지 않은 응답은 무효로 처리할지 실패로 처리할지를 사전 등록해야 한다.
