## 2. 과제 유형 — 판단 지점 하나

어려운 능력 과제가 아니라, 기준 에이전트가 자주 틀리는 **판단 지점 하나**를 가진 작은 과제다(조사: 지시가 결과를 크게 바꾼 항목은 모두 이 형태).
과제마다 **함정 변형**(하면 안 되는 쪽이 정답)과 **대조 변형**(해야 하는 쪽이 정답)을 짝지어 "아무것도 안 하기" · "늘 묻기"가 이기지 못하게 한다.
v0 = 6종 11항목(이미 고친 버그 · 명세와 모순된 테스트 · 무관한 정리 유혹 · 없는 입력 · 묻지 말아야 할 명확한 변경 · 숨은 사용처).

**과제 내용은 공개 저장소에 두지 않는다**(학습 오염 · 하네스를 과제에 맞추는 과적합 방지). 픽스처 · 지시문 · 채점기는 비공개 위치에 git 으로 둔다.

## 3. 팔 · 등급

- A = 목표 · 스택 두 절의 CLAUDE.md · B = 같은 CLAUDE.md + `agent-harness install --track base --cli claude`. 준비 뒤 시작점을 다시 찍어 채점 diff 에서 준비물을 뺀다.
- P(위약, 다음 판) = 같은 분량의 무관한 규칙 파일 — 규칙 파일이 있다는 사실만으로도 효과가 났다는 조사 결과(+13.8%p) 때문에, B−P 가 "내용 효과"다.
- 등급: GLM-5.3 · GLM-5.3-flash(사용자 승인 2026-11-08, 정액 아님 — 주간 크레딧 상한). 하위 에이전트도 같은 모델로 고정해 등급을 섞지 않는다.
- 생각 수준은 등급마다 하나로 고정(v0 = high). 따로 "하네스 + 낮은 생각 ≈ 하네스 없음 + 높은 생각?" 을 중간 등급 · 변별 항목에서만 잰다 — 그 전에 effort 가 GLM 에 전달되는지부터 확인한다.
- 두 팔 모두 웹 조회 끔 · 키는 env-file 로만 · 호스트 `~/.claude` 미마운트.

## 4. 선별과 판정 — 선택 편향을 막는 순서

1. **채점기 검증(모델 0회)** — 과제마다 정답 · 오답 스크립트 정책으로 채점기가 기대대로 가르는지(v0: 23/23).
2. **선별 실행** — 전 항목 × A · B × 3회 × 등급. **두 팔 합친 통과율이 0도 1도 아닌 항목**만 변별 후보로 남긴다(갈린 짝으로 고르면 효과 0 에서도 +53%p — 모의실험).
3. **확인 실행** — 후보만 새로 돌린다(선별 실행은 효과 계산에 쓰지 않는다). 판정 = 항목별 B−A 차이의 t-구간 + 정확 조건부 검정. 15 항목 × 3회면 약 +28%p 를 80% 로 잡는다.
4. 판을 거듭할 때 = 고정 닻 항목 + 새 항목 일부 교체(과제에 맞춘 개선을 막는다).
