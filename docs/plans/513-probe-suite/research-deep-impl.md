# 조사 D — 구현 중심 벤치마크 심층 조사(반박 검증) · 대조 · 실행 가능성 (2026-11-09)

질문 = 우리 설계(팔 A/B/C/P · 등급 3 · 여섯 축 · 독립 필터 + 5회 확인)와 북극성(개발 속도 · 높은 품질의 안전한 딜리버리) 기준으로,
하네스의 효과가 드러날 구현 과제 소스. 심층 조사(5갈래 검색 · 출처 22 · 주장 110 추출 · 25 검증 → 확인 11 · 기각 14)와
단일 조사(`research-impl-benchmarks.md`)를 대조했다. 기각은 "존재 부정"이 아니라 "이번 검증에서 세부 미확인"이다.

## 1. 두 조사가 일치한 것

| 결론 | 근거(검증 수준) |
|---|---|
| **주력 = 실제 저장소의 기능 구현 과제, 새 기능 테스트(F2P) + 기존 동작 테스트(P2P)를 Docker 안에서 실행해 결정적으로 채점** | FeatBench 실패 122건 수작업 분석에서 **회귀형(기능은 넣고 기존 동작을 깸) 73.6%**, 저자는 요청 밖 확장 · 리팩터를 원인으로 지목(3-0). 하네스의 범위 규율 · 검증 · 독립 리뷰가 겨냥하는 실패가 실제 기능 과제의 주된 실패라는 외부 증거 |
| **보안은 BaxBench(392)/AutoBaxBench(40) — 실제 익스플로잇으로 결정적 판정** | 설계 3-0 · 천장에서 멂(Claude-4.5 Sonnet sec_pass 36%, 3-0) |
| **보안은 "하네스가 해치지 않는가" 비열등 점검으로 쓴다** | 지시문 수준 보안 개입은 효과가 없거나 정답률을 깎는다는 1차 출처 셋(2-1 · 3-0 · 3-0). 특히 Claude Code + Sonnet 4.5 에 "스스로 테스트해 정확성 · 보안을 검증하라"를 더하자 sec_pass 70% → 54%(Codex + GPT-5 는 52 → 59%) — 우리 앵커의 증거 기반 완료 지시가 같은 방향일 수 있는 위험 |
| **SWE-bench Pro 는 요구사항 · 인터페이스 명세를 줘서 하네스 여지가 작다** | 단일 조사 ○ · 심층 조사 1-2(구성 세부 미확인) |
| **외부에 "같은 에이전트 위에 지시문 묶음만 얹은 효과"를 등급별로 잰 연구는 없다** | 스캐폴드 전체 교체(Trae vs Agentless · Claude Code vs Aider vs OpenHands)는 차이가 있으나 상당수가 잡음 범위(SecRepoBench Sonnet 4.5 p≈0.10) — 우리 측정이 이 공백을 메운다 |

## 2. 갈린 것 · 남은 것

- **NoCode-bench Verified(현재 이름 Doc2Feat-Bench, 114)**: 심층 조사의 1순위(3-0 — 문서 변경 → 기능 구현, F2P/P2P). 단일 조사는 오염 위험(SWE-bench 저장소) ·
  리더보드 도메인 상태를 이유로 후순위. 통과율 분포는 미확인(0-3) — **우리 환경에서 걸러 봐야 안다**.
- **FeatBench 중위 모델 통과율 대역**: 단일 조사가 공개 결과 JSON(Harbor 패리티 9회 + 논문 8구성)을 내려받아 과제별로 집계해 **0.2–0.8 대역 42개**를 냈다(✱ 계산).
  심층 조사는 같은 출처의 전체 해결률 주장을 0-3 으로 확인하지 못했다 — 과제별 집계는 우리 선별 실행으로 검증한다.
- **품질(유지보수성) 축**: 결정적으로 재는 소스가 검증되지 않았다(SlopCodeBench 는 단일 조사만). 대리 지표 = **정답 패치가 건드리지 않은 파일의 변경 수 · 줄**(범위 이탈 — 외부 검증 없음, 우리 제안)
  + 보안(sec_pass). LLM 판정은 Opus 고정(사용자 결정 2026-11-09)을 보조로.
- **새 축 후보 = 거짓 완료 보고**: 최종 보고는 "완료 · 테스트 통과"인데 실제 F2P/P2P 실패. 지금까지 유일하게 변별된 사고(없는 입력 지어내기)와 같은 계열이고, 앵커의 증거 기반 완료 판정이 직접 겨냥한다.

## 3. 실행 가능성 — 이 머신에서 확인 (2026-11-09, 모델 호출 0)

- FeatBench 과제 이미지 = `ghcr.io/kndy666/featbench_<repo>:<번호>` — **amd64 전용 · 과제당 압축 약 0.74–0.76 GB**(2개 확인). 이 Mac(arm64)에서는 에뮬레이션으로 돈다.
- Harbor 레지스트리에 FeatBench 는 없다(`Dataset featbench not found`) — 어댑터로 과제 디렉터리를 만든다. 어댑터 실행은 호스트가 아니라 **격리 컨테이너 안**에서 했다(외부 코드 — 자동 승인 분류기가 호스트 실행을 막았고, 우회하지 않았다).
- `jpadilla__pyjwt-979`: **정답 패치 → 보상 1(F2P 1/1 · P2P 241/241, 45 s)** · **변경 없음 → 보상 0(F2P 0/1 · P2P 241/241, 50 s)**. 채점이 기대대로 갈린다.
- 위험: 채점 단계가 `pip install -e .` 로 네트워크를 다시 쓴다 — 변경 없음 첫 시도가 PyPI 일시 실패로 채점 전에 죽었다(재시도 통과). **채점 실패는 무효로 표시하고 다시 채점**해야 한다(모델 재실행 불필요). P2P 수천 개 저장소(conan 등)는 에뮬레이션에서 채점이 길다 — 작은 저장소부터.

## 4. 다음 — 변별력 증명(GLM 만, 사용자 결정 2026-11-09)

1. **파일럿**: FeatBench 작은 저장소 3과제 × A × 1회(GLM-5.3) — Claude Code + 하네스를 과제 이미지에 얹는 방식 확인 · 시행당 토큰 · 시간 실측 → 선별 규모를 역산한다(GLM 주간 상한).
2. **선별**: 단일 조사의 사전 선별 22과제(회귀 서명 16 + 대조 6, 처치를 보지 않고 고름) → A · B 각 1–2회, 두 팔 합친 통과율 0.25–0.75 를 남긴다.
3. **확인**: 남은 과제 × A · B × 새 5회 · 한 배치 · 항목별 정확 검정. 주 지표는 연속값(깨뜨린 P2P 수 · 범위 밖 변경 · 거짓 완료 보고 · 토큰 · 시간) — 통과/실패만으로는 15과제 × 3회에서 +28–31%p 가 필요하다.
4. 보조: BaxBench(FastAPI · Express) 비열등 점검 · NoCode-bench Verified 실행 가능성 확인.
