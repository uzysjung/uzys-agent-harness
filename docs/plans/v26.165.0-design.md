### A.3 결정

#### A.3.1 #605 — `toml-region` 충돌 규칙: "설치자 값을 바꾸는 항목은 넣지 않는다"

지금 `filterRender`(`src/adapters/toml-region.ts`)는 항목을 ⓐ 경로 충돌(`hasPath`, 배열 표는 제외) ⓑ 합친 문서가 안 읽힘 두 가지로만 뺀다. `[[hooks.SessionStart]]` 는 ⓐ 에서 "배열 표는 더하기" 로 통과하고 ⓑ 도 통과한다(유효한 TOML) — 그러나 설치자 `hooks[0]` 에 `SessionStart` 키가 **생긴다**. ADR-097 §6.2 ⓑ "설치자의 같은 키·절·줄이 있으면 그것이 이긴다" 의 뜻은 설치자 값이 바뀌지 않는다는 것이므로, 이것은 새 규칙이 아니라 기존 규칙을 판정에 옮기지 못한 자리다.

**규칙(추가)**: 항목 하나를 더한 문서를 파싱한 결과 `after` 에서, 설치자 것만 파싱한 `before` 의 **모든 경로가 같은 값으로 남아 있어야** 그 항목을 넣는다. 같음의 정의 `unchangedUnder(before, after)`:
- `before` 의 키마다 `after` 에 그 키가 있어야 한다.
- 둘 다 표 → 재귀.
- 둘 다 배열 → `after.length >= before.length` 이고 `before[i]` 와 `after[i]` 가 깊은 동치(**끝에 붙는 것만 더하기다**).
- 그 밖 → 깊은 동치.
- 하나라도 어긋나면 항목을 **뺀다**(`kept` 에 이름을 넣는다 — 화면 `kept yours: [[hooks.SessionStart]]`).

**딸린 규칙**: 한 항목이 빠지면, 같은 구간에서 **그 경로를 접두로 갖는 뒤 항목**(`[[hooks.SessionStart.hooks]]`)도 함께 뺀다 — 부모 없이 자식만 들어가면 뜻이 달라진다(`hooks.SessionStart` 가 배열이 아니라 표로 태어난다). 빠진 이름은 전부 `kept` 에 넣는다.

판정 자리: `filterRender` 안, 지금의 `taken || readToml(doc()) === null` 분기에 `|| !unchangedUnder(installer, readToml(doc()))` 를 더한다(파싱 1회를 재사용). `top` 구간의 최상위 키도 같은 규칙을 지난다(설치자 `[profiles.x]` 안 키와는 경로가 달라 영향 없음).

**설치자 배열에 끝으로 붙는 경우는 그대로 더하기다**: 설치자가 자기 `[[hooks.SessionStart]]`(자기 matcher group)를 갖고 있으면 하네스 group 이 두 번째 원소로 붙는다 — Codex 는 둘 다 돈다. 이것이 `[[배열 표]]는 더하기` 문장의 참인 범위다.

화면: `shared-write.ts` 의 `kept` 필터는 구간 이름(`top` · `tables`)만 `leftAsIs` 로 가르므로 항목 이름은 그대로 `kept yours` 로 나간다 — 변경 없음. 하네스 훅이 배선되지 않았다는 사실은 `kept yours` 줄 자체가 말한다(별도 줄을 더하지 않는다 — USAGE 의 "yours wins and the summary says kept yours" 그대로).

#### A.3.2 #724 — `[features]` 표를 템플릿에서 뺀다

`templates/codex/config.toml.template` 의 `# Features …` 머리 주석부터 `child_agents_md = false` 줄까지(§Features 블록 전체)를 지운다. 근거: `hooks` · `multi_agent` · `plugins` 는 Stable · 기본 true(확인) 라 켜 둘 이유가 없고, `child_agents_md` 는 Codex 가 모르는 키(경고의 원인), `tool_search` · `skill_mcp_dependency_install` 은 유효 여부 미확인. **기본값을 되풀이하는 표는 설치자에게 주는 것이 없고 경고만 만든다.** 표가 없으면 사양 의존도 없다.

이미 깐 설치본의 `update` 한 번:
- `tables` 구간 sha 가 기록과 같다 → `replace`(새 렌더에 `[features]` 없음) → 경고 0. 기존 `toml-region` 동작.
- 구간 모델 이전 판이 통째로 쓴 파일이 기준선 sha 그대로다 → `shared-write` 의 `harnessMade` 가 새 형식으로 다시 쓴다 → 경고 0. 기존 동작.
- 설치자가 구간 안을 고쳤다(`leftAsIs`) · 옛 통째 파일을 고쳤다(`LEGACY_CHANGED`) → 하네스는 손대지 않는다(원칙). **추가**: `src/codex/config-toml.ts` 에 `retiredFeatureKeys(disk: string): string[]` — 파싱한 `features` 표에서 `codex_hooks` · `child_agents_md` 가 있으면 그 이름을 돌려준다(못 읽으면 `[]`). `update-mode.ts` 의 `.codex/config.toml` 결과 줄에 `hasLegacyHarnessHook`(#625) 와 같은 자리로 한 줄을 덧붙인다:
  `  ⚠ .codex/config.toml  [features] codex_hooks · child_agents_md make Codex warn ("ignoring unrecognized configuration") — delete those lines, or delete the harness region and run update`
  조건: 이 파일의 하네스 구간이 갈아 끼워지지 않은 실행(`leftAsIs` 에 `tables` 가 있거나 `action === "left"`)에서만. 설치자가 구간 밖에 직접 둔 같은 키도 같은 줄을 받는다 — 지우라는 안내는 그때도 맞다.

테스트 사본 정리: `tests/codex/config-toml.test.ts` 가 `codex_hooks` 를 단언한다 — 반대로(`features` 키 부재) 뒤집는다. `templates/codex/README.md` · `docs/specs/codex-compat.md` 의 `[features]` 서술은 현행 결정으로 고친다(README 는 배포물).

#### A.3.3 #685 — trust 항목: 파서 판정 · 이스케이프 · 쓰고 다시 읽기

`src/codex/trust-entry.ts` 를 다음 계약으로 다시 쓴다(`registerTrustEntry` · `hasTrustEntry` 의 호출부 시그니처는 유지):

1. **키 후보** `trustKeysFor(projectDir): string[]` — `[canonical, raw]` 순서(중복 제거). `canonical = realpathSync.native(projectDir)`(없으면 raw). `process.platform === "win32"` 면 둘 다 소문자화(Codex `normalize_project_trust_lookup_key` 와 같다). **쓰는 키 = 첫 후보(canonical)** — Codex `project_trust_key` 와 같은 선택.
2. **중복 판정** `hasTrustEntry(content, projectDir)`: `smol-toml` 로 파싱 → `projects` 가 표이고 후보 키 중 하나가 그 표의 키로 있으면(값이 표이면) `true`. 파싱 실패 → `false`(지금 호출부 `install-render.ts:717` 의 `alreadyTrustedGlobally` 는 이 값을 "안내를 낼까" 에만 쓴다 — 못 읽는 파일은 `registerTrustEntry` 가 `unreadable` 로 따로 말한다). 정규식 `TRUST_BLOCK_REGEX` 는 지운다.
3. **쓰기** `registerTrustEntry`:
   - 파싱 실패 → `unreadable`(지금과 같다, #644).
   - 이미 있다 → `already-present`. `trust_level` 이 `"trusted"` 가 아니면 `message: 'already present (trust_level = "untrusted") — left as is'` — 설치자의 명시적 결정을 덮지 않는다.
   - 없다 → `block = "\n[projects." + tomlBasicString(key) + "]\ntrust_level = \"trusted\"\n"`, `next = existing + block`. **`parse(next)` 가 성공하고 `parsed.projects[key].trust_level === "trusted"` 일 때만 쓴다.** 아니면 `{ status: "error", message: "adding the entry would make this file unreadable TOML — left untouched" }` 로 돌아온다(바이트 불변). 이 경로가 닿는 실제 경우: 설치자가 `projects = { … }` **인라인 표**로 써 둔 파일 — TOML 은 인라인 표를 뒤에서 넓히지 못한다. 그때는 손으로 넣으라고 화면이 말한다(아래).
   - `tomlBasicString(s)`: `"` + `s` 의 `\` → `\\`, `"` → `\"`, U+0000–U+001F · U+007F → `\uXXXX` 치환 + `"`. (TOML 1.0 기본 문자열 이스케이프 집합. 다른 문자는 그대로.)
4. **기록**: `codexTrust.projectDir` 에는 **쓴 키**(canonical)를 적는다 — uninstall 의 "손수 지울 것" 줄이 같은 키로 `[projects."…"]` 를 찍되 `tomlBasicString` 으로 찍는다(지금은 raw 를 따옴표로만 감싼다).
5. 화면(`install-render.ts` trust 행): `error` 는 지금처럼 `skip` 행 + `message`. NEXT 의 headless 안내는 `status === "error"` 일 때 `headless: add [projects."<key>"] trust_level = "trusted" to ~/.codex/config.toml by hand (the harness could not append it safely)` 로 바꾼다(`unreadable` 분기와 나란히).

**#685 본문의 "실 Codex 가 trust 를 쓰는 표기를 Docker 에서 먼저 확인" 은 불필요해졌다** — 소스에서 쓰기 함수(`set_project_trust_level_inner`)와 키 생성(`project_trust_key`)을 확인했고, 따옴표 종류에 설계가 기대지 않는다(§A.2 미확인 항목).

#### C-2 렌더 주체 하나 — `src/agents-md-transform.ts`

runAgentsMdTransform({

  clis,                       // 이번 실행의 AGENTS.md 집합(아래)
  selectedInternalSkills, rules, baseline, refreshOnly, shared, journal,
  installedByRecord,          // clis ∩ 기록 집합 ≠ ∅ — refresh 에서 없어도 만든다(ADR-099 R2)

#### C-3 `uninstall --cli` 가 남는 집합으로 다시 렌더한다

`removeCliAction`(`uninstall.ts`) 에서 `stripCliShared` 다음, `AGENTS.md` 가 **회수 대상이 아니고**(`plan.shared` 에 없음 = 남는 CLI 가 아직 쓴다) 파일이 있으면:
`runAgentsMdTransform({ clis: remaining ∩ {codex,opencode,antigravity}, refreshOnly: true, baseline: 기록 externalFiles, shared: 기록 portions/excluded, installedByRecord: true, selectedInternalSkills: 기록에서(update 와 같은 방법 — `installedBundledSkills`), rules: 기록 트랙의 `resolveRules` })`.
- 절 모델: `mergeAgentsMd` 가 하네스 절(제목 · Harness Rules · Session Start · Protected Files)을 새 집합 판으로 갈아 끼우고 설치자 절을 잇는다. 기준선 sha 가 같으면 백업 없이, 설치자가 하네스 절을 고쳤으면 ADR-048 대로 파일 하나 백업(이미 update 와 같은 규칙).
- 블록 모델: `agents` 블록을 새 렌더로 `replace`(기록 sha 그대로일 때). 고쳤으면 `leftAsIs`.
- `settleCliLog` 가 결과 `ownership.files`(AGENTS.md 새 sha) 와 `portions` 를 기록에 싣는다 — 안 실으면 다음 update 가 "고쳤다" 로 읽어 백업을 만든다(#550 의 형태).
- 화면: `  ✓ AGENTS.md  re-rendered for <remaining> (your sections kept)` · 블록 모델이면 `harness block re-rendered for <remaining>`. `--dry-run` 은 `would re-render AGENTS.md for <remaining>`.
- 이것은 uninstall 이 "하네스 몫을 빼는" 동작의 한 형태다 — 빠지는 CLI 의 몫(제목의 이름 · `## Session Start` · 안내 문단)을 걷는 가장 단순한 구현이 "남는 집합으로 다시 렌더" 다. **검증자 확인 요청 §6-8.**

그 밖은 결정해 두었다. 가정으로 표시한 것: ⓐ `AGENTS.md` 에도 Antigravity 24,000 bytes 상한이 적용된다고 보고 B-T8 로 잰다 ⓑ `tool_search` · `skill_mcp_dependency_install` 은 유효하더라도 기본값이라 표 제거로 잃는 것이 없다 ⓒ 혼합 설치의 룰 이중 상주는 감수한다(§B.1).

## 7. 검증자에게 — 갈릴 수 있는 지점 전부 (심각도 무관)

1. **A.3.1 배열 더하기의 허용 범위**: 설치자의 `[[hooks.SessionStart]]` 끝에 하네스 group 을 붙이는 것을 "설치자 값 불변" 으로 본다(접두 동치). Codex 는 두 group 을 모두 돈다. 이것을 충돌로 봐야 한다는 판정이 가능하다면 근거를 달라 — 그 경우 규칙은 "배열에도 손대지 않는다" 로 단순해지지만 설치자가 자기 SessionStart 훅을 가진 흔한 경우에 하네스 훅이 영영 안 깔린다.
2. **A.3.1 딸린 규칙**(부모가 빠지면 자식도)의 구현 위치 — `segment()` 가 항목을 헤더마다 자르므로 `[[hooks.SessionStart.hooks]]` 가 독립 항목이다. 접두 판정을 빼먹으면 자식만 들어가 `hooks.SessionStart` 가 표로 태어난다(A-T1 이 `kept` 두 이름을 단언하는 이유).
3. **A.3.2 ⚠ 줄의 발화 조건** — "구간을 갈아 끼우지 못한 실행" 으로 좁혔다. 설치자가 구간 **밖**에 같은 키를 둔 경우도 같은 줄을 받는데, 그때 "delete the harness region" 절반은 틀린 안내다. 두 문장을 가르려면 구간 안/밖을 파싱 위치로 가려야 한다(`maskRegions` 재사용 가능) — 비용 대비 가치를 판정해 달라. 지금 설계는 한 줄로 둔다.
4. **A.3.3 canonical 키** — macOS 에서 `/var/folders/…` 와 `/private/var/…` 가 갈린다. Codex 는 둘 다 조회하므로 어느 쪽을 써도 동작한다. 기록 `codexTrust.projectDir` 를 canonical 로 바꾸면 기존 테스트 단언이 바뀐다(A-T14). 옛 기록(raw)과 새 기록(canonical)이 섞여도 uninstall 안내는 기록된 값을 찍을 뿐이라 문제없다 — 맞는가.
5. **A.3.3 `already-present` + `untrusted`** — 설치자가 명시로 untrusted 한 폴더를 하네스가 trusted 로 바꾸지 않는다. 대신 화면이 말한다. 이 비대칭(플래그를 줬는데 안 바뀜)을 `error` 로 내야 한다는 판정도 가능하다.
6. **B-2 옛 로그 유도** — `installedClis` 는 `externalFiles ∋ 앵커` 로 antigravity 를 유도한다. 은퇴 단계가 같은 update 에서 그 항목을 빼므로, **그 update 가 `clis` 를 반드시 써야** 다음 실행이 antigravity 를 잃지 않는다. `buildInstallLog` 가 update 경로에서도 `clis` 를 쓰는지(ADR-096 D2) 코드로 확인해 달라 — 안 쓰면 은퇴 단계가 `clis` 를 명시로 적어야 한다.
7. **B-3 ⓒ(합치지 않음)** — 두 파일을 다 채운 설치자의 앵커 문장이 라이브에서 사라지고 백업에만 남는다. #645 의 요구("채운 노동이 백업행") 와 모양이 같아 보일 수 있다. 차이: 한 번뿐이고 화면이 경로를 말하며, 합치면 어느 문장이 맞는지 하네스가 판정하는 셈이 된다(ADR-096 D7 금지). 다른 판정이 있으면 달라.
8. **C-3 uninstall 이 공유 파일을 "다시 쓴다"** — 원칙 문장은 "빼기" 인데 구현은 재렌더다. 빠지는 CLI 의 몫(제목 이름 · Session Start · 안내)이 절 단위가 아니라 문장 단위로 섞여 있어 strip 으로는 표현이 안 된다. 재렌더가 설치자 절을 건드리지 않음은 C-T3 · C-T5 가 문다. 이것을 원칙 위반으로 본다면 대안은 "update 를 돌리라" 안내뿐이다(#642-2 미해결).
9. **C-2 집합에 `recordedClis` 를 install 에서도 합친다** — 옛 로그의 유도가 틀려 있던 설치본(ADR-096 Consequences "기록에 없는 `.claude/`" 류)에서 집합이 커질 수 있다. 커지는 방향은 제목에 이름이 하나 더 붙고 절이 하나 더 들어가는 것뿐(파일 삭제 없음). 안전한 쪽이라 보지만 확인해 달라.
10. **B-T8 크기 게이트** — "상시 테스트는 안착만" 메모리와 긴장한다. 벤더 상한(24,000 bytes · 32 KiB)에 묶인 계약이라 하나 두기로 했다. 빼야 한다면 근거를. **더 무거운 질문**: 실측 19,562 bytes 는 24,000 까지 4.4 KB 뿐이다. Antigravity 가 `AGENTS.md` 에도 그 상한을 건다면 Project Context 를 성실히 채운 설치자일수록 끝부분이 잘린다 — 그 경우의 대안은 (ⓐ) Antigravity 가 집합에 있으면 `## Harness Rules` 인라인을 빼고 `.agents/rules/` 에만 두기(혼합 설치의 이중 상주도 함께 사라진다 — 단 codex 가 함께 있으면 codex 가 룰을 잃으므로 불가 → codex ∉ 일 때만) (ⓑ) 상한 적용 여부를 실 Antigravity 에서 먼저 확인. 이 설계는 ⓑ 를 후속으로 두고 상한 미적용을 가정하지 않았다(테스트가 잰다) — 판정을 달라.
11. **Antigravity `glob` 의 뜻**("agent interacts with files matching") 과 Claude `paths:`(파일을 읽을 때 로드)의 등가성은 문서 문장 비교뿐이다. 차이가 중요하면 `cli-development` 도 `always_on` 으로 — 그러면 셸 룰이 매 턴 상주한다(≈700 bytes).
12. **미확인 사양에 기대는 곳이 있는가** 점검: trust 키 따옴표 종류(기대지 않음 — 재파싱) · `name` 키(범위 밖) · `AGENTS.md` 24 KB 상한(보수적 가정) · HTML 주석(기존 상태 유지). 빠뜨린 것이 있으면 지적해 달라.
13. **L-A 가 문턱 위인가** — `~/.codex/config.toml` 쓰기는 ADR-097 결정 2 범위의 옵션 동작이고, 이 변경은 "쓰지 않는 경우" 를 늘리는 방향이다. 문턱 아래(CI 만)로 봐도 된다는 판정이면 리뷰 비용이 준다.

### 9.1 BLOCKER-1 — `spec.clis` 이행점 (§B-3 3단계 교체)

**넣을 문장(§B-3 3단계 교체)**:
> 3. **기록**: 은퇴 단계는 `externalFiles` 에서 앵커 경로를 빼기 **전에** `installedClis(log)` 를 계산해 두고, 같은 기록 쓰기에서 `spec.clis` 를 그 값으로 **명시로 적는다**(없던 필드면 만든다 — `buildInstallLog` 가 install 에서 하는 1회 이행을 이 update 가 대신한다, ADR-096 D3 의 "다음에 로그를 쓸 때" 가 바로 이 쓰기다). update 경로의 다른 기록 쓰기(`src/update-mode.ts:1783-1800`)는 `spec` 을 건드리지 않으므로 이 한 자리가 유일한 이행점이다. B-T4 · B-T5 의 픽스처는 **`spec.clis` 가 없는 옛 로그 모양**으로 만들고, update 뒤 기록에 `spec.clis ∋ antigravity` 를 단언한다 — 지금 설계의 B-T4 단언 "`clis` 에 antigravity" 는 `installedClis()` 반환값이 아니라 **기록 필드 자체**를 읽어야 이 결함을 문다.

### 9.2 BLOCKER-2 — 스캐폴드 판정은 하네스 줄을 뗀 뒤 (§B-3 1단계 앞 · FILL 문구 항)

**넣을 문장(§B-3 1단계 앞에 추가 · §B-3 FILL 문구 항에 덧붙임)**:
> **스캐폴드 판정은 하네스가 쓴 줄을 뺀 뒤 한다.** `isPristineScaffold` · `stripHarnessFromAgentsMd` · 은퇴 1단계의 "채웠는가" 는 ① `<!-- FILL:… -->` 주석 줄(여러 줄이면 `-->` 까지)과 ② `## Skills that apply continuously` 헤딩부터 다음 `## ` 전까지의 절(마커 유무 무관 — ADR-095 D4 가 옛 AGENTS.md 에 쓰는 같은 단서 `CONTINUOUS_SKILLS_HEADING`)을 **양쪽(디스크 본문 · 기준 스캐폴드)에서 뗀 뒤** 비교한다. 그래야 FILL 문구를 고친 이 릴리즈가 기존 설치본의 안 채운 스캐폴드를 "채웠다" 로 읽지 않고, 옛 Antigravity 앵커의 마커 없는 안내 절이 설치자 글로 옮겨 가지 않는다. 설치자가 "Delete this comment when done" 대로 주석만 지우고 자리표시자를 남긴 상태도 같은 규칙으로 "안 채움" 이다(같은 뜻). 회귀: B-T5 픽스처는 **옛 FILL 문구 + 상시 스킬 절이 든** 26.164 앵커로 만들고 `AGENTS.md` Project Context 에 `Skills that apply continuously` 가 **한 번만** 있음을 단언한다. 기존 `tests/anchor-seed*` · `uninstall-cli-scope` 에 "옛 문구 스캐폴드(안 채움) → seed 없음 / 파일째 삭제" 대조군 1건.

### 9.3 BLOCKER-3 — 읽기(변환 전)·지우기(변환 후) 두 토막 (§B-3 머리 교체)

**넣을 문장(§B-3 머리 교체)**:
> B-3 은 두 토막이다. **(읽기 · 변환 전)** `readLegacyAntigravityContext(projectDir, log)` — 기록 `externalFiles` 에 앵커가 있을 때만 디스크 앵커의 `## Project Context` 설치자 줄(BLOCKER-2 규칙으로 하네스 줄을 뗀 뒤)을 돌려준다(없으면 `null`). `runAgentsMdTransform` 은 이 값을 `seed` 후보(루트 `CLAUDE.md` 다음 순위)로 받고, **파일이 없으면** seed 로 만들며, **파일이 있고 그 `## Project Context` 가 (BLOCKER-2 규칙으로) 손대지 않은 스캐폴드이면** `mergeAgentsMd` 가 그 절 본문을 seed 로 바꾼다(새 분기 — 지금은 디스크 절을 그대로 이어받는다, `agents-md-merge.ts:264-271`). 이미 채워져 있으면 바꾸지 않는다(ⓒ). 쓰기는 지금처럼 owned-write 한 번 — 기록 sha = 최종 바이트. **(지우기 · 변환 후)** 앵커를 `judge(remove)` 로 지우고(백업 규칙 그대로) 기록에서 빼며 `spec.clis` 를 적는다(BLOCKER-1). 회귀: B-T4 · B-T6 에 "**이어서 `update` 를 한 번 더 해도 `AGENTS.md.backup-*` 0건 · 화면에 `retired` 줄 없음**" 을 단언한다(C-T3 가 uninstall 재렌더에 거는 것과 같은 음성 대조).
