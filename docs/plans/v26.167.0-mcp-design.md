## 2. 현재 코드 사실 (실측 — 구현자는 여기서 다시 확인)

- 서버 정의 원천 = `templates/mcp.json`(모든 트랙: context7 · github · chrome-devtools) + `templates/track-mcp-map.tsv`(railway 5트랙 · supabase 2트랙). 행 형식 4열 `name\tpattern\tcommand\targs_json`, 파서 `parseTrackMcpMap`(`src/mcp-merge.ts:28-55`)은 args 가 문자열 배열이 아니면 행을 버린다.
- 내부 모델 `McpServerConfig`(`src/mcp-merge.ts:8-13`) = `{ type?: "stdio"|"http", command, args, env? }` — `type:"http"` 가 타입에만 있고 `url` 이 없어 원격을 표현하지 못한다. `mergeMcpServers`(`:61-95`)는 행을 `{type:"stdio", command, args}` 로만 만든다.
- 한 실행에 한 번 렌더(`renderHarnessMcp`, `src/cli-transforms.ts:175-182`) → `.mcp.json` writer(`writeMcpShared`, `src/install-writes.ts:738`) · Codex(`renderMcpServers`, `src/codex/config-toml.ts:155-171` — `command` · `args` · `env` 세 줄) · OpenCode(`toLocal`, `src/opencode/opencode-json.ts:42-51` — `{type:"local", command:[…]}`). Antigravity 변환에는 MCP 가 없다(`grep -rn mcp src/antigravity/` 0건, 대조군 `src/codex/` 2파일 — 조사 보고서 §④ check-absence 실측과 일치).
- 선택 경로(ADR-101): 카탈로그 `internal` 자산의 `key` 가 행 이름이면 고를 수 있다(`selectableMcpServers`, `src/mcp-merge.ts:121-129`). 렌더 = 트랙 기본 행 ∪ 선택 행(`selectedMcpServers`, `:146-158` — ⓐ 빼지 않았고 ⓑ 이번에 골랐거나 **기록의 `.mcp.json` 몫에 있다**). 빼기는 자산 id · 키 id 어느 꼴이든 세 자리에 닿는다(`droppedMcpServers`, `:166-178`).
- 키 단위 판정은 `planUpsert`(`src/adapters/contract.ts:140-215`): 기록 sha 그대로 + 렌더 값 다름 → `replace` · 기록에 있고 렌더에 없고 sha 그대로 → `remove` · sha 다름 → `kept`. `.mcp.json` writer 는 렌더에 없어 걷은 키를 `retired` 로 돌려준다(`src/install-writes.ts:359-361`)지만 화면은 `.gitignore` 의 한 줄만 특별 취급한다(`src/commands/install-render.ts:1657-1672`). **`replace` 된 키 이름은 화면 어디에도 안 나온다**(`SharedWrite` 에 필드 없음, `src/install-writes.ts:62-92`).
- 옛 로그(`records !== "writer"`, v26.161 이하)의 `.mcp.json` 몫은 `legacyMcpSeed`(`src/install-writes.ts:687-701`)가 채운다: 하네스가 그 파일을 **만들었을 때만**, 지금 렌더의 키가 파일에 있으면 그 키를 하네스 몫으로 보고 sha 는 **렌더 값**으로 적는다(디스크 값과 대조하지 않는다). uninstall 의 remnant(`src/commands/uninstall.ts:1286-1335`)는 `renderEverySelectableMcp` 값과 같은 키만 알린다.

## 3. ⓐ 원격 서버 — 데이터 형태와 세 렌더

### 3.1 트랙 표 (`templates/track-mcp-map.tsv`) — 이번 판의 전체 내용

```
# 형식: <name>\t<track_pattern>\t<command|url>\t<args_json|remote_json>
# - track_pattern `-` = 어느 트랙에서도 기본이 아니다 — 같은 이름의 카탈로그 internal 자산으로만 고른다(#709 경로)
# - 3열이 리터럴 `url` 이면 원격(Streamable HTTP) 행: 4열 = {"url":"https://…","bearerEnv":"ENV_NAME"?}
#   bearerEnv 는 Authorization: Bearer 를 환경변수에서 읽게 한다 — 값은 파일에 쓰지 않는다
railway-mcp-server	csr-supabase|csr-fastify|csr-fastapi|ssr-htmx|full	url	{"url":"https://mcp.railway.com"}
supabase	csr-supabase|full	npx	["-y", "@supabase/mcp-server"]
chrome-devtools	csr-*|ssr-*|full	npx	["-y", "chrome-devtools-mcp@latest", "--no-usage-statistics"]
vercel	-	url	{"url":"https://mcp.vercel.com"}
github-mcp	-	url	{"url":"https://api.githubcopilot.com/mcp/","bearerEnv":"GITHUB_PAT"}
```

`templates/mcp.json` 은 **context7 하나**만 남는다(`_comment` 의 setup-harness.sh 언급은 낡았으니 같이 지운다 — 선택).

- `-` 는 `globToRegex`(`src/track-match.ts:26-29`)가 `^-$` 로 바꾸므로 어떤 트랙 이름과도 맞지 않는다 — 파서 변경 없이 "기본 없음" 이다. `trackDefaultMcpAssetIds`(`src/cli-transforms.ts:188-199`)에도 안 잡힌다.
- 파서(`parseTrackMcpMap`): `command === "url"` 이면 4열을 객체로 읽어 `{ name, pattern, url, bearerEnv? }` 행을 만든다. 4열이 객체가 아니거나 `url` 이 `https://` 로 시작하지 않으면 행을 버린다(지금 규칙 "깨진 행은 버린다" 와 같다). 그 밖은 지금처럼 stdio 행.

### 3.2 내부 모델

```ts
export type McpServerConfig =
  | { type: "stdio"; command: string; args: string[]; env?: Record<string, string> }
  | { type: "http"; url: string; auth?: { bearerEnv: string } };
```

`McpJson.mcpServers` 값이 이것이다. **Claude 형식으로 바꾸는 함수 하나** `toClaudeServer(cfg)` 를 `src/mcp-merge.ts` 에 두고, `.mcp.json` 에 쓰는 자리(`writeMcpShared` 의 render 맵 · uninstall remnant 의 값 대조 · `renderEverySelectableMcp` 소비처)만 그것을 거친다. 키 id · 선택 · 빼기 로직은 이름만 보므로 그대로다.

왜 Claude 형식을 내부 모델로 쓰지 않나: Codex 는 토큰을 **환경변수 이름**(`bearer_token_env_var`)으로 받는다. Claude 형식(`"Bearer ${GITHUB_PAT}"`)을 저장하면 Codex 렌더러가 문자열에서 변수 이름을 다시 뽑아야 한다. 필드 하나(`auth.bearerEnv`)를 두면 세 렌더러가 각자 형식을 그대로 낸다.

### 3.3 세 렌더 (출처는 §4.2 표)

| 자리 | 원격(인증 없음 — OAuth) | 원격 + bearerEnv |
|---|---|---|
| `.mcp.json`(Claude) | `{"type":"http","url":"https://mcp.railway.com"}` | `{"type":"http","url":"https://api.githubcopilot.com/mcp/","headers":{"Authorization":"Bearer ${GITHUB_PAT}"}}` |
| `.codex/config.toml` `tables` 구간 | `[mcp_servers.railway-mcp-server]`<br>`url = "https://mcp.railway.com"` | `[mcp_servers.github-mcp]`<br>`url = "https://api.githubcopilot.com/mcp/"`<br>`bearer_token_env_var = "GITHUB_PAT"` |
| `opencode.json` `mcp.<name>` | `{"type":"remote","url":"https://mcp.railway.com"}` | `{"type":"remote","url":"https://api.githubcopilot.com/mcp/","oauth":false,"headers":{"Authorization":"Bearer {env:GITHUB_PAT}"}}` |

- Codex 렌더러(`renderMcpServers`): http 면 `url` 줄(+ `bearer_token_env_var`), stdio 면 지금 세 줄. `{GITHUB_TOKEN}` 치환(`config-toml.ts:147`)과 템플릿 주석(`config.toml.template:61-63`)은 지운다 — 옛 github 서버와 함께 은퇴.
- OpenCode 렌더러: `toLocal` 옆에 `toRemote`. `oauth: false` 는 헤더 인증 서버에 OpenCode 가 401 을 보고 OAuth 를 시작하지 않게 한다(공식 문서 "Disable automatic OAuth … for servers that authenticate via static API keys or custom headers").
- 세 자리가 **같은 `McpJson`** 을 받는 구조(#568 · ADR-101 결정 4)는 그대로다 — 원격 행이 Codex · OpenCode 에서만 빠지는 경로는 없다.

### 3.4 Antigravity 제외

- Antigravity 는 `.mcp.json` 을 읽지 않고 변환이 MCP 를 내지 않는다 — `.mcp.json` 자체는 CLI 와 무관하게 늘 쓰이므로(`src/installer.ts` `writeMcpPortion`) Antigravity 단독 설치에도 생기지만 무해하다(설계 검증 N4). 코드로 "제외" 할 것이 없다. 카탈로그 항목 4종 모두 `cliSupportOverride: ["claude", "codex", "opencode"]`(railway 전례 `src/external-assets.ts:488`) — 위저드 · COMPATIBILITY · "outside reach — not installed" 판정이 그것을 읽는다. Vercel 승인 클라이언트 목록에 Antigravity 가 없다는 사실(조사 보고서 §#711)과 맞는다.
- Antigravity 에 MCP 를 하나도 안 까는 대칭 결손은 이번 범위 밖(§13 후속).

## 4. ⓑ GitHub 공식 서버 opt-in — 정확한 설정

### 4.1 카탈로그 항목

```ts
{
  id: "github-mcp",
  tier: "vetted", // github/github-mcp-server 33.5k — REPO_OVERRIDE 에 추가
  description: "GitHub's official remote MCP server (api.githubcopilot.com) in .mcp.json, Codex and OpenCode — needs a GitHub personal access token in GITHUB_PAT in the shell you start the CLI from. Not needed when the agent uses the gh CLI (Anthropic's recommendation)",
  category: "dev-tools", source: "github",
  condition: { kind: "opt-in" },
  cliSupportOverride: ["claude", "codex", "opencode"],
  method: { kind: "internal", key: "github-mcp" },
}
```

- 왜 이름이 `github` 가 아닌가: 옛 `github` 행의 기록된 몫(`mcpServers.github`)은 지금 코드에서 "기록이 하네스 몫으로 적었다" 는 이유로 선택된 서버로 읽힌다(`selectedMcpServers` ⓑ, `src/mcp-merge.ts:146-158`). 같은 이름을 쓰면 update 가 **모든 옛 설치본**에 공식 서버를 깔고, `GITHUB_PAT` 가 없으면 Claude Code 는 매 세션 `Invalid MCP server config … Missing environment variables: GITHUB_PAT` 로 그 서버를 못 띄운다(공식 troubleshooting, 플러그인 문서 기준 — `.mcp.json` 에서도 같은 문구인지는 **미검증**). 사용자 결정은 "기본에서 제거 · 원하는 사람만 opt-in" 이므로 자동 승계는 결정 위반이다. 이름을 가르면 옛 키는 ADR-100 과 같은 **은퇴 키**가 되고(§7), 예외 규칙 없이 `planUpsert` 가 걷는다.
- 대안 기각: 같은 이름 + "기록 sha 가 옛 정의와 같으면 선택 근거가 아니다" 규칙 — `selectedMcpServers` 에 경우별 예외가 생기고, 설치자가 옛 항목을 고친 경우(sha 가 둘 다 아님) `.mcp.json` 은 `kept yours` 인데 Codex · OpenCode 에는 새 서버가 들어가 세 자리가 갈린다.
- 도구 이름은 `mcp__github-mcp__*` 가 된다. 설치자 `settings.json` 의 `mcp__github__*` 허용 목록은 옛 서버용이라 영향 없다(가정 A3).

### 4.2 인증 — 시크릿을 파일에 쓰지 않는 방법 (CLI 별 공식 근거)

| CLI | 파일에 쓰는 것 | 시크릿 위치 | 출처(2026-10-11 확인) |
|---|---|---|---|
| Claude Code | `headers.Authorization: "Bearer ${GITHUB_PAT}"` | 셸 환경변수 — `${VAR}` 는 실행 시 확장(**[확인]**) · 미설정이면 그 서버만 `Missing environment variables` 로 실패(**[확인-플러그인 문서]**) | code.claude.com/docs/en/agent-sdk/mcp "HTTP headers for remote servers … `${API_TOKEN}` syntax expands environment variables at runtime" · docs/en/plugins/troubleshooting `Invalid MCP server config … Missing environment variables` · GitHub 공식 `docs/installation-guides/install-claude.md` 가 `.env` 의 `GITHUB_PAT` + `claude mcp add-json github '{"type":"http",…,"headers":{"Authorization":"Bearer …"}}'` 를 안내 |
| Codex | `bearer_token_env_var = "GITHUB_PAT"` | 셸 환경변수 — "The actual secret value must be provided via the environment"(**[확인-소스]**) | context7 `/openai/codex` `codex-rs/config/src/mcp_types.rs` `StreamableHttp { url, bearer_token_env_var, http_headers, env_http_headers, … }` · learn.chatgpt.com/docs/extend/mcp 예시 `[mcp_servers.figma] url = … bearer_token_env_var = "FIGMA_OAUTH_TOKEN"` |
| OpenCode | `headers.Authorization: "Bearer {env:GITHUB_PAT}"` + `oauth: false` | 셸 환경변수 — `{env:VAR}` 치환, 미설정이면 빈 문자열(**[확인]**) | opencode.ai/docs/config "Substitute environment variables … `{env:VARIABLE_NAME}`" · opencode.ai/docs/mcp-servers "Disable automatic OAuth … `oauth: false` … `"Authorization": "Bearer {env:MY_API_KEY}"`" |

- OAuth 를 쓰지 않는 이유: GitHub README "Each MCP host application needs to configure a GitHub App or OAuth App to support remote access via OAuth. Any host application that supports remote MCP servers should support the remote GitHub server with PAT authentication." — 세 CLI 가 GitHub 에 OAuth 앱을 등록했는지 확인되지 않았고(**[미검증]**), 공식 Claude 가이드는 PAT 뿐이다.
- 환경변수 이름 `GITHUB_PAT` 는 GitHub 의 Claude 가이드를 따른다(Agent SDK 문서는 `GITHUB_TOKEN` — gh CLI · Actions 가 같은 이름을 다른 뜻으로 쓰므로 피한다, 가정 A4).
- `X-MCP-Toolsets` · `X-MCP-Readonly` 헤더(`docs/remote-server.md`)는 넣지 않는다 — 기본 toolset 이 공식 기본값이고, 더 줄이는 것은 설치자 몫.

## 7. ⓓ 기존 설치본 마이그레이션 — 기록 상태 × 동작 × 화면

공통 규칙(새 코드 없음 — `planUpsert` 가 이미 이렇게 한다): 기록 sha 그대로인 키는 갈아 끼우거나 걷고, 설치자가 고친 키는 `kept yours` 로 남기며, 설치자 키는 건드리지 않는다. Codex 는 `tables` **구간 단위** — 구간 안을 고쳤으면 구간째 남기고 `harness part left as you edited it … delete that part and run update` 를 이미 말한다(`sharedLeftRow`, `install-render.ts:650-668`).

## 8. ⓕ 첫 사용 인증 안내 — 어디서

## 12. ⓗ ADR 과 사용자 결정

### ADR-106 초안 제목
**"MCP 기본은 현행 공식 경로가 정한다 — 원격(HTTP) 서버 지원 · github 기본 제거와 공식 서버 opt-in · chrome-devtools 웹 트랙 한정 · Railway 원격 교체 · Vercel opt-in"**
- Amends: ADR-101 결정 2("Vercel MCP 자체는 넣지 않는다 — stdio 전용 조립으로 표현되지 않는다" → 원격 행으로 표현된다) · 결정 3(첫 항목 railway 의 정의와 tier 근거 repo) · 결정 6(배지 문구) · Consequences("카탈로그 도달 범위는 Claude · Codex · OpenCode" 는 그대로, 총계 55). ADR-102 의 "Next.js 의 Vercel 기본은 공식 MCP(#711)로 채운다" 한 구절(→ opt-in, 사용자 확정 2026-10-11). ADR-063 은 그대로.
- Alternatives(기각): 카탈로그 `method: mcp-remote`(원천 둘) · 같은 이름 `github` + sha 예외(§4.1) · railway 를 `railway` + `["mcp"]` stdio(CLI ≥ 5.44 전제 — 조사 §#712 B안) · chrome-devtools 를 CLI/스킬로(experimental · 전역 설치) · OAuth 로 GitHub(호스트별 앱 등록 미확인).
- Consequences: 세 CLI 가 원격 MCP 를 같은 행에서 받는다 · github 는 기본에서 사라지고 옛 키는 update 가 걷으며 화면이 말한다 · 비웹 트랙 새 설치에 chrome-devtools 가 없다 · 기록된 chrome-devtools 는 남는다 · 옛 로그의 비웹 chrome 은 걷힌다(§7.2 C) · Antigravity 는 여전히 MCP 를 받지 않는다 · 카탈로그 52 → 55.

### 사용자 결정 필요 (제품 범위 · 되돌리기 비싼 것만)
1. **벤더 공식 원격 서버의 trust tier 표시.** `railway-mcp-server` 는 Railway 의 공식 엔드포인트인데 ★ 규칙(≥1000 = vetted)으로는 `railwayapp/cli` 621★ 라 experimental 이고, csr-* 기본값 옆에 `⚠ experimental (default on your tracks)` 가 뜬다. 선택지: (기본) 규칙대로 experimental 유지 — 정직하지만 "공식인데 ⚠" / tier 정의에 "벤더 공식 호스팅" 을 넣어 vetted 로 — ADR-021 tier 규칙 변경이라 별도 결정. 설계는 **기본(유지)** 으로 쓴다.

그 밖의 갈림(이름 `github-mcp` · 환경변수 `GITHUB_PAT` · 옛 로그 비웹 chrome 걷기 · vercel 의 감시 repo)은 구현 방식이라 설계자가 정했고 §14 가정에 있다.

## 14. 가정 (틀리면 여기만 고친다)
- **A1** 서버 정의 원천은 트랙 표 하나 — 기본 없는 행의 패턴 리터럴은 `-`.

- **A4** 환경변수 이름 `GITHUB_PAT`(GitHub 의 Claude 가이드). `GITHUB_TOKEN` 은 gh · Actions 와 겹쳐 피한다.
- **A5** trust-tier 감시 repo: `vercel` → `vercel/vercel`, `github-mcp` → `github/github-mcp-server`, `chrome-devtools` → `ChromeDevTools/chrome-devtools-mcp`, `railway-mcp-server` → `railwayapp/cli`.

- **A7 [확인]** `.mcp.json` 에서 `${GITHUB_PAT}` 미설정이면 설정은 그대로 로드되고 `claude mcp list` 가 그 서버에 missing-variable 경고를 내며 펼치지 않은 `${VAR}` 를 그대로 쓴다(공식 `code.claude.com/docs/en/mcp` §Unset variables without a default — 설계 검증 N1). 남은 확인: `GITHUB_PAT` 가 원격 서버에서 "빈 값으로 읽는 자격 변수" 집합 밖인지(Docker 실 CLI)

- **A9** `update` 는 vercel-cli 핀을 올려도 기존 설치자의 `package.json` 을 바꾸지 않는다(자산 재설치 없음 — ADR-101 Consequences 와 같은 성질).
