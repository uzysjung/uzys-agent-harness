## BLOCKER

### B1. `PRIOR_MCP_SERVERS` 가 "지우는 근거" 로 새는 범위가 열려 있다 — 옛 로그 ssr-nextjs 의 railway 가 걷힌다(미열거) · A/C 가 같은 디스크에 다른 결과

**근거**
- 설계 §7.1 ①: "`legacyMcpSeed` — 디스크 값이 이 표의 값과 같으면 그 sha 로 몫을 적는다". 표에는 `railway-mcp-server`·`chrome-devtools` 의 옛 값이 든다.

- railway 행은 **원래 `ssr-nextjs` 를 포함**했다가 #710 에서 빠졌다:
  `git log -p -- templates/track-mcp-map.tsv` → `cfe1b97`(2026-04-17) `+railway-mcp-server	csr-supabase|csr-fastify|csr-fastapi|ssr-htmx|ssr-nextjs|full …` / `05b967f`(2026-10-05, #710) 에서 `ssr-nextjs` 제거. 즉 **v26.164 이하로 깐 ssr-nextjs 설치본(몫 기록 없음 = `records !== "writer"`, `src/install-writes.ts:156`) 에는 옛 값의 railway 가 있다.**
- 그 설치본에서 이번 설계대로 update 하면: 렌더에 railway 없음(패턴 밖 · portions 없음) → PRIOR 표가 옛 값을 알아봄 → `remove` → 화면 `retired: railway-mcp-server`(note 가 비어 일반 문구). **설계 §7.2 에 이 행이 없다.**
- ADR-101 Consequences 는 정반대를 약속했다: "몫 기록이 없는 옛 기록(v26.161 이하)에서는 설치자 것으로 분류돼 그대로 남는다(관리 밖)". 설계는 ADR-101 을 Amends 하면서 이 문장을 바꾼다고 적지 않았다.
- 같은 메커니즘이 §7.2 C/chrome(비웹) 행의 근거다(A6). 결과: **기록 있는 설치본(A)은 chrome 을 남기고 `updated`, 옛 로그(C)는 걷고 `retired`** — 디스크가 같은데 이전 판에 따라 결과가 갈린다. 루트 CLAUDE.md §설치자 디스크 "CLI 조합 · **이전 판** · 첫 설치 여부가 달라도 같은 원칙" 위반. 설계 자신도 §7.2 끝에서 "note 가 빈 이름(railway · chrome 은 은퇴가 아니라 교체)은 `retired` 에 올 일이 없다" 고 적어 C/chrome 행과 모순이다.

**실패 시나리오**: v26.160 으로 ssr-nextjs 를 깐 사람이 update → Codex·OpenCode·`.mcp.json` 에서 railway 가 사라지고 화면은 "retired" 라 말한다(행은 살아 있다). 되돌리는 명령 안내도 없다(note 빈 이름 = 일반 문구).

**대안(둘 중 하나로 §7.1·§7.2·A6·테스트 5 를 고친다)**
- ⓐ(추천 — 같은 원칙): PRIOR 표에서 **지우는 근거**는 "하네스가 더는 어떤 트랙에도 렌더하지 않는 이름"(= github) 에만 쓴다. 트랙 표에 살아 있는 이름(railway·chrome)은 `legacyMcpSeed` 가 알아본 뒤 **선택 근거로 넘긴다**(A6 의 배선: `renderHarnessMcp` 의 `McpChoice` 에 "옛 로그에서 값으로 알아본 하네스 서버 이름" 을 더해 `selectedMcpServers` 가 `recorded` 처럼 본다 — 입력은 `rootFiles.created` 기록 + 하네스가 쓴 값과의 바이트 동일, 지금 `legacyMcpSeed` 와 같은 근거). 결과: A ≡ C — 남기고 `updated`(인자 갱신). 문장: "옛 로그에서 하네스가 만든 `.mcp.json` 의 서버 중 값이 하네스가 전에 쓴 것과 같은 것은 기록된 몫과 같이 다룬다 — 트랙 표에 살아 있으면 선택으로, 은퇴한 이름이면 걷는다."
- ⓑ(최소안): PRIOR 표를 은퇴 이름(github)에만 적용하고 살아 있는 이름은 지금처럼 관리 밖(ADR-101 Consequences 그대로, 화면 없음). 대가: C 의 chrome 은 `--no-usage-statistics` 를 못 받는다.
- 어느 쪽이든 §7.2 에 "C · railway · ssr-nextjs(옛 로그)" 행을 추가하고, ADR-104 Amends 에 ADR-101 Consequences 의 그 문장을 넣는다. 테스트 5 에 변이 ⓓ: "옛 로그 ssr-nextjs + 옛 값 railway → update 뒤 세 자리에 남는다" 를 손으로 적은 표본으로.

### B2. 첫 사용 인증 안내(NEXT)를 두는 자리가 update 화면에 없다 — §8 "install · update 공통" 은 틀린 전제

### B3. 비웹 트랙 기존 설치본의 chrome-devtools — 남기는 결정은 ADR-101 4ⓑ 와 정합하지만, 화면이 "기본이 아니게 됐다 · 빼는 법" 을 말하지 않아 사용자 결정이 도달하지 않는다

**근거**
