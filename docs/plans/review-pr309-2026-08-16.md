## New findings (author looked only at rule exclusion + page navigation)

### [HIGH] F1 — `agent-harness update` silently re-installs what the user unchecked, and labels it "added by this release"
`src/update-mode.ts:294-336` (`installNewAssets`) + `:308` (`trackOnlyFileAssets`) + `:482`
(`rules: ALL_RULES`). The exclusion is never persisted — `install-log.ts:98-101` records
`spec.tracks` and `spec.cli` only — so `update` has no way to know and re-derives the manifest
from tracks alone.

Executed (install with `baselineExclude` of one rule / one agent / one hook / one skill, then
`runInstall(mode:"update")` on the same dir):

| target | after install | after `update` |
|---|---|---|
| `.claude/rules/git-policy.md` | absent | **present** |
| `.claude/agents/reviewer.md` | absent | **present** |
| `AGENTS.md` contains `Git Safety` | false | **true** |
| `.agents/rules/git-policy.md` | absent | **present** |
| `.claude/skills/deep-research` | absent | absent (dir entries are skipped) |
| `.claude/hooks/protect-files.sh` | absent | absent |

Report payload: `installedNew = [".claude/rules/git-policy.md", ".claude/agents/reviewer.md"]`,
`restored = []`, `needsReinstall = [".claude/hooks/protect-files.sh"]`. Rendered
(`install-render.ts:445`) as **"added by this release"** — false, they were shipped in the same
release the user just installed from — and (`:460`) **"new in this release but update cannot
wire them — run `agent-harness install` to get them"**, i.e. every future `update` nags the user
to re-acquire a hook they deliberately removed.

Two consequences beyond the resurrection itself: (a) behavior is kind-dependent — rules/agents
come back, skills/hooks do not — so the user cannot form any model of what "uncheck" means;
(b) **ADR-074:63 is untrue as written**: "`update` 는 이 목록을 묻지 않는다(기존 설치본의 선택을
그대로 갱신한다)". It does not preserve the selection; it reverses it. A scope carve-out resting
on a false premise is not a carve-out. Either persist `baselineExclude` in the install log and
have `installNewAssets`/`refreshExternalCli` honor it, or change the ADR to state plainly that
`update` restores excluded baseline assets — but do not ship the sentence that is currently there.

### [HIGH] F2 — Step 5 confirm screen is byte-identical with and without exclusions, and its context-cost number counts the excluded assets
`src/interactive.ts:284-290` builds the confirm summary without passing `baselineExclude`;
`formatSummary` (`:348-397`) has no branch for it, and `:383`
`residentCost(buildManifest(spec).filter((e) => e.applies(spec)))` counts the full manifest.

Executed: `formatSummary(base)` vs `formatSummary({...base, baselineExclude:[2 rules, 1 agent,
1 skill, 1 hook]})` → **identical strings**, both printing
`session-start context cost: 23 items resident · ~5036 tokens/session (rules 6 … agents 9 …)`
when 4 rules and 8 agents will actually be installed.

Why this is HIGH rather than cosmetic: this is the last screen before writing to the user's
repo, `-User removed:` on the same screen already reports external-asset removals (so the
absence reads as "nothing was removed"), and the overstated number is the repo's own primary
metric (Context Cost per Install). A user who unchecks 20 items specifically to cut resident
cost is shown the unchanged figure and gets no confirmation their choice registered.

### [MEDIUM] F3 — non-Claude installs exclude silently (no "excluded by you" row)
`src/installer.ts:323-328`: the non-claude branch calls `installCliNeutralAssets`
(`:550-567`), which returns `emptyClaudeBaseline()` with `excluded: []`. Executed with
`cli:["codex"]` + `baselineExclude:["baseline:rules/git-policy"]`: the rule **is** dropped from
`AGENTS.md` (`Git Safety` false, `Documentation Boundaries` true) but `report.baselineExcluded`
is `[]`, so the new row at `install-render.ts:646` never renders. The one screen element added
to prove exclusion worked is absent exactly where the exclusion is least visible (no
`.claude/rules/` directory to eyeball). This is the surface-asymmetry-by-CLI shape the repo
logs as adjudicated three times.

### [MEDIUM] F4 — `add` mode reports "excluded by you" for a file that is still on disk
Executed: full install, then `runInstall(mode:"add", baselineExclude:["baseline:rules/git-policy"])`.
`.claude/rules/git-policy.md` is **still present** afterwards (nothing deletes it) while the
screen prints `excluded by you — rules/git-policy`. The wizard's mitigation for this class of
confusion — the `● installed` marker plus the "체크 해제해도 제거되지 않는다" line
(`prompts.ts:507-509`) — cannot fire for baseline items: `installedSet` is built from
`installed.installed.map(id => "asset:" + id)` (`interactive.ts:246`) and the install log holds
no baseline ids. So in `add`/`reinstall` the user sees every baseline item unmarked and freshly
checked, unchecks one, and is told it was excluded when it was not.

### [MEDIUM] F5 — wizard offers baseline items that `--with ecc-plugin` guarantees will not be installed
`listBaselineTargets` evaluates `applies()` with `withEcc` and `selectedInternalSkills`

It is not trivially fixable in-page (ecc-plugin is chosen on a later page of the same step), so
either recompute on submit, or say so in the ADR instead of claiming the opposite.

## Positive observations (specific)

- The two exclusion predicates are one function used in both places
  (`isBaselineExcluded` at `installer.ts:382` for the copy loop and `:359` for the CLI fan-out),
  so `.claude/` and `AGENTS.md` cannot drift apart — verified by the A1 table.
- `excluded` is deliberately kept out of `skipped` (`installer.ts:349-355`), so a user choice is
  not reported as a missing-source defect. Correct call.
- Structural assets are excluded by target-prefix rather than by a name list
  (`baseline-targets.ts:126-152`), so a bogus id cannot half-install a project — I passed
  `".claude/settings.json"` and `"CLAUDE.md"` as exclusion ids and both files still installed.
- `tests/wizard-page-parity.test.ts` guards the *screen*, which is the layer that would otherwise
  disappear with all data/install tests still green; the author states they verified that by
  deleting both pages and watching 25 tests stay green.
