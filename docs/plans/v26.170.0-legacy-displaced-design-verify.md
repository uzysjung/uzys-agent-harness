## BLOCKER

### B1. "지문 일치 = 하네스 것 = 백업 없이 삭제" 는 사용자 확정 문장을 바꾸는 결정이다 — 설계가 정할 수 없다 (검증자 목록 ① · ⑤ · 가정 2)

**주장.** 루트 `CLAUDE.md` §설치자 디스크의 첫 불릿 *"하네스 몫은 설치 기록 하나가 정한다. 디스크 존재는 근거가 아니다"* 는 **사용자 확정(2026-09-27, #551)** 이고 ADR-097 결정 1("소유 근거 = 기록에 있는 경로")·ADR-096 D6 가 같은 말을 한다. 설계 §8.2 는 이 불릿에 *"기록이 없는 옛 판의 파일 · 절은 그 판의 바이트 그대로일 때만 하네스 것이다"* 를 **덧붙여 쓰고**, §8.1 ADR-111 로 두 번째 근거를 세운다. 설계 자신이 §11 ① 에서 "사용자 결정 7 과 정반대 방향" 이라 적었다. 사용자 확정 문장의 변경은 설계가 결정할 수 없다 — 사용자 결정으로 올려야 한다(브리프 · `change-management` Major CR).

**증거 — 같은 바이트를 두 경로가 반대로 부른다.**
- `v26.170.0-design-evidence/container/26.125.0-A/new-update-1.txt:58-61` — v26.169 update 가 옛 판의 `.claude/agents/strategist.md` 를 **첫 접촉**으로 읽어 `policy files had files with these names … — yours, put back on uninstall` · `data-analyst.md` 를 `same as the harness version … (left yours in place)` 라 말하고 `displaced` 로 적는다(결정 7 · Q3). 그 뒤 uninstall(A) 은 두 파일을 **"yours"** 로 되돌리거나 남긴다.
- 설계 §2 #6·#9 · §4.4 ⓑ′ — 같은 바이트의 같은 파일을 update 를 거치지 않은 B 흐름에서는 **"하네스 것"** 으로 백업 없이 지운다. 설계 §1.2 의 "update 를 몇 번 거쳤든 결과가 같다" 는 이 두 파일(그리고 v26.169 update 가 displaced 로 적는 모든 옛 하네스 파일)에 대해 거짓이다 — 기록 모양이 결과를 가른다.
- `src/commands/install-render.ts:88` `LEGACY_ANCHOR_NOTE = "legacy anchor · … delete it when you no longer need it"` · `26.125.0-A/new-update-1.txt:52-69` "은퇴 — … 를 지워도 된다". update 는 설치자에게 **보관 여부를 맡기는** 말을 하고, 설계의 uninstall 은 그 판단 없이 백업도 없이 지운다(설계 §11 ⑲ 가 인지하되 넘어갔다).
- 설계 §2 #9 "내용이 하네스 것이라 손실 없음 — 다시 깔면 돌아온다" 는 **은퇴 자산에는 거짓**이다: 은퇴 스킬 29~47파일 · `commands/ecc` · 옛 앵커는 현행 번들에 없어 다시 깔아도 돌아오지 않는다(복구 = 옛 npm tarball). "지워도 된다" 고 들은 뒤 **쓰려고 남긴** 설치자가 잃는다.

**판정.** 결정 7 자체(첫 접촉 write 경로)를 글자 그대로 바꾸는 것은 아니지만, 결정 7 이 세운 규율("같은 내용 = 하네스 것으로 삼지 않는다 · 기록 없는 파일에 소유를 주장하지 않는다")과 원칙 문장을 **기록 밖 영역에서 뒤집는다**. 기록된 `no-sha` 자리(§4.4 ⓑ, `next = disk`)는 ADR-097 표의 뜻 안이다 — 기록이 이미 하네스 자리라 말하고 지문은 백업 생략만 정한다. 문제는 **기록 밖**(ⓑ′ · `AGENTS.md` 절 걷기 · 꼬리 절 필터)이다.

### B2. 지문 회수(ⓑ′ · ⓐ₀)가 **깔린 CLI 집합**으로 범위를 가르지 않는다 — 하네스가 쓴 적 없는 자리의 설치자 파일이 지워진다

**주장.** 설계 §4.4 ⓑ′ 는 `.claude/{rules,agents,commands,hooks,skills}` · `.claude/CLAUDE.md` · `.agents/skills` 를 "`scope.has` 안만" 걷고, §4.3 의 ⓐ₀(기록 없는 옛 `AGENTS.md` 걷기)는 "`removeHarnessFiles` ⓐ 앞" 에 둔다. 둘 다 **`installedClis(log)`** 를 보지 않는다. 전량 uninstall 의 `FULL_SCOPE.has = () => true`(`src/commands/uninstall.ts:1515-1516`)이므로:
- **codex 단독(또는 opencode·antigravity) 설치본**의 `.claude/` 는 설치자 디렉터리다(ADR-096 Alternatives 3 · BLOCKER-5 — "설치자가 직접 만든 `.claude/`"). 그 안에 설치자가 다른 프로젝트에서 복사해 둔 하네스 룰·스킬(바이트 그대로)이 있으면 ⓑ′ 가 지운다. 기존 ⓑ 는 `recorded()` 의 `legacyOwned = clis.includes("claude") && …`(`src/recorded.ts:107-108`) 로 이것을 막는다 — ⓑ′ 에는 그 문이 없다.
- **claude 단독 설치본**의 `AGENTS.md`(설치자가 다른 프로젝트의 하네스 판을 복사해 와 머리 블록인용이 그대로) 는 하네스가 쓴 적 없는 파일이다. 기존 `stripSharedFiles` 는 `relevant()`(`uninstall.ts:1790-1794` — 소유 CLI 가 깔렸을 때만)로 읽지도 않는다. ⓐ₀ 를 "ⓐ 앞" 에 두면 그 문을 지나치고, 설계대로면 절을 걷고 **남는 것이 없으면 파일을 지운다**.

**실패 시나리오.** codex 로만 깐 팀이 `.claude/rules/git-policy.md` 를 손으로 복사해 Claude Code 용으로 쓰다가 `agent-harness uninstall --yes` → 그 룰이 사라진다(B1 ⓐ 면 백업도 없다). 화면은 "left by an older harness version" 이라 말한다 — 거짓이다(그 판은 거기 설치된 적 없다).

**고칠 문장(§4.4 ⓑ′ · §4.3 ⓐ₀ 에 넣는다).** "지문 회수의 범위 = `scope.has` ∩ **기록의 CLI 집합이 그 자리를 쓴다** — `.claude/**` · `.claude/CLAUDE.md` 는 `installedClis(log)` 에 claude 가 있을 때만, `.agents/skills/**` 는 codex·opencode·antigravity 중 하나가 있을 때만(`ownersOf(path)` ∩ `installedClis(log)` ≠ ∅, `recorded()` 의 `ownedByLog` 와 같은 술어). ⓐ₀ 는 `stripSharedFiles` 의 `relevant()` 안쪽에 둔다(`AGENTS.md` 의 소유 CLI 가 깔렸을 때만)." 테스트 = §7.1 `uninstall-legacy-fingerprints` 에 ⑧ "codex 단독 로그 + `.claude/rules/<룰>.md`(옛 판 바이트) → 그대로 남는다" · ⑨ "claude 단독 로그 + 머리 지문 있는 `AGENTS.md` → 바이트 그대로" 를 더하고, CLI 문을 빼는 변이에서 red.

### N3. 꼬리 절 삭제는 update 에서 **조용한 overwrite** 다 — 화면 줄 하나 (검증자 목록 ⑤)

### N6. §7.1 `uninstall-legacy-fingerprints` ③ "스크립트를 남긴 1줄 유지" 는 **fieldless 로그에서 성립하지 않는다**

### N7. ⓑ′ 제외 목록에 `excluded` 경로를 더한다

### N11. PR 분할 · 완료 기준 (완료 기준 6)
- 네 PR 은 main 기준이지만 **순서 의존**이 둘 있다: PR-B(`--only` 되돌리기)가 PR-A 의 `src/displaced.ts` 를 쓰고, PR-D 가 PR-C 의 `src/legacy-fingerprints.ts` 를 쓴다. 스택 PR 은 아니나 **B·D 는 A·C 머지 전에 착수할 수 없다**(또는 B·D 가 그 모듈을 자기 PR 에 들고 와야 한다). §6 에 "A ‖ C 병렬 → B · D 는 각각 머지 뒤" 로 적는다.

### N13. 구현자가 정해야 할 암묵 사항 (완료 기준 7) — 설계에 한 줄씩 넣을 것
1. ⓑ′ 의 걷기 단위: 디렉터리 재귀 깊이(스킬 하위 폴더 포함) · 비텍스트 파일(sha 는 바이트라 무관하지만 `readFileSync` 실패 → `unjudged`) · 심링크 **디렉터리**(`.claude/skills/<id>` → `.agents/skills/<id>` 링크 슬롯, #524)는 통째 건너뛴다.
2. ⓑ′ 와 `pruneFrom`/빈 디렉터리 걷기(ⓓ)의 연결 — 지문으로 지운 파일의 부모도 `pruneFrom` 에 넣는다고 §4.4 가 적었다(맞음). `.claude/commands/ecc/` 같은 폴더가 비면 걷힌다는 기대를 테스트 ①에 명시.
3. `--only` 되돌리기 뒤 `settleLog` 가 `rootFiles` 를 처음 쓴다(§9.2 ⑧) — `withSkillsLock`(`uninstall.ts:289`) 이 `--only` 에서 `rootFiles` 를 빈 배열로 만드는 자리와 섞이지 않게, `withoutRestored(installLog.rootFiles, …)` 는 **원본** `installLog.rootFiles` 에 건다.
4. `update-mode.ts:618` 되돌리기의 입력 로그 = `logAtStart`(그 실행 시작 시점) — `pruneOrphans` 뒤 `refreshPolicyBaseline` 이 로그를 다시 쓰므로 `recordDisplaced` 자리에서 `readInstallLog` 를 **다시 읽은 뒤** `withoutRestored` 를 걸어야 중간 쓰기를 덮지 않는다.
5. `restoreDisplaced` 의 `has` 술어가 update 에서 `.claude/<dir>/<file>` 와 `rootFiles.path`(프로젝트 상대) 의 같은 표기를 쓰는지 — `pruneOrphans` 는 파일명만 돌려준다(§4.1 이 접두를 붙이라 적음, 맞음).
6. ⓐ₀ 의 결과 파일에 `neutralizeScaffoldBanner` 를 적용하는가(`uninstall.ts:2254` — 기존 `removeHarnessMadeShared` 는 한다). 옛 파일의 Project Context 를 보존할 때 배너를 떼지 않으면 "SCAFFOLD — not filled in yet" 이 하네스 없는 프로젝트에 남는다.
7. `isLegacyHarnessAgentsMd` 가 `block` 판정 뒤의 **`--cli` 재렌더**(`rerenderAgentsMd`, `agentsMdRerenderSet` 은 기록 있는 파일만) 에서도 같은 길을 가는지 — 기록 없는 옛 파일은 재렌더 대상이 아니므로 `--cli codex`(opencode 남음) 뒤 옛 31절이 남는다. 범위 밖이면 §9.1 에 한 줄.
8. 화면 동사: "left by an older harness version" 은 ADR-097 결정 9 의 여섯 동사 밖이다 — `removed … (older harness version, byte-identical)` 처럼 여섯 안의 동사로 시작한다.
