### B4. Docker 확인 D1–D3 이 **jq 부재로 깨진다** — D3 는 거짓 초록

- 실측: `docker run --rm node:22-bookworm sh -c 'command -v jq || echo ABSENT'` → **`jq: ABSENT`**(git 은 있음, node v22.23.3). 설계가 고른 이미지 그대로다. 이 리포의 실 CLI 이미지는 그래서 `apt-get install -y … jq` 를 한다(`test/docker/Dockerfile.realcli:16-18`).
- D1·D2 는 `bash -euo pipefail` 이라 `cat ~/.claude/plugins/installed_plugins.json` 다음 줄은 돌아도 D2 의 `jq -r … .harness-install.json` 에서 **127 로 중단** — 세 스킬 양쪽 자리 · `.github/workflows` · D2b 확인이 한 줄도 안 돈다.
- D3 는 `-e` 없이 `diff <(jq -S .plugins …) <(jq -S .plugins …) && echo "OK plugins unchanged"` — 프로세스 치환 안의 jq 가 127 이어도 `diff` 는 **빈 스트림 둘을 비교해 0** → "OK plugins unchanged" 가 찍힌다. 통과 기준 "플러그인 목록 diff 0" 이 **아무것도 재지 않고 초록**이다(cli-development 룰 "빈 결과는 부재의 증거가 아니다" 그 자체).
- 넣을 문장: 세 스크립트 머리에 `apt-get update -qq && apt-get install -y -qq jq >/dev/null && command -v jq` (또는 jq 를 `node -e` 로 대체) + D3 의 diff 앞에 대조군 `jq -e '.plugins | length > 0' /tmp/plugins-before.json`(0 이면 무효 처리). `scripts/check-absence.sh --control … --subject …` 형태로 적어도 된다.
