## BLOCKER-1 — 옛 전역 범위(`scope: "global"`) 기록에서는 아무것도 바꾸지 않은 Update 가 opt-in 번들 스킬을 뺀다

**File**: `src/interactive.ts:136` (`const projectSkills = log.scope === "global" ? [] : skills;`)과 `:274` · `:695`

**무엇이 일어나나**: 전역 범위 기록에서는 깔린 opt-in 번들 스킬이 3단계에서 체크되지 않은 채 시작한다(`projectScoped` 에서 빠지기 때문). 그런데
`classifyUpdateIntent`(:274)와 `confirmUpdate`(:695)는 범위와 상관없이 `recordedBundledSkillIds(log)` 를 보고, "기록돼 있는데
체크가 안 됐다"를 해제로 읽는다. 그래서 설치자가 **아무것도 건드리지 않고 확인만 눌러도** 엔진이 add 가 되고, 화면에는
`-Unchecked by you: gemini-delegate` 와 `RUNS AS … --scope global --without gemini-delegate` 가 뜬다. 실행하면 기록에 그 스킬의
빼기가 남는다. 설치자가 하지 않은 해제가 화면과 기록에 "설치자가 한 일"로 남는 것이다.

**회귀임을 확인한 방법(음성 대조)**: 같은 실험을 88096fe 의 `src/interactive.ts` 로 돌리면 `mode update` · `RUNS AS agent-harness update`
가 나온다. 변경 후에는 `mode add` · `--without gemini-delegate` 가 나온다.

**구현 가정이 틀린 이유**: 전역 범위는 외부 자산 설치기(`external-installer.ts` 의 plugin `--scope user` · `npx skills -g` · `npm -g`)에만
적용된다. 번들 스킬은 범위와 상관없이 늘 프로젝트 `.claude/skills/`·`.agents/skills/` 에 깔린다(ADR-097 결정 6: "하네스 파일은
언제나 프로젝트 안이다"). `InstalledTargetState` 주석이 말하는 "사전 체크하면 project 에 한 벌 더 깔린다"는 위험은 번들 스킬에는
없다. 같은 자리의 MCP(`mcp`)도 범위로 거르지 않는다. 인계서에도 "이 분기는 테스트 없음"이라고 적혀 있다.

**누가 이 상태를 만드나**: ADR-097 전에 `--scope global` 로 설치했고, opt-in 번들 스킬을 `--with` 로 더한 설치본이다. 새 전역 설치는
거절되지만, 옛 전역 설치본은 update 가 계속 받는다(ADR-097 결정 6). 해당하는 사람은 적지만, 실제로 쓰는 update 위저드의 기본 경로다.

**재현**: `rev-wizard/repro/zz-review.tmp.test.ts` 의 케이스 `B:`. 이 파일을 `tests/` 에 두고 `npx vitest run tests/zz-review.tmp.test.ts -t "B:"`
를 돌린다. 하는 일은 `install --with gemini-delegate`(claude · tooling) → 기록의 `scope` 를 `"global"` 로 → 위저드에서 3단계를 그대로 두고 확인.

**완료 기준**: 기록 범위와 상관없이, 깔린 번들 스킬은 체크된 채 시작하거나(사전 체크) 해제 판정에서 빠져야 한다. 어느 쪽이든 손대지 않은
전역 범위 기록이 refresh 로 끝나는지 무는 테스트가 있어야 한다.

## 판정 항목별 결과

### 1. #760 의 "해제 = `--without <id>`" 확장은 맞는 확장이다(범위 침범 아님)
- 표시만 고치면 체크된 행을 풀어도 아무 일이 없다. 그러면 위저드 원칙("체크 = 확인 뒤 디스크에 있다", #709 기록된 MCP 와 같은 규칙)과
  화면이 어긋나므로, 요청한 기능을 올바르게 쓰려면 필요한 범위다.
- **디스크에서 일어나는 일(직접 실행)**: 해제 → add 실행(`executeSpec` 경로)을 하면 스킬 파일은 **남는다**. 기록에는 `excluded` ·
  `skillExclude` 에 그 id 가 더해지고, `skillFiles` 기록(원래 sha)도 유지된다. 이어서 `update` 를 돌려도 파일은 남는다.
  설치자가 고친 SKILL.md 는 내용 그대로 남는다(편집 sha 와 원래 sha 를 대조해 확인). 지우는 동작이 아예 없으므로 백업할 일도 없다.
  "파일은 이 흐름 어디서도 지워지지 않는다"(`runUpdateFlow` 주석)는 그대로 지켜진다. 파일을 지우는 것은 Uninstall 몫이다.
  재현: `repro/zz-review.tmp.test.ts` 케이스 `A` · `C` · `C0`.
- 이 결과는 CLI 의 `install --without gemini-delegate` 와 같은 엔진을 탄다. 새 삭제 경로는 없다.

### 2. `--without mcp:context7` 의 뜻이 넓어진 것 — 설치자가 직접 쓴 내용은 잃지 않는다. 전용 테스트는 필요 없다(NOTE-1 참조)

### 3. context7 정의를 tsv 로 옮긴 것 — 확인한 모든 경로에서 출력이 같다

## NOTE (선택 — BLOCKER 와 무관)

- **NOTE-1 `mcp:context7` 의미 변화가 문서에 없다.** ADR-106 은 chrome-devtools 의 같은 변화를 Consequences 에 적었는데

  update 화면도 이 제거를 따로 말하지 않는다(`external CLI artifacts 2 files updated` 가 `3 files updated` 로 바뀔 뿐이다).
  릴리즈 때 CHANGELOG 한 줄과 ADR-106(또는 ADR-101 결정 5)에 Amended 한 줄을 남기기를 권한다.
- **NOTE-2 supabase 기본 패키지 `@supabase/mcp-server` 가 npm 에 없다.** 직접 확인: `npm view` 가 E404 이고, 대조군
  `@supabase/mcp-server-supabase` 는 0.13.0 으로 존재한다. 이번 변경 전부터 있던 문제지만, 이번 커밋으로 카탈로그가 이 서버를 vetted 로
  광고하고 **모든 트랙에서 `--with supabase` 로 고를 수 있게** 되어 문제가 닿는 범위가 넓어졌다. 별도 이슈로 처리하기를 권한다
  (고치면 새 설치 바이트가 바뀌므로 이 PR 범위 밖이다).
- **NOTE-3 해제 뒤 위저드가 매번 add 가 된다.** 한 번 해제한 opt-in 번들 스킬은 `skillExclude` 에 남는다. 이후 위저드를 그대로 두면
  `confirmed.skillExclude`(추천 대비 빼기만 셈) `[]` ≠ 기록 `[gemini-delegate]` 이 되어 매번 add + `--without gemini-delegate` 가 된다.
  CLI 로 `--without` 한 경우에도 이미 있던 동작이지만, #760 이 이 상태를 위저드로 만들 수 있게 했다. 손실은 없다(add 도 refresh 를
  포함한다). 재현: `repro/zz-review.tmp.test.ts` 케이스 `A2`.
- **NOTE-4 이슈 #751 본문은 착수 조건으로 "범위 결정(SPEC Non-Goals '기본 설치 항목 재정의') 뒤 착수"를 적었다.** 기본값이 그대로라
  Non-Goals 를 넘지 않는다는 판단은 타당해 보인다. 다만 그 결정이 실제로 내려졌는지는 리드가 확인할 몫이다. SPEC Change Log 2026-10-11 줄은
  "MCP 기본 서버에 한해"라고 적혀 있다.
- **NOTE-5 (LOW) ADR-039 단언 강화.** `EXTERNAL_ASSETS.some(a => a.method.kind === "plugin" && a.method.pluginId.startsWith("context7@"))`
  가 false 인지 보면 원래 의도("플러그인 미등록")를 id 와 무관하게 문다.
- **NOTE-6 (LOW) `docs/REFERENCE.md` 의 `--without <key id>` 행** 첫 예시가 여전히 `mcp:context7`(a server in `.mcp.json`)이다. 이제
  `mcp:` 키 id 는 모든 하네스 서버에서 세 자리 모두에 닿으므로, ".mcp.json 한 자리만 빼는 예"로는 맞지 않는다(같은 행의 Exception 문장과
  충돌한다). 그 밖에 낡은 주석(`templates/codex/config.toml.template`, `tests/doc-asset-ref-drift.test.ts`)은 구현자가 이미 적었다.
