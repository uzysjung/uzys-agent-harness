# 상주 컨텍스트 비용 — 비용대비 효과 검증 (Opus 5 기준)

- 일자: 2026-07-26 · 릴리즈: v26.136.0
- 계측 규약: `src/context-cost.ts` — **문자수 ÷ 4**. 실측 토크나이저가 아니라 이 리포의 근사
  규약이고, 표기는 항상 `~`. **바이트가 아니라 문자다** (한글은 UTF-8 3바이트라 바이트로 세면
  약 2배 부풀려진다 — 첫 시도에서 실제로 그랬다).
- 판정 기준: **상주(resident)** = 매 세션 상시 올라가는 것(rules 전문 · CLAUDE.md · skill/agent
  descriptor) / **발화(fired)** = 트리거될 때만(skill body). 단위가 다르므로 합산하지 않는다.

**룰이 64%** 로 최대 항목이고, 스킬 descriptor 는 9% 다.

## 2. Opus 5 환산 — 달러는 제약이 아니다

단가: input $5 / output $25 per MTok. 룰·CLAUDE.md 는 프롬프트 **선두의 안정 prefix** 라
2번째 요청부터 cache read(0.1× = $0.50/MTok)로 청구된다. 세션 시작 1회는 cache write(1.25×).

| 대상 | 상주 | 1,000 요청 (uncached) | 1,000 요청 (**cache read**) | 세션당 cache write |
|------|------|------------------------|------------------------------|---------------------|
| 하한 (~4,269) | 4.27M tok | $21.35 | **$2.13** | $0.027 |
| tooling (~5,877) | 5.88M tok | $29.39 | **$2.94** | $0.037 |
| full (~9,789) | 9.79M tok | $48.95 | **$4.89** | $0.061 |

컨텍스트 점유율: tooling 5,877 / 1M = **0.59%**.

**결론: 돈도 용량도 프루닝의 근거가 못 된다.** 1,000 요청에 $3 수준이고 창의 0.6% 다.
"토큰이 아까워서 룰을 지운다"는 논증은 이 수치 앞에서 성립하지 않는다.

## 3. 그러면 실제 비용은 무엇인가 — 그리고 왜 미측정인가

남는 가설은 **지시 준수율 희석**: 룰이 늘수록 개별 룰의 구속력이 떨어진다.
`harness-health-audit` §C1 이 인용하는 근거(Chroma context rot · Liu et al. lost-in-the-middle)는
**길이가 늘면 성능이 떨어진다**까지는 말하지만, "룰 N개에서 준수율 M%" 같은 수치는 주지 않는다.

**이 리포에서 그것을 측정한 적은 없다.** 정확히 그걸 재려던 지표가 `Justified Asset Ratio`
(NORTH_STAR 2차 NSM, ADR-043/044)인데 **미구현**이다.

따라서 이 감사의 결론은 "비용을 줄여라"가 아니라 **"비용의 정의를 고쳐라"** 이다.
달러로는 무시 가능하고, 유일하게 값이 나가는 축은 아직 재지 못한다.

### 그래서 v26.136.0 에서 무엇을 근거로 잘랐나

"준수율에 나쁠 것 같다"는 추정을 **쓰지 않았다**. 잘라낸 것은 전부 **구조적으로 확인 가능한**
결함이다 (상세 = `gap.md`):

1. **배포 부적합** — 설치자 프로젝트에 해로운 규약 (예: 이 리포의 CalVer 를 "절대 위반 금지"로
   배포판에 박아 두면, 낯선 사람의 SemVer 프로젝트에서 에이전트가 버전 체계를 바꾸려 든다).
2. **dangling 참조** — 설치자 환경에 존재하지 않는 문서/룰을 가리키는 문장.
3. **중복 블록** — 같은 산출물 형식이 한 파일에 두 번.

이 셋은 **없어도 되는 것이 아니라 틀린 것**이다. 크기 때문에 자른 게 아니라 틀려서 잘랐고,
그 결과가 **−279 tokens/세션**(전 트랙 동일)이다.

## 4. 미측정 — 정직하게 남기는 것

| 항목 | 왜 못 했나 | 무엇이 풀리면 되나 |
|------|-----------|---------------------|
| chars/4 근사의 실제 오차 | 실측 토크나이저와 대조한 적이 없다. 한글은 토큰/문자 비가 높아 **실측이 이 값보다 클 가능성**이 있다 | `messages.count_tokens` API 로 대조 (외부 호출이라 사용자 승인 필요) |
| 훅 stdout 의 컨텍스트 비용 | `context-cost.ts` 는 훅을 "비대상"으로 둔다. 훅 자체는 안 올라가지만 **PreToolUse/PostToolUse 의 stdout 은 대화에 들어간다** | 세션 트랜스크립트에서 훅 출력 바이트를 집계하면 잰다 |
| 지시 준수율 희석의 크기 | with/without eval 미실행 (ADR-043 2단계) | `Justified Asset Ratio` 구현 |
| 세션당 요청 수 분포 | 보유 데이터 없음 — cache write vs read 비중 판정에 필요 | 세션 로그 집계 |
| MEMORY.md 성장 | 이 리포 상주의 약 20%인데 ratchet 게이트가 없다 | baseline 에 메모리 인덱스 축 추가 |

**사용자의 "훅이 토큰을 낭비한다" 전제는 절반만 맞다** — 훅 파일 자체는 상주 0이지만 그 출력은
대화에 들어간다. 그 절반이 위 표의 2행이고, 아직 안 쟀다.
