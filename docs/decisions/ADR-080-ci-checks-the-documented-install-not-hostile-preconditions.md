# ADR-080: CI 는 **문서대로의 설치**를 보고, 적대적 사전 상태는 안 본다

- Status: Accepted
- Date: 2026-08-28
- PR: #380
- Context 근거: ADR-077 (G1~G5) · ADR-079 (컨테이너는 세 질문만)

## Context

G1(#370)의 AC 는 세 축이었다: ⓐ 4 CLI 각각 설치 완주 ⓑ **비정상 사전 상태**(자산 자리에
심볼릭 링크·일반 파일·FIFO)에서도 완주 ⓒ 트랙 다수.

ⓑ 를 컨테이너로 구현해 실제로 돌려 봤고, **초록이 나왔다**. 그런데 그 과정에서 두 가지가 드러났다.

1. **이미 소유자가 있다.** 그 판정은 `src/foreign-slot.ts` 한 술어가 하고,
   `tests/install-foreign-skill-dir.test.ts` 20건이 `runInstall` 을 직접 불러 심링크·일반 파일·
   깨진 링크·FIFO·중첩 링크까지 덮는다. 컨테이너판은 같은 질문을 더 느리게(설치 4회, 약 95초)
   다시 물었다.
2. **검사기를 지키는 검사기가 자라났다.** opencode 는 번들 스킬을 스킬 슬롯이 아니라
   `.opencode/commands/<id>.md` 로 내보내므로 심어 둔 자리를 겨냥하지 않는다. 그래서 초안이
   opencode 에서 틀렸고, 나는 시나리오 안에 "이 CLI 가 이 계열을 겨냥하는가"를 판정하는 로직을
   한 겹 더 얹어 통과시켰다. 방어를 막으려고 방어를 만든 형태다.

사용자 판정(2026-08-28): *"테스트는 도큐먼트 보고 설치를 그대로 했으면 기대대로 추가되었는지만
보면 된다. 번들 스킬은 AI 코딩 도구의 정해진 위치에 가면 되는 거지. 이걸 막기 위해 방어 코드를
만들고 또 이걸 막으려고 방어 코드 만들고 이런 식으로 하지 마라. 특수한 예외는 어쩔 수 없다."*

## Decision

**CI 컨테이너는 문서에 적힌 설치 명령의 입력과 결과만 본다.** 사용자가 자산 자리에 미리 무엇을
놔뒀는지는 CI 의 범위 밖이다.

- **범위 안** — 문서대로 설치했을 때 고른 항목이 그 도구의 자리에 생기는가.
- **범위 밖** — 자리를 남이 점유한 상태(심볼릭 링크·일반 파일·FIFO·깨진 링크)에서의 동작.
  이건 `foreign-slot.ts` 와 그 단위 테스트가 소유한다. 크래시(#343)는 이미 고쳤고, 그 회귀는
  `npm run ci` 안에서 이미 막힌다.
- **번들 스킬과 외부 스킬을 함께 본다.** 두 배달 방식은 자리 규약이 다르다 — 실측
  2026-08-29: 외부 스킬(`npx skills add`)은 codex·opencode·antigravity 가 `.agents/skills/`
  **한 자리를 공유**하고 Claude Code 만 별도 사본을 받는 반면, 우리가 복사하는 번들 스킬은
  opencode 만 `.opencode/commands/<id>.md` 로 갈린다. 한쪽만 보면 나머지가 빠져도 안 보인다.
- **G1 이 CI 에 남기는 것은 축 하나** — **CLI 를 하나만 골랐을 때의 도달**
  (`test/docker/scenarios/scenario-single-cli.sh`). 기존 두 게이트는 4 CLI 를 한 호출에 몰아
  주므로 합집합만 보이고, "OpenCode 만 쓰는 사람이 받는가"는 아무도 안 본다 — #344 가 정확히
  그 형태로 사용자에게 갔다.
- **자리 매핑 표를 만들지 않는다.** 도구마다 규약이 다르므로(claude=`.claude/skills/<id>/` ·
  codex·antigravity=`.agents/skills/<id>/` · opencode=`.opencode/commands/<id>.md`) 표를 적으면
  규약이 정상적으로 바뀔 때 제품이 아니라 표가 먼저 썩는다. 항목이 그 도구 트리 안에 있으면 됐다.

## Alternatives

- **ⓑ 를 컨테이너에도 남긴다** — 기각. 같은 술어를 두 층에서 묻고, 느린 쪽이 먼저 썩는다.
  실제로 초안이 opencode 에서 오탐을 냈고 그걸 덮으려 로직이 자랐다.
- **ⓒ 트랙 다수를 컨테이너에 넣는다** — 기각(이번 범위). 트랙마다 자산 구성이 달라 기대 목록
  유도가 다시 복잡해지고, `install-matrix.yml` 이 이미 멀티트랙 core 를 본다. **다만 그건
  게시를 막지 않는다 — 미검증 축으로 남는다.**
- **`single-cli` 를 신호로만 돌린다** — 기각. #344 는 사용자가 발견한 결함이고 대상은 우리
  설치다. 사용자 확정 기준(2026-08-28, ADR-079)에서 **우리 설치는 차단·남의 CLI 는 신호**다.

## Consequences

- `publish: needs: [ci, docker-e2e]` 의 `docker-e2e` 가 3단계가 된다. 릴리즈 **+약 1.6분**
  (총 약 3.5분). 비싸지면 먼저 강등할 후보는 이것이다 — 근거는 위 Alternatives 세 번째 줄이다.
- ⓑ 축이 CI 에서 회귀하면 `npm run ci` 의 단위 테스트가 잡는다. 컨테이너는 안 잡는다 —
  **의도된 공백**이므로 다음 감사에서 "빠졌다"로 세지 않는다.
- 트랙 다수 축은 게시를 막지 않는 채로 남는다. 이 사실을 ship 보고에 미검증으로 적는다.
