# ADR-112: 기록이 global 인 외부 스킬의 프로젝트 사본은 하네스 몫으로 회수한다

- Status: Accepted
- Date: 2026-10-19
- PR: TBD
- Issue: #851 (AC3)

## Context

v26.174.0 이하의 update(`refreshExternalSkills`)는 외부 스킬을 자산별 기록 scope 가 아니라 로그 하나의 `log.scope` 로 다시 받았다.
global 로 깐 자산 뒤에 플래그 없는 재설치가 있던 설치본(mixed 이력 — #560 이 받아 주는 상태)에서는 `log.scope` 가 project 라, 기록이
global 인 자산이 `-g` 없이 `npx skills add … --agent … --copy` 로 프로젝트의 CLI 자리마다(`.claude/skills/<skill>` · `.agents/skills/<skill>`)
기록 밖 사본을 만들었다. 기록은 그 사본을 모르므로 uninstall 은 홈 사본의 제거 명령(`npx skills remove -g`)만 안내하고 프로젝트 사본을
거두지도 말하지도 못했다. 같은 브랜치의 06fb16b 가 새 사본 생성을 막았고(자산별 scope 로 묶어 부른다), 남은 것은 이미 생긴 사본이다.

기록 밖 파일은 설치자 것으로 다루는 것이 원칙이다(디스크 존재는 소유 근거가 아니다 — ADR-096 · CLAUDE.md §설치자 디스크). 그래서
이 사본을 지울지는 사람이 정했다. 사용자 확정(2026-10-19) 원문:

> 업데이트하면서 프로젝트에 설치된 것이고 프로젝트에 설치된 것이면 지워

소스 전체를 까는 자산(`detail.skill` 없음)은 어떤 스킬 폴더 이름으로 깔렸는지 기록에 없어 처음엔 회수에서 뺐다. 사용자 확정(2026-10-19) 원문:

> 소스 전체를 까는 자산(예: jakubkrehel/skills) 기록해줘

## Decision

1. **기록 scope 가 global 인 외부 스킬 자산의 프로젝트 자리 `<root>/<skill>` 은 하네스 refresh 가 만든 자리다**
   — 기록이 "이 자산은 홈에 있다" 고 말하므로 같은 이름의 프로젝트 자리는 옛 update 결함의 산물이고, 하네스 몫으로 회수한다. 판정
   근거는 디스크가 아니라 기록(scope = global)이다. 자리는 그 refresh 가 쓴 곳 그대로다 — 깔린 CLI 집합(`installedClis`)의
   스킬 루트(claude → `.claude/skills` · 그 밖 → `.agents/skills`, 집합이 비면 둘 다). `<skill>` 은 `detail.skill` 이고, 소스 전체를
   까는 자산은 기록의 `skills`(아래 5) 이름마다다.
2. **설치자 손이 닿았을 수 있는 파일만 그 파일 하나를 백업한다.** 파일마다 홈의 global 사본(같은 상대 경로)과 바이트로 댄다 — 같으면
   지우고, 다르거나 global 사본에 없으면 `<file>.backup-<시각>` 을 남기고 지운다. global 사본 자리가 아예 없으면 댈 수 없어 파일마다
   백업하고 지운다. global 자리는 `skills@1.5.11` 실측(`getAgentBaseDir`): claude-code = `$CLAUDE_CONFIG_DIR/skills`(없으면
   `~/.claude/skills`), `.agents/skills` 를 쓰는 에이전트 = 공용 `~/.agents/skills`. 홈 사본과 기록은 건드리지 않는다.
3. **따라가지 않는 자리** — 자리가 실제 폴더가 아니면(링크 — 그 refresh 의 `--copy` 는 폴더를 만든다) · 실체가 프로젝트 밖이면 ·
   홈의 그 자리와 같은 폴더면(프로젝트가 홈) 건드리지 않는다. 폴더 안의 링크 · 다른 자산이나 하네스 기록이 말하는 경로 · 앞선 백업은
   지우지 않는다(링크는 남긴 줄로 말한다).
4. **같은 함수 하나**(`reclaimGlobalSkillCopies`)를 update(외부 스킬 갱신 직전) · uninstall(전량 · `--only` 의 해당 자산) · uninstall
   `--dry-run` 이 쓴다. 확인 규약은 각 경로의 기존 것 그대로다(update 는 다른 회수 경로처럼 묻지 않고 백업으로 지킨다 · uninstall 은
   `--yes` / 확인 화면). 화면은 자리마다 한 줄 · 백업마다 판정 줄 하나(update 는 `judged` · 백업 목록에도 든다) · 남긴 파일마다 한 줄.
   `--only <global 자산>` 이 사본을 회수했으면 "아무것도 자동 제거되지 않았다" 로 끝내지 않는다 — 기록의 그 자산은 남고 홈 제거 안내는
   그대로 나온다.
5. **소스 전체를 까는 global 자산은 깐 스킬 이름을 기록에 남긴다**(자산 엔트리의 선택 필드 `skills`). 카탈로그에 이름을 적지 않는다 —
   상류가 스킬을 더하거나 바꾸면 썩고, 하네스 몫의 SSOT 는 기록 하나다(ADR-096). install · update 가 도구 호출 전후로 홈 스킬 자리를
   잰다 — 스킬 폴더마다 정체(`ino:ctime`)를 대어 바뀐(새로 생긴) 폴더의 이름이다. 내용 비교가 아니라 정체인 이유: `skills@1.5.11` 은
   `--copy` 로 까는 폴더를 지우고 새로 만들어(`installSkillForAgent` → `cleanAndCreateDirectory`) 이미 깔려 있던 같은 바이트의 폴더도
   정체가 바뀌고, 도구가 안 건드린 설치자 스킬은 그대로다. 다시 깔면 합집합이다. project 로 깐 자산은 이름을 두지 않는다(그 자리는
   `files` 가 말한다). 루트 밖을 겨냥하는 이름(`/` · `..`)은 회수가 쓰지 않는다.
   이름이 없는 옛 기록은 다음 update 의 갱신이 이름을 재 남기고, **같은 실행**에서 갱신 뒤에 그 이름 자리만 회수한다. 그때 홈 사본은
   이미 새 판이라 상류가 바꾼 파일은 "다르다" 로 백업하고 지운다(무손실 — 받아들인다).

## Alternatives

- **남기고 안내만 한다** — 원칙(기록 밖 = 설치자 것)에 가장 가깝지만, 설치자가 고르지 않은 자리(프로젝트)에 매 세션 사본이 상주하고
  같은 스킬이 두 벌 보인다. 사용자가 "지워" 로 기각.
- **프로젝트 사본을 project 자산으로 승격해 기록한다** — 사용자가 고른 자리(global)와 반대 자리의 본문을 사후 인정하는 꼴이라 이슈
  본문에서 이미 기각.
- **사본을 통째로 백업 폴더로 옮긴다** — 폴더 단위 백업·이동은 하지 않는다(CLAUDE.md §설치자 디스크 — 파일 하나만 백업).
- **소스 전체를 까는 자산은 회수하지 않는다**(초판) — 이름을 몰라 루트 전체를 겨냥하게 되므로 뺐지만, 그런 자산의 사본이 영구히 남는다.
  사용자가 "기록해줘" 로 기각 — 결정 5.
- **이름을 카탈로그에 적는다** — 상류가 바뀌면 썩는다. 기각.
- **이름을 도구의 잠금 파일(`~/.agents/.skill-lock.json`)에서 읽는다** — 키가 폴더 이름이 아니라 정규화 전 스킬 이름이고, 자리가
  `XDG_STATE_HOME` 에 따라 바뀌며, 도구가 쓰기 실패를 삼킨다. 기각.
- **홈 스킬 자리의 내용(sha)을 전후로 비교한다** — 이미 같은 판이 깔려 있던 스킬을 놓친다. 기각.

## Consequences

- ADR-096 Consequences 의 "디스크 존재는 이 안내를 낼지 말지에만 쓰인다" 와 같은 선 위다 — 여기서도 디스크는 회수할 것이 있는지만
  말하고, 하네스 몫이라는 판정은 기록(scope = global)이 한다. ADR-096 의 예외가 아니다.
- 사본 폴더 안에 백업이 남으면 그 폴더(`<root>/<skill>/`)도 남는다 — 스킬 본문(`SKILL.md`)이 없어 CLI 가 스킬로 읽지 않고, 다음 update ·
  uninstall 은 앞선 백업을 다시 백업하지 않는다.
- 홈 사본이 상류에서 바뀐 뒤에는 안 고친 파일도 "다르다" 로 백업될 수 있다(보수적인 쪽 — 지우는 쪽으로 넘어가지 않는다). update 는
  도구가 홈 사본을 갱신하기 **전에** 대어 이 폭을 줄인다.
- `uninstall --cli` · `--track` 은 자산을 건드리지 않는 경로라 이 회수도 하지 않는다.
- 소스 전체를 까는 자산의 이름은 도구가 폴더를 새로 만든다는 동작에 기댄다 — `skills` 버전을 올릴 때 이 동작을 다시 잰다(`SKILLS_CLI_VERSION`
  bump 시 재검증과 같은 자리). 이름이 없는 옛 기록에서 uninstall 을 먼저 돌리면 이름을 잴 기회가 없어 사본은 회수되지 않는다(update 를
  한 번 거치면 잡힌다).
