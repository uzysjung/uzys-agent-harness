# ADR-078: update 는 외부 스킬도 상류 최신판으로 갱신한다

- Status: Accepted
- Date: 2026-08-27
- PR: #375
- Context:
  `update` 는 우리가 놓아둔 정책 파일과 우리가 렌더한 CLI 산출물만 새로 썼다(ADR-049).
  `npx skills add` 로 깐 **외부 스킬**은 그 경로에 없어서 `update` 를 몇 번 돌려도 첫 설치
  판본이 그대로 남았다 — 실측(2026-08-27, npx 호출 추적)으로 `install` 2회 · `update` **0회**.
  그런데 화면에는 `✓ external CLI artifacts` 가 떠서 다 갱신된 것처럼 보였다. 상류가 스킬을
  고쳐도 설치받은 사람은 받지 못하고, **못 받는다는 사실조차 알 수 없었다.** 영향은
  `method.kind:"skill"` 자산 18종.

- Decision:
  `update` 가 프로젝트 루트에 `skills-lock.json` 이 있을 때 **`npx skills@<고정> update -p -y`**
  를 프로젝트 디렉터리에서 한 번 부른다. 성공·실패 모두 화면에 자기 행을 갖는다.
  잠금 파일이 없으면 부르지 않는다(없는 대상에 네트워크 왕복을 태우지 않는다).
  **실패해도 `update` 는 정책 파일 갱신을 끝낸다** — 네트워크 하나 때문에 나머지를 잃는 것이
  사용자에게 더 나쁘다.

  착수 전 컨테이너 실측(`skills@1.5.11`, 2026-08-27):

  | 확인 | 결과 |
  |---|---|
  | 우리 `--copy` 사본을 인식하나 | 인식한다 — `add` 가 남긴 `skills-lock.json` 을 읽는다 |
  | 두 사본(`.claude/`·`.agents/`)을 다 갱신하나 | 둘 다. 양쪽 변이가 update 후 0으로 돌아왔다 |
  | 버전 고정과의 관계 | 고정 유지 — `skills@1.5.23` 은 node 20 에서 `EBADENGINE` |
  | 실패가 update 를 죽이나 | 빈 디렉터리는 CLI 가 exit 0. 오프라인은 npx 가 멈춘다(60초 대조군 124) |

- Alternatives:
  - **우리가 깐 스킬만 이름으로 지정** (`skills update <이름…>`): skill 자산 18종 중 `--skill`
    로 이름을 특정하는 것은 15종뿐이고 나머지는 저장소 통째 설치라 깔린 이름을 우리가 모른다.
    이름을 아는 것만 부르면 **3종이 조용히 낡는다** — #372 가 정확히 그 "일부만 조용히 빠지는"
    결함이었으므로 기각.
  - **`skills add` 재실행**: 이미 받은 것을 다시 받는다. `update` 가 그 일을 위해 있고 더 싸다.
  - **못 한다고 화면에만 적기**: 정직하지만 상류 개선이 영영 도달하지 않는다는 사실은 그대로다.
  - **여기에만 짧은 타임아웃**: 오프라인 정지 시간을 줄이지만 `install` 의 `skills add` 는 같은
    노출을 그대로 둔 채 여기만 다르게 만든다. 새 상수 없이 공유 상한(120초)을 쓴다.

- Consequences:
  - **상류 스킬 개선이 `update` 로 도달한다.** 그전에는 재설치가 유일한 경로였다.
  - **제3자 코드가 들어오는 시점이 `install` 하나에서 `update` 로도 늘었다.** 자산 선정·vetting
    계약은 그대로지만(카탈로그가 SSOT), *언제* 새 본문이 디스크에 앉는지는 달라진다.
  - `skills-lock.json` 에 적힌 스킬 **전부**가 대상이다 — 사용자가 직접 `npx skills add` 로 깐
    것도 포함된다. 그 자리는 같은 CLI 의 잠금 파일이고 갱신은 그 CLI 의 정의된 동작이라
    받아들인다. 화면 행이 그 사실을 말한다.
  - 오프라인이면 공유 상한(120초)까지 화면이 조용하다. `install` 의 `skills add` 와 같은 노출이다.
  - 글로벌 스코프 설치는 대상이 아니다 — 하네스 `update` 자체가 `--project-dir` 전용이다.
