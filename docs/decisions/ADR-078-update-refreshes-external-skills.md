# ADR-078: update 는 외부 스킬을 install 과 같은 호출로 다시 받는다

- Status: Accepted
- Date: 2026-08-27
- PR: #375
- Context:
  `update` 는 우리가 놓아둔 정책 파일과 우리가 렌더한 CLI 산출물만 새로 썼다(ADR-049).
  `npx skills add` 로 깐 **외부 스킬**은 그 경로에 없어서 `update` 를 몇 번 돌려도 첫 설치
  판본이 그대로 남았다 — 실측(2026-08-27, npx 호출 추적) `install` 2회 · `update` **0회**.
  그런데 화면에는 `✓ external CLI artifacts` 가 떠서 다 갱신된 것처럼 보였다. 상류가 스킬을
  고쳐도 설치받은 사람은 받지 못하고, **못 받는다는 사실조차 알 수 없었다.**

- Decision:
  `update` 가 **설치 기록(`.harness-install.json`)에 적힌 skill 자산**에 대해
  **install 과 같은 호출**(`npx skills@<고정> add <source> --agent … --copy --yes`)을 다시
  돌린다. 같은 함수(`runExternalInstall`)를 쓴다 — 인자 조립을 두 벌 두면 한쪽만 고쳐지는
  순간 조용히 갈린다(ADR-049 와 같은 이유).

  대상 선정은 **기록에서만** 한다. 트랙·옵션에서 다시 유도하면 ⓐ 고른 적 없는 자산이 update
  로 새로 깔리고 ⓑ opt-in 으로 깐 자산이 조건 불일치로 조용히 빠진다. `forceInclude` 로
  조건·tier 판정을 우회해 **깐 것을 깐 그대로** 다시 받는다.

  화면은 **성공 · 실패 · 판정 불가**가 각자 한 줄을 갖는다. 셋을 같은 침묵으로 합치는 것이
  이 결함의 정체였다. 실패해도 `update` 는 정책 파일 갱신을 끝낸다 — 네트워크 하나 때문에
  나머지를 잃는 것이 사용자에게 더 나쁘다.

- Alternatives:
  - **`skills update -p -y`** (최초 구현안, **독립 리뷰가 CRITICAL 로 기각**): 그 서브명령은
    **`--copy` 도 `--agent` 도 받지 않는다**(도움말의 *Update Options* = `-g`·`-p`·`-y` 뿐).
    그래서 자기 기본 배치로 스킬 자리를 다시 만든다. 실측(2026-08-27, 컨테이너):

    | claude 단독 설치 | `.claude/skills/<id>` | `.agents/` |
    |---|---|---|
    | install 직후 | 실제 디렉터리 | 없음 |
    | `skills update` 후 | **`.agents/` 로의 심링크** | **생성됨** |

    이건 #372 가 세운 "두 자리에 각각 실제 사본" 계약을 되돌린다. **측정된 해악은 셋이다**:
    ⓐ 고른 적 없는 CLI 의 자산 트리가 생긴다(ADR-031 이 P0 로 닫은 형태) ⓑ 사용자가 정체 모를
    `.agents/` 를 지우면 `.claude/skills/*` 는 **끊긴 링크**가 되어 본문이 사라진다 ⓒ 슬롯
    이름이 번들 스킬과 겹치면 `foreign-slot.ts` 가 디렉터리 아닌 자리를 "남의 것"으로
    판정해(#343) 하네스 writer 가 건너뛴다.

    **정정**: 이 문단의 초판은 "그 뒤로 우리 최신본이 영영 그 자리에 안 들어간다"고 적었는데
    **틀렸다**. 외부 스킬 id 는 `templates/skills/` 에 없어 우리 writer 가 그 자리를 겨냥하지
    않고, 실측에서 이 구현은 이미 심링크가 된 슬롯을 오히려 **디렉터리로 복구한다**. 독립
    리뷰 2라운드가 반증했다 — 기각 결론은 위 세 해악만으로 선다.
  - **잠금 파일(`skills-lock.json`) 존재로 발화 판정**: 잠금 파일이 없는 설치본(잠금 파일을
    커밋하지 않은 저장소를 clone 한 팀원 등)이 **침묵 무동작**이 된다. 설치 기록으로 가르면
    "갱신할 게 없다"와 "무엇을 갱신할지 모른다"를 구분해 말할 수 있다.
  - **못 한다고 화면에만 적기**: 정직하지만 상류 개선이 영영 도달하지 않는다는 사실은 그대로다.
  - **여기에만 짧은 타임아웃**: 오프라인 정지 시간을 줄이지만 `install` 의 같은 호출은 같은
    노출을 그대로 둔 채 여기만 다르게 만든다. 새 상수 없이 공유 상한(120초)을 쓴다.

- Consequences:
  - **상류 스킬 개선이 `update` 로 도달한다.** 그전에는 재설치가 유일한 경로였다.
  - **제3자 코드가 들어오는 시점이 `install` 하나에서 `update` 로도 늘었다.** 자산 선정·vetting
    계약은 그대로지만(카탈로그가 SSOT), *언제* 새 본문이 디스크에 앉는지는 달라진다.
  - **사용자가 직접 `npx skills add` 로 깐 스킬은 대상이 아니다.** 설치 기록에 없기 때문이다.
    (최초 구현안이던 `skills update` 는 그것까지 건드렸고, 그것도 기각 사유의 하나였다.)
  - **`update` 가 자산 수 × 수 초 만큼 느려진다.** 대신 자산마다 진행 줄(`→ <자산>`)이 뜬다 —
    `install` 과 같은 표시다. 오프라인이면 공유 상한(120초)까지 기다린 뒤 실패 행을 낸다.
  - **스코프는 설치 기록의 것을 그대로 쓴다**(`-g` 포함) — install 이 한 것과 같은 자리를
    갱신한다. 그래서 글로벌 설치본의 `update` 는 `~/.claude/` 에 쓴다. **그 사실이 화면
    헤더의 `SCOPE` 행에 나와야 한다** — `buildUpdateSpec` 이 기록의 스코프를 싣지 않으면
    렌더러 기본값이 *"no global write"* 를 찍고, 홈에 쓰면서 안 쓴다고 적게 된다(독립 리뷰
    HIGH-1 이 실측으로 잡았다).
  - **`forceInclude` 는 신뢰 티어(T3) 게이트도 지난다 — 이건 결정이다.** install 은 experimental
    자산을 명시 opt-in 없이 안 깔지만, update 는 **이미 깐 것**을 티어와 무관하게 계속 갱신한다.
    update 는 무엇을 깔지 다시 묻는 자리가 아니고, 강등을 이유로 조용히 갱신을 끊으면 사용자는
    낡은 본문을 쥔 채 그 사실을 모른다. 강등 자체는 `trust-tier-drift` 가 따로 감시한다.
  - **설치 기록에는 있는데 카탈로그에서 사라진 자산**은 갱신할 방법이 없다. 조용히 빼지 않고
    화면에 이름을 낸다 — 이 저장소는 실제로 자산을 지운 적이 있고(`north-star-skill`), 그
    릴리즈 뒤 옛 설치본이 도는 자리다.

- 검증 (전부 재현 가능한 실행):
  - 컨테이너 시나리오 `scenario-update-external-skills.sh` — 변이 후 갱신 · **update 후에도
    슬롯이 디렉터리** · claude 단독에 `.agents/` 미생성 · 설치 기록 부재 시 판정 불가 고지.
  - **음성 대조 ①**: 수정 없는 `main`(1d6786d)을 별도 워크트리·이미지로 세워 같은 시나리오 →
    **exit 1**(두 사본 다 변이 잔존). 수정본 **exit 0**.
  - **음성 대조 ②**: 기각안(`skills update`)을 같은 프로젝트에 적용 → 시나리오의 심링크·
    `.agents/` 단언이 **둘 다 문다**. 게이트가 기각안을 실제로 잡는다.
  - 시나리오의 대상 슬롯은 **설치 기록의 skill 자산에서만** 고른다. 디스크를 훑어 고르던
    초판은 내부 번들 스킬(`audit-harness-fit`)을 뽑아 **자기 대상이 아닌 것을 재고 초록**을
    냈다 — 그 상태로는 수정 없이도 통과했다.
  - **독립 리뷰 2라운드**가 CRITICAL 해소를 직접 재확인했고(claude 단독·claude+codex 모두
    update 후 슬롯 DIR·`.agents/` 미생성), HIGH 1건(스코프 표기)과 MEDIUM 3건을 새로 냈다 —
    전부 이 ADR 과 코드에 반영됐다.
