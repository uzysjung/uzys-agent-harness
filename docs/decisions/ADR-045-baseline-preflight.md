# ADR-045: 착수 전 baseline 대조를 doc-governance 의 Pre-flight 절로 신설

- Status: Accepted
- Date: 2026-07-19
- PR: #233 (v26.119.0)
- Context:

  `doc-governance` 는 **출구**만 규정하고 있었다 — "## 작업 완료 처리(merge = 코드 + 추적 동기화)"
  는 머지 직후 TODO/SPEC/README 를 코드에 맞춘다. 이 규약은 **"관련된 모두가 매번 지켰다"를
  전제**하는데, 그 전제가 깨진 사례가 관측된다:

  - **이 저장소**: 로드맵이 8 PR 동안 미갱신되어 자산 수치가 어긋나고 완료분이 미완으로 박제됨
    (CHANGELOG v26.88.0). 그때 추가한 대책은 `ship-checklist` 의 "로드맵 SSOT 동기화" —
    **출구 쪽 프로즈 강화**였고 입구 대책은 없었다.
  - **사용자 개인 프로젝트 2건**(DYLD-GoalTrack · dyld_vantage): 문서와 구현 불일치 + TODO/로드맵
    미정리로 사고 및 불필요 작업이 반복 발생했다는 사용자 보고 (2026-07-19).
  - **외부 1건**: 한 sprint 에서 미완 표기 5건이 이미 구현돼 있어 4~6일 추정이 0일로 정정된 기록
    (사용자 개인 프로젝트 · 이 저장소에서 **재현 불가** · 표본 1).

  전제가 깨진 순간 `[ ]` 는 "안 된 것"이 아니라 "모르는 것"이다. 그 상태를 다루는 규약이 없었다.

  판정 근거로 eval(with/without 행동 비교)을 돌리는 안을 검토했으나 채택하지 않았다 — eval 은
  근거가 없을 때 쓰는 **대리 지표**인데, 3개 프로젝트의 실제 사고 기록이 그보다 강한 직접 증거다.

- Decision:

  `templates/rules/doc-governance.md` 에 **"## 착수 전 baseline 대조 (Pre-flight)"** 절을 신설한다
  (실측 **242 토큰**, 계약 테스트 상한 246). 설계 원칙은 **MECE — 이미 다른 자산이 소유한 것은
  재서술하지 않고 참조한다**:

  | 신규 절이 소유 | 참조로 위임 |
  |---|---|
  | 발동 조건(git 기반) · 3분류 처리 · 착수 단위 · 기록 위치 | "완전 구현" 엄격도 → `benchmark-parity.md` "단순 존재 ≠ 완결" |
  | Rule 8 과의 경계 선언 | 문서 정정 승인 범위 → `change-management.md` CR 분류 |
  | | 사고 서사·수치 → 본 ADR (`git-policy.md` "Drift Period" 관용구) |

  본 절은 **프로즈로만 작동하며 미준수를 잡는 게이트가 없다**. `recurrence-prevention` 의 사다리상
  첫 도입이므로 프로즈에서 시작하고, 스킵이 반복되면 게이트로 승격한다 — 그 한계를 절 본문에
  명시해 독자가 신뢰 수준을 알게 한다(`doc-governance` "검증 게이트" 절의 기존 관용구).

- Alternatives:

  1. **`CLAUDE.md` Rule 8 확장** — Rule 8("Read before you write")이 이미 상주하고, 본 절은 그
     특수화다. 기각 사유: Rule 8 은 전부 2~4줄짜리 원칙 목록이고 절차·분기표를 넣으면 그 형식이
     깨진다. 대신 **경계를 절 서두에 한 줄로 선언**해 중복 고지 문제만 해소했다.
  2. **`gates-taxonomy.md` 로 이관** — Pre-flight 유형의 구체 사례가 0건이라는 결손을 같이 메울 수
     있다. 기각 사유: 그 파일은 게이트 **유형의 분류표**(173 토큰)다. 246 토큰짜리 인스턴스를
     넣으면 인스턴스가 분류표보다 커져 파일 정체성이 뒤집힌다. 문제 영역("문서가 거짓 상태")의
     소유자는 `doc-governance` 다.
  3. **스킬화(발화형)** — 발동이 "계획 착수" 국면 한정이라 상주보다 발화 프로필에 맞는다는 지적이
     있었다. 기각 사유: 발화는 **트리거가 걸려야** 로드되는데, 이 규약의 실패 모드는 정확히
     "확인해야 한다는 걸 떠올리지 못하는 것"이다. 떠올려야 로드되는 자산은 이 실패를 못 막는다.
  4. **신설하지 않음** — 3개 프로젝트 실측 사고 기록이 있어 기각.
  5. **최소판(~84 토큰)** — 서사를 걷어낸 압축안. 부분 채택: 서사 삭감은 전량 수용했으나, 그
     압축안이 함께 덜어낸 항목들("완전 구현" 판정 기준 · 판정 실패 시 기본값 · CR 분류)은
     **오작동을 낳는 결손**이라 복원했다. 아래 Consequences 참조.

- Consequences:

  - `doc-governance` 601 → **847 토큰**으로 룰 중 1위가 된다(기존 1위 git-policy 720). 상주 총합은
    5,194 → 5,440 (**+4.7%**). ADR-043 의 축은 "더 작게"가 아니라 "전부 근거 있게"이므로 크기
    자체는 부결 사유가 아니지만, ADR-043 2단계 eval 대상 1순위가 이 파일이 된다.
  - **행동을 바꾸지 않는 문장을 상주시키지 않는다**는 선례를 세운다. 1차 초안(234 토큰) 대비
    2차(242)는 값이 사실상 같지만 내용이 전부 바뀌었다 — 서사·수사 전량 삭제, 그 자리에 실행
    가능한 조건·기준·참조. 이후 룰 증분은 이 기준으로 심사한다.
  - **새로 연 위험**: "완전 구현" 오판정. 심볼 존재만으로 완료 처리하면 재구현을 막으려다 안 되는
    기능을 완료로 박제한다 — `no-false-ship` 사례표의 v26.82.0 과 같은 실패군이다. `benchmark-parity`
    기준 참조 + "애매하면 부분 구현" 기본값으로 봉했으나, 참조가 끊기면 다시 열린다(계약 테스트로 가드).
  - 미준수는 관측되지 않는다(게이트 없음). 후속 후보: `spec-drift-check.sh` 를 확장해 TODO 항목의
    키워드를 코드에 정적 대조하는 pre-flight 경고 추가 — 탐색은 결정론, 판정(완전/부분/미구현)은
    모델 몫으로 분리(Rule 5).

- 검토 경과:

  5인 페르소나 패널(회의적 신규 설치자 · 룰 실행 에이전트 · SSOT 감사자 · 적대적 독자 · 비용 심판)
  을 독립·병렬로 실행. **4인 회수**(SSOT 감사자는 4회 요청에도 미전달 — MECE 매핑은 오케스트레이터가
  직접 작성했으므로 독립 검증분이 아니다). 판정은 3 반대 / 1 조건부 통과였고, 1차 초안은 다음
  결함으로 폐기됐다 — 모두 저장소 파일 대조로 확인:

  | 결함 | 위반한 자기 규약 |
  |---|---|
  | 발동 조건 "며칠 이상" | `benchmark-parity.md` "heuristic threshold 를 근거 없이 단정" 금지 |
  | "4~6일→0일" 인용 (저장소 내 grep 0건) | `doc-governance` "추정/임의 단정 금지" |
  | Rule 8 중복 미고지 | `doc-governance` "같은 사실을 두 곳에 쓰지 않는다" |
  | "완전 구현" 실행 검증 부재 | `benchmark-parity` "단순 존재 ≠ 완결" |
  | 서사 인라인 서술 | `git-policy` "Drift Period" 관용구(2줄 + ADR 참조) |
