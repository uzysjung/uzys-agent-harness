# ADR-111: 옛 판의 하네스 바이트는 닫힌 지문으로 알아본다 — 소유 근거가 아니라 "백업 생략" 과 "백업 뒤 치우기" 의 근거

- Status: Accepted
- Date: 2026-10-12
- PR: #789 (PR-C · #774) · PR-D(#781)
- Amends: ADR-097(결정 1 "소유 근거 = 기록" 은 그대로 · 결정 4 `RETIRED_PATHS` backup+remove 그대로 — 문구만 지문이 보강) · ADR-089 · ADR-090(은퇴 자산 — update 는 여전히 안내만, uninstall 은 지문 일치면 백업 뒤 회수)
- 설계: `docs/plans/v26.170.0-legacy-displaced-design.md` §3 · §4.3 · §4.4 · §8.1 · §13

## Context

v26.83~v26.161 설치본은 기록이 하네스 파일을 다 열거하지 못한다(설계 §1.1 표 — v26.125 이하는 파일 필드가 아예 없고, v26.126~v26.161 은 스캔 필드가 커맨드 · 옛 앵커 · `.agents/skills` 사본 · `AGENTS.md` 를 모른다). 그 판의 바이트는 git 태그에 고정돼 있고 npm 게시판과 같다(설계 §1.1 실측). 그래서 기록 모양에 따라 결과가 갈렸다 — 블록 모델로 읽힌 옛 `AGENTS.md` 는 update 뒤 옛 파일 전체 + 새 블록(51절)이 매 세션 상주했고, 옛 템플릿의 꼬리 절은 설치자 절로 되살아나 uninstall 뒤에도 남았다(설계 §1.3 · #774). 같은 이유로 은퇴 스킬 · 옛 커맨드 · 옛 앵커가 uninstall 뒤 남는다(설계 §1.2 · #781).

설계 1차안은 지문 일치를 하네스 것으로 삼아 백업 없이 지웠다. 1차 검증(2026-10-12 B1)이 ① 그것이 사용자 확정 문장 "하네스 몫은 설치 기록 하나가 정한다" 를 바꾸는 결정이고 ② update 가 "yours / 지워도 된다" 라 부른 파일을 uninstall 이 묻지 않고 지우며 ③ 은퇴 자산은 다시 깔아도 돌아오지 않음을 지적했다. 사용자가 네 선택지(ⓐ 설계대로 · ⓑ 전부 backup+remove · ⓒ leave+안내 · ⓓ 절충) 중 **ⓓ 를 확정했다(2026-10-12)**.

## Decision

1. **소유 근거는 여전히 기록 하나다**(ADR-097 결정 1 불변). 지문은 소유를 주장하지 않고 두 가지 일만 한다 — ⓐ 기록이 하네스 자리라 말하는 `no-sha` 자리에서 **현행 번들에 있는 경로**(`isRecordedTrackTarget` — 그 자리가 현행 판으로 다시 채워진다)이고 바이트가 지문과 같으면 백업을 생략한다 ⓑ 기록이 없는 옛 판 바이트 그대로의 파일 · `AGENTS.md` 절, 그리고 기록 자리이되 현행 번들에 없는 것(은퇴 자리)은 **백업하고** 치운다(파일은 `<file>.backup-<시각>` · 절은 파일 1회). 지문 불일치 = 설치자 것 — 기록 밖이면 남긴다.
2. 지문 회수의 범위 = 기록의 CLI 집합이 그 자리를 쓸 때만(`ownersOf ∩ installedClis ≠ ∅`) — 하네스가 쓴 적 없는 자리는 읽지 않는다(`AGENTS.md` 는 uninstall 의 `relevant()` 안에서만).
3. 지문은 생성기 하나(`scripts/gen-legacy-fingerprints.mjs`)가 git 태그 v26.70.0~v26.169.0(**양끝 고정**)에서 만든 모듈 하나(`src/legacy-fingerprints.ts`)이고 손으로 고치지 않는다. #739 의 앵커 절 지문 53 도 같은 생성물이 낸다(손목록과 0 차이). 새 판은 쓰는 순간 기록하므로 목록은 늘지 않는다.
4. `AGENTS.md`: 옛 하네스 파일 술어는 **머리 지문 하나**(제목 다음 블록인용이 옛 템플릿 그대로)다 — 첫 접촉 블록이 붙어 있으면 떼고 본다. 참이면 update 는 절 모델로 갈아탄다(첫 접촉이 아니라 체크섬 없는 하네스 파일로 — 1회 백업). 옛 판이 바이트 그대로 쓴 절(앵커 절 ∪ 옛 템플릿 절)은 어느 자리에 있든 되살리지 않고, 떨어뜨린 쓰기는 파일 1회 백업 + update 화면 한 줄을 남긴다. uninstall 은 같은 지문으로 걷고 설치자 절만 남기거나 파일을 지운다(쓰기 · 삭제 전 백업 1회). **하네스 이름 절**(`## Project Rules` 머리말 · `## Harness Rules` 안내 · `## Session Start` · 인라인 룰 절)도 이름이 아니라 옛 렌더 바이트(`LEGACY_AGENTS_MD_NAMED_KEYS`)로 가른다 — 일치하면 걷고, 다르면 설치자가 고친 절이다: uninstall 은 그 절을 남기고 화면이 `kept N section(s) you edited` 로 말한다(사용자 결정 ⓓ "설치자가 고친 절은 남는다"). update 는 그 절을 현행 판으로 바꾼다 — 절 모델에서 이름 절은 하네스 몫이라 매 update 가 다시 쓰고, 남겨 두면 같은 이름의 절이 두 벌 생겨 다음 update · uninstall 이 이름으로 다시 판정한다. 대신 쓰기 전 1회 백업과 화면 한 줄(`harness section(s) you had edited … your edit is in the copy`)로 고친 글의 자리를 말한다. uninstall 화면은 파일째 지울 때도 "설치자 몫이 없었다" 고 단언하지 않고 백업 위치만 말한다 — 제목 한 줄 편집 · 첫 접촉 블록 안 줄처럼 지문이 가르지 못하는 몫이 있어, 단언을 경우별로 가르는 것보다 단언을 없애는 쪽이 단순하고 늘 참이다(PR #789 리뷰 r2).
5. update 는 옛 은퇴 스킬 · 커맨드 · 옛 앵커 파일을 지우지 않고 안내한다(ADR-089 · ADR-090 유지) — "갱신" 이 설치자 디렉터리를 비우는 동작이 되는 것은 별도 결정이다.

## Alternatives

- ⓐ 지문 일치 전부 백업 없이(설계 1차안) — 사용자 확정 문장 변경 · update 화면("yours" · "지워도 된다")과 uninstall 이 서로 반대 말 · 은퇴 바이트는 번들에 복구 경로 없음 → 사용자 기각.
- ⓑ 지문 일치 전부 backup+remove — 손실 0 은 같으나 현행 자리의 "no checksum — saved a copy" 노이즈가 그대로 → 차선.
- ⓒ leave + "safe to delete" 안내 — 원칙 불변이지만 "깨끗이 빠진다" 미달 → 기각.
- 경로 목록만(sha 없음) — 설치자가 같은 이름으로 쓴 파일을 지운다 → 기각.
- 내용 유사도 · 정규화 비교 — "설치자가 고쳤다" 와 못 가른다 → 기각(PR-A NOTE-C).
- 지문을 update 의 파일 회수에도 적용 — 결정 5 로 보류.
- 기록 이관 명령 — ADR-096 D3 과 같은 사유로 기각.

## Consequences

- 지문 모듈(`src/legacy-fingerprints.ts`, 생성물 약 60 KB — 앵커 절 53 · 이름 절 50 · 주석 포함)이 번들에 상주한다. `recorded()` · `RETIRED_PATHS` 는 바뀌지 않는다.
- 백업이 는다 — 옛 `AGENTS.md` 를 걷거나 절 모델로 바꾸는 쓰기마다 `AGENTS.md.backup-<시각>` 1회. #739 의 앵커 절 걷기도 이제 백업을 남긴다(전에는 기록 sha 그대로라 조용한 덮어쓰기였다). 2회차부터는 떨어뜨릴 절이 없어 백업도 없다.
- 설치자 파일이 우연히 옛 하네스 바이트와 같으면: 번들 자리에서는 백업 없이 치워진다(그 자리는 현행 판으로 다시 채워진다 · 옛 바이트는 옛 판 tarball 에 있다), 번들 밖에서는 백업 뒤 치워진다 — 번들 밖은 백업으로 디스크에 남고, 번들 자리의 옛 바이트는 옛 판 tarball 에만 있다. `displaced` · `excluded` 기록이 있으면 기록이 이기고, 그 자리를 쓰는 CLI 가 기록에 없으면 읽지도 않는다.
- 머리 블록인용이 없는 옛 판(v26.151~v26.159 — 실측 v26.153.0)의 `AGENTS.md` 는 이 술어에 걸리지 않는다. 그 판들은 `externalFiles` 에 sha 가 있어 이미 절 모델이고 꼬리 절도 없으므로 이번 변경의 영향이 없다. **비목표(PR #789 손실 탐색 MEDIUM)**: 그 판 설치본에 설치자가 절 하나라도 더한 채 **바로 uninstall** 하면 기록 sha 가 달라 #516 대로 파일이 통째 남고 하네스 절이 함께 남는다 — v26.169.0 과 같은 동작이고 손실은 없다. update 를 한 번 거치면 절 모델 병합이 정리한다.
- `.codex/hooks/*.sh` 렌더본은 식별 밖이다(템플릿과 바이트가 다르다).
- 루트 `CLAUDE.md` §설치자 디스크의 첫 불릿은 그대로이고 바로 아래 지문 보강 한 줄이 더해진다.
