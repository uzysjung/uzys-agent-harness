# ADR-072: `mcp-pre-exec` 훅과 `.mcp-allowlist` 를 뺀다

- Status: Accepted
- Date: 2026-08-16
- PR: #307

## Context

훅 4종을 판정하며 `mcp-pre-exec`(MCP allowlist 차단)을 *"결정론적이다 · 걸림돌은 allowlist 를
켠 경우만"* 을 근거로 **남긴다**고 판정했다. 사용자가 그 판정을 적발했다 — *"MCP 취약점 때문에
보안 지키겠다고 항상 실행하는 게 의미가 있나. 우리 제품 목적은 사용자가 AI 코딩 도구로 개발을
잘하게 만드는 건데."*

그 앞에서 이미 기준이 주어져 있었다: **"훅은 결정론적으로 정말 필요한 것만 — AI 가 일하는 데
걸림돌이 되어서는 안 된다."** 앞 절반만 체크리스트로 썼고 뒤 절반은 재지 않았다. 판정 기준 자체는
루트 `CLAUDE.md` §판정은 목적에서 시작한다 로 성문화됐다(#306) — 이 ADR 은 그 기준을 이 훅에
처음 적용한 결과다.

목적 기준으로 다시 재니 근거 셋이 전부 제거를 가리켰고, **셋 다 원래 판정 시점에 확인 가능한
사실이었다.** 자료가 없어서 틀린 게 아니라 질문을 안 던져서 틀렸다.

| # | 근거 | 확인 방법 |
|---|---|---|
| ⓐ | 우리 북극성이 *"기준선이 움직인다: MCP 추가를 기준에 반영한다"* 인데, 이 훅은 **MCP 를 추가하는 순간 차단한다** — 방향 문서와 정확히 반대로 작동한다 | `docs/NORTH_STAR.md` §1 |
| ⓑ | allowlist 가 `.mcp.json` 에서 **자동 생성**되므로, 사용자가 이미 한 동의를 두 번 묻는다 | 구 `writeMcpAllowlist` 는 `mcpServers` 키를 그대로 복사했다 |
| ⓒ | 훅 matcher 실측이 `Write\|Edit`·`mcp__.*` 둘뿐이라 **Bash 는 무방비**다. 문서 MCP 에 질의하는 것은 막히고 `rm -rf` 는 안 막힌다 — 보안 경계가 아니라 **오탐 생성기**다 | 구 `templates/settings.json` |

## Decision

**`mcp-pre-exec.sh` 훅과 `.mcp-allowlist` 를 통째로 뺀다.** 훅 파일 · `templates/settings.json`
배선 · 생성기(`writeMcpAllowlist`) · 설치 화면 행 · `templates/mcp-allowlist.example` · 사용자
도달 문서를 함께 제거한다. 반쪽 제거는 `tests/hook-wiring-parity.test.ts` 가 양방향으로 막는다.

**기존 설치본의 `.mcp-allowlist` 는 `update` 가 백업 후 회수하고 화면에 고지한다**
(`retireMcpAllowlist`). 훅 스크립트 쪽은 `hooks` 가 `POLICY_DIRS` 에 있어 `pruneOrphans` 가 이미
자동으로 물러낸다 — 새 코드가 필요한 것은 `.claude/` **밖**에 있는 allowlist 하나뿐이다.

백업은 조건 없이 남긴다. 자동 생성물이지만 사용자가 서버 줄을 주석 처리해 자기 정책을 적어 넣는
파일이었고, 그 편집 여부를 update 시점에 판정할 수단이 없다 — **판정할 수 없으면 지우기 전에
남긴다**(구 앵커를 안 지운 것과 같은 잣대, ADR-060).

## Alternatives

- **기본 비활성으로 강등** — 기각. 파일이 없으면 이미 통과하므로 현행과 같고, 아무도 안 켜는
  기능의 코드·문서·테스트만 남는다. ⓐ 를 해소하지도 못한다(켜는 순간 같은 문제).
- **matcher 를 Bash 까지 넓혀 ⓒ 를 고친다** — 기각. 오탐 범위를 넓히는 방향이고, 목적 부적합
  (ⓐ)은 그대로다. **첫 질문을 통과 못 한 자산은 나머지를 아무리 잘 만족해도 넣지 않는다.**
- **훅만 빼고 `.mcp-allowlist` 생성은 남긴다** — 기각. 읽는 쪽이 없는 파일을 남의 저장소에
  계속 만든다.
- **기존 파일을 그대로 둔다** — 기각. 아무도 안 읽는 파일이 사용자 저장소에 영구히 남고,
  다음 사람은 그게 무슨 게이트인 줄 안다.

## 적용 범위

배포판(`templates/`)과 이 리포의 개발 사본(`.claude/hooks/`) **양쪽**. 이 리포는 자기 배포물을
도그푸딩하므로 한쪽만 고치면 파는 것과 쓰는 것이 갈린다.

**범위 밖**: 이 리포의 `.claude/settings.json` 은 **사용자 소유 파일**이라 건드리지 않았다 —
그 파일에 남은 배선 한 줄은 사용자가 지운다(Consequences 참조). 과거 기록 문서(ADR-058/061 ·
`docs/research/*` · 완료된 Phase 기록)도 그대로 둔다 — 그때는 사실이었던 서술이다.

## Consequences

- **배포판에서 차단하는 훅은 `protect-files` 하나가 된다.** `hook-blocks.log` 계약은 유지되지만
  기록원이 하나로 줄어, "무엇이 실제로 막는가"의 표본이 그만큼 좁아진다.
- **MCP 호출은 하네스가 막지 않는다.** 승인은 각 CLI 자신의 권한 체계가 한다. 이것은 감수한
  결과이지 간과가 아니다 — ⓒ 때문에 기존 훅도 실제 보안 경계가 아니었다.
- **이 리포의 `.claude/settings.json` 에 죽은 참조 한 줄이 남는다.** 사용자 소유 파일이라
  하네스가 못 고친다. 설치본에서는 update 의 `cleanStaleHookRefs` 가 자동으로 정리한다.
- **미검증**: 이 훅이 실제로 몇 번이나 발화했는지는 끝내 모른다 — `hook-blocks.log` 가 이
  머신에 존재하지 않아 차단 이력이 0줄이다. 제거 판단은 **로그가 아니라 목적 적합성**에
  근거한다. 로그가 있었다면 근거가 하나 더 있었을 뿐, 판정은 같았다.
