# ADR-069: 외부 실행기 레인 — 저장소 코드가 제3자에 도달하는 경로를 연다

- Status: Accepted
- Date: 2026-08-10
- PR: #289
- 관련: ADR-068(배포 앵커 7원칙) · 이슈 #286

## Context

이슈 #286 은 세 스킬(`model-orchestration` · `multi-persona-review` · `external-model-consult`)에
OpenCode·agy·Codex 를 **보조 실행 수단**으로 편입해 달라고 요청한다. 그중
success_criteria 2 — *"단순 반복 구현과 가벼운 테스트는 OpenCode 의 사전 설정 모델을 활용할 수
있다"* — 가 지금까지 없던 경로를 요구한다.

**현재 외부 도구는 자문만 한다.** `external-model-consult` 는 중립 임시 디렉터리에서 외부 CLI 를
돌린다 — 저장소가 그 세션의 워크스페이스에 **아예 들어가지 않는다.** 그것이 그 스킬의 중심
약속이고, 래퍼가 환경변수까지 allowlist 로 좁히는 이유다.

실행기는 성질이 반대다. 코드를 고치려면 **저장소 안에서** 돌아야 하므로, 저장소 코드가 제3자
제공자의 세션 컨텍스트에 들어간다. 이것은 자문 경로의 확장이 아니라 **새 신뢰 경계**다.
`change-management` 기준으로 보안 정책 변경은 Major CR 이고, 그래서 인간 결정을 받았다.

되돌릴 수 없다는 점도 결정에 포함된다 — 한 번 나간 코드는 회수할 수 없다.

## Decision

**레인을 연다.** 사용자 결정(2026-08-10). 다음 가드레일과 함께 한다.

1. **최초 1회 사용자 확인.** 저장소 코드가 특정 제3자 제공자에 처음 도달하기 전에 확인을 받는다.
   확인 소유자는 `model-orchestration` 이다. 설정이 끝난 뒤의 일반 위임은 자율(이슈 `<autonomy>`).
2. **이 레인이 사는 것은 용량이지 품질이 아니다.** 새 판단이 남아 있지 않은 기계적 구현만 간다.
   기존 라우팅 질문(*"새 판단이 남아 있는가?"*)을 그대로 쓰고 새 판별자를 만들지 않는다.
3. **테스트·검증·핵심 구현은 이 레인에 가지 않는다.** 현행 정책(Opus 전속)이 그대로 유지된다 —
   이슈 Non-scope 가 기존 역할 정책의 대체·제거를 금지한다. 다만 **이미 형태가 고정된 표에
   케이스 한 줄을 복제하는 일**은 허용한다(사용자 결정: 무엇을 단언할지 정하는 일과 이미 쓰인
   기준을 복제하는 일은 다른 일이다). **기존 스위트 실행**은 애초에 모델 위임 대상이 아니다 —
   셸 명령이므로 라우팅 0단계에서 걸러진다.
4. **외부 산출물은 in-harness 교차검증 전까지 아무것도 게이트하지 않는다.** 외부 레인의 결과가
   머지·배포 판정에 직접 쓰이지 않는다.
5. **도구가 없거나 인증이 끊기면 레인을 내리고 보고한다.** 대신 설치하거나 인증하지 않는다.
6. **새 래퍼 스크립트·새 훅·새 룰을 만들지 않는다.** 자문 래퍼의 핵심 가드레일(중립 cwd)이
   실행기에서는 정반대라, 같은 스킬에 두 약속을 넣으면 배포 본문이 자기모순이 된다.
   확인은 프로즈 게이트 + 테스트로 한다(이 리포 원칙: 로컬 차단 훅을 더 얹지 않는다).

**호출 방법은 `external-model-consult` 가 계속 소유한다** — 실행 위임 쪽은 옮겨 적지 않고
가리킨다(`doc-governance` 의 "한 사실은 한 곳에"). 패널 구성과 독립성 판정은
`multi-persona-review` 가 소유한다.

## 적용 범위

- **대상**: 세 스킬의 본문(`templates/skills/` 및 개발 사본 `.claude/skills/`)과 그 계약을 무는
  테스트.
- **비대상**: description(frontmatter) — 셋 다 손대지 않는다. 2종이 이미 공식 상한을 넘고 있어
  트리밍은 트리거 동작 변경이라 별도 검증이 필요하다(별건으로 보고만 한다).
  `src/opencode/*`·`src/external-assets.ts`·`src/manifest.ts` 도 비대상이다 — 그 OpenCode 는
  **설치 대상 CLI** 이지 워커가 아니다.
- **미적용**: 외부 CLI 의 실동작·인증 확인. 이 사이클에서도 미검증으로 남는다.

## Alternatives

- **자문만 유지한다** — 기각. #286 success_criteria 2 를 만족시킬 수 없다. 다만 이 안이
  안전한 것은 맞아서, 위 가드레일 3·4 가 그 안전성의 상당 부분을 레인 안으로 가져온다.
- **실행기용 래퍼 스크립트를 새로 만든다** — 기각. 자문 래퍼의 중립 cwd 가 실행기에서는
  반대로 뒤집혀 같은 배포 본문이 자기모순이 된다. `model-orchestration` 에 `scripts/` 가
  생기면 OpenCode 에서 그 스킬의 권한 등급도 바뀐다.
- **외부 호출을 확인하는 훅을 신설한다** — 기각. 이 리포는 되돌릴 수 없는 것만 서버 규칙으로
  막고 로컬 차단 훅을 더 얹지 않는다.
- **`external-model-consult` 에 OpenCode 를 자문 provider 로 추가한다** — 기각. 그 스킬의
  중심 약속(저장소 미노출)을 지킬 수단이 없다.

## Consequences

- **새 신뢰 경계가 생긴다.** 저장소 코드가 제3자 제공자 세션에 도달할 수 있다. 되돌릴 수 없다.
  가드레일은 프로즈와 테스트이지 기계적 차단이 아니다 — 이 한계를 그대로 적어 둔다.
- 배포 본문에 **구체 모델명·티어명을 쓰지 않는다.** 이슈가 예로 든 모델 중 일부는 작성자 머신에도
  없었다. 위생 게이트가 로컬 설정에서 파생한 모델 id 누출을 막는다(로컬 실행 한정 — CI 에는 그
  설정이 없다. CI 에서 상시 무는 것은 슬라이스 기반 모델 슬러그 검사 쪽이다).
- 상주 비용 증가 **0** — frontmatter 를 손대지 않으므로 descriptor 토큰이 그대로다. 본문 증가는
  발화 시에만 비용이 된다.
- **미검증**: 외부 CLI 실동작·인증. 그리고 이 문장들이 실제 위임 행동을 바꾸는지도 측정하지
  않았다 — 문면·배선 판정이다.
