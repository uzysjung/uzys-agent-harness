# ADR-075: 이번 선택이 밀어낸 자산은 지울지 묻는다

- Status: Accepted
- Date: 2026-08-17
- PR: #314

## Context

사용자 질문에서 출발했다 — *"에이전트가 추가되는 툴을 설치하는 경우에 기존 agent 설치된 항목에
대해서 유지할지 삭제할지 물어보면 어떨까?"*

빈 프로젝트로 실측했다:

| 단계 | `.claude/agents/` |
|---|---|
| ① ECC 없이 설치 | 9개 (그중 4개가 `applies: (s) => !s.withEcc` **폴백**) |
| ② `--with ecc-plugin` 추가 설치 | **여전히 9개** |
| ③ `update` | **여전히 9개** |

`ecc-plugin` 을 고르면 폴백 4종은 manifest 상 설치 대상에서 빠진다. 그런데 **이미 깔린 파일은
아무도 안 지운다** — install 은 안 깔 뿐이고, `pruneOrphans` 는 `templates/` 에 원본이 있으면
손대지 않는다(그쪽 판정 기준은 "폐기됐는가"이지 "이번에 안 깔리는가"가 아니다).

결과는 **같은 일을 하겠다는 에이전트가 두 벌**이다. ECC 는 자기 `code-reviewer.md` 를 들고
오므로 이름까지 겹친다. 비용은 `build-error-resolver` 83 + `code-reviewer` 68 +
`security-reviewer` 90 + `silent-failure-hunter` 46 = **~287 tok/세션**, 영구. 그리고 화면은
이 사실을 한 번도 말하지 않았다.

## Decision

**설치가 밀어낸 자산이 디스크에 남아 있으면 위저드가 지울지 묻는다.** 묻지 않고 지우지 않고,
0건이면 화면을 띄우지 않는다.

### 판정식 — 이름을 열거하지 않는다

`ecc` 를 코드에 적으면 그게 두 번째 하드코딩 사본이 되고, 다음에 같은 형태(플러그인 ↔ 폴백)가
생기면 그때 또 같은 파일을 고쳐야 한다. 그래서 **manifest 가 답하게 한다**:

| 조건 | 뜻 |
|---|---|
| ① 디스크에 있다 | 실제로 사용자 저장소를 차지하고 있다 |
| ② 이번 spec 에서 `applies() === false` | 이번 선택이 밀어냈다 |
| ③ install log 해시가 일치 | **하네스가 깔았고 사용자가 안 고쳤다** |

③ 이 삭제 제안의 유일한 근거다. `pruneOrphans` 와 **같은 술어**(`isHarnessOwned`)를 쓴다 —
소유 판정이 두 벌이 되면 한쪽이 백업한 것을 다른 쪽이 조용히 지운다.

원인 표기도 열거하지 않는다. **반사실로 판정한다**: 고른 자산을 하나씩 빼 보고 밀려남이
줄어들면 그것이 원인이다. 안 짚이면 지어내지 않고 일반 문구로 떨어진다.

### 함께 정한 것 셋

1. **비대화형은 보고만 한다.** `--track` 플래그 설치에는 물어볼 사람이 없고, 물어보지 않은
   삭제는 승인 없이 넘은 경계다(전역 원칙 6). 대신 `superseded — kept` 행으로 사실을 낸다.
2. **ESC 는 "예"가 아니다.** 삭제를 묻는 화면에서 취소는 확인 단계로 되돌린다 — `null` 과
   `false` 를 나누는 이유가 이것이다.
3. **지운 것과 남긴 것을 둘 다 화면에 낸다.** 지운 것을 안 알리면 사라진 파일을 못 쫓고,
   남긴 것을 안 알리면 에이전트가 두 벌이라는 사실이 계속 안 보인다.

## Alternatives

- **알림만 하고 안 지운다** — 기각. 사실은 정직해지지만 ~287 tok/세션이 그대로 남고, 사용자가
  `uninstall` 인자를 직접 조립해야 한다. 애매할 때 묻는다는 결론과도 어긋난다.
- **묻지 말고 자동 정리** (`pruneOrphans` 규율 그대로) — 기각. 폐기된 룰과 다르다: 이 4종은
  `templates/` 에 멀쩡히 살아 있고 ECC 것과 우리 것을 **둘 다 쓰고 싶은 사용자가 있을 수 있다.**
  하네스가 "불필요"라고 선언한 것은 맞지만 그 선언이 사용자의 의도를 대신하지 않는다.
- **위저드에 정리 전용 페이지 추가** — 기각. 대부분의 설치는 후보 0건인데 페이지는 항상 존재하게
  된다. 후보가 있을 때만 뜨는 확인 하나가 같은 일을 한다.

## 적용 범위

위저드 설치 경로(`fresh`·`add`·`reinstall`) · 설치 화면의 두 보고 행 · `InstallSpec.cleanSuperseded`.

**범위 밖 셋** — 전부 사유가 있다:

- **`update`** — 무엇을 골랐는지 다시 묻지 않는 명령이다. 밀려남 판정은 사용자가 옵션을 고르는
  자리의 것이다.
- **트랙이 바뀐 경우** — 트랙을 바꿔서 안 깔리게 된 것과 옵션을 골라서 밀려난 것은 **원인이
  다르고, 원인이 다르면 문구도 달라야 한다**(`installedNew` vs `restored` 와 같은 규율). 게다가
  트랙 제거는 위저드가 *"Track removal is not automated"* 로 **자동화하지 않겠다고 이미 선언한**
  영역이라, 여기서 슬쩍 자동화하면 그 선언이 거짓이 된다.
- **디렉터리 자산(스킬)** — 스킬 디렉터리 안에는 사용자가 자기 참고 파일을 넣는다. ADR-046 이
  "스킬은 지우지 않는다"로 이미 판정했고 그 판정을 여기서 뒤집을 이유가 없다.

## Consequences

- **`ecc-plugin` 을 고른 사용자의 상주가 ~287 tok/세션 줄어든다** — 정리를 고른 경우에만.
- **백업을 남기지 않는다.** 후보 판정이 이미 해시 일치(= 사용자가 안 고침)를 요구하므로 지우는
  내용은 `templates/` 에 그대로 있고, 그 자산 없이 재설치하면 돌아온다. 사용자가 고친 파일은
  애초에 후보가 아니다.
- **삭제 실패는 삼키고 `kept` 로 보고한다**(read-only 등). 정리는 설치의 목적이 아니라 뒷정리라
  여기서 던지면 성공한 설치가 실패로 보고된다 — 대신 못 지운 사실이 화면에 남는다.
- **구조 자산 가드는 지금 도달하지 않는다.** `classifyBaselineTarget` 검사가 실제로 무는 대상은
  `.claude/commands/uzys/*.md` 인데 `templates/` 에 원본이 0개다(ADR-073 이 남긴 선재 결함).
  변이 대조에서 그 가드가 살아남았고, 테스트에 **특성 기록**이라고 명시했다 — 게이트인 척하지
  않는다.
- **중복 가드 하나를 걷어냈다.** 초안은 스킬을 `entry.type !== "file"` 와 `policyKey` 둘로 막았고
  **변이에서 둘 다 살아남았다** — 서로를 가려 어느 쪽도 게이트가 아니었다. 필요한 하나만 남기니
  같은 변이가 7건을 red 로 만든다.
