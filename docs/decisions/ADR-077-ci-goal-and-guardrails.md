# ADR-077: CI 의 목표는 "고른 것을 그대로 받는가" 하나다

- Status: Accepted
- Date: 2026-08-27
- PR: #368
- Epic: #366 · 첫 수 #367

## Context

사용자 지시(2026-08-27): *"CI를 왜 하는지 명확한 목표를 설정하고, 가드레일을 정해 내가 무엇까지는
완벽히 커버하겠다. 의미 없는 CI 하지말자."*

이 저장소의 CI 는 테스트 1,525개를 돌린다. 그런데 **최근 사용자에게 도달한 결함 3건이 전부 CI 초록인
채로 나갔다.**

| 결함 | 누가 잡았나 |
|---|---|
| #343 다른 도구로 스킬을 받아 둔 프로젝트에서 설치 전체 실패 | **실사용자 신고** |
| #344 Codex·OpenCode·Antigravity 에 기본 자산이 한 번도 안 감 | **사용자 발견** |
| #340 같은 스킬이 두 판본으로 설치 | 독립 리뷰 |

그리고 그것을 잡을 수 있었던 도구는 **이미 있는데 아무도 안 돌린다** — `test/docker/scenarios/`
19개 중 `scenario-realcli-*.sh` 셋이 실 CLI 의 자산 인식을 본다. `.github/workflows/` 안의
`docker` 매치는 **주석 한 줄**이 전부다(전수 열거 확인).

같은 날 `v26.148.0` 릴리즈에서 `ci` 워크플로가 발동하지 않아 게시가 조용히 빠졌다(GitHub Actions
major outage). 같은 push 에서 `install-matrix` 는 정상 실행됐다 — **부분 발동**이라 화면에는 성공한
워크플로 하나가 보였고, 빨간불이 아니라 *아무것도 없음*이라 조용했다.

즉 CI 의 양은 충분한데 **무엇을 지키는지가 정해져 있지 않았다.**

## Decision

**CI 는 "설치받는 사람이 고른 것을 그대로 받는가" 를 지킨다. 그 밖은 CI 의 일이 아니다.**

### 완벽히 커버하겠다고 선언하는 것

| | 가드레일 | 근거 사고 |
|---|---|---|
| **G1** | 4 CLI 각각에서 설치가 **완주**한다 (크래시 0) | #343 |
| **G2** | **고른 자산이 디스크에 실재**한다 (CLI × 자산 종류) | #344 |
| **G3** | **안 고른 것은 안 깔린다** (중복·오설치 0) | #340 |
| **G4** | 배포물에 시크릿·사설 내용 0 | #243 |
| **G5** | 검증 없이 게시 안 됨 **+ 게시가 실제로 일어났음** | v26.128~131 · 2026-08-27 |

"완벽히 커버"는 **그 축의 결함이 CI 를 통과해 나가면 그것은 CI 의 실패로 센다**는 뜻이다.
빠져나간 사례가 생기면 게이트를 고치지 말고 이 표를 다시 판정한다.

### 명시적 비목표 (CI 가 하지 않는다)

- **룰·스킬 본문의 뜻** — 이력과 판정이 맡는다. 어휘로 판정하려던 시도는 세 라운드 모두
  우회당해 폐기했다(#345 · #357, `change-management` §자산은 자기 변경 요청 없이 건드리지 않는다).
- **문서 수치의 완전 정합** — G1~G5 에 안 걸리는 정합 검사는 유지 근거가 없다.
- **커버리지 숫자 추구** — branches 88% 는 결과지 목표가 아니다.

### 적용 범위

이 저장소의 CI 에만 적용한다. 배포되는 `templates/rules/` 는 남의 프로젝트의 검증 정책이므로
바꾸지 않는다 — G1~G5 는 **우리 제품의 실패 이력**에서 나온 것이라 남에게 참이 아니다.

## Alternatives

- **지금 구성을 유지하고 테스트만 더 추가한다** — 기각. 1,525개가 이미 있고 그중 무엇도 위 3건을
  못 잡았다. 문제는 양이 아니라 **무엇을 지키는지 안 정한 것**이다.
- **G1~G5 를 지금 한 번에 구현한다** — 기각. `change-management` §자산은 자기 변경 요청 없이
  건드리지 않는다에 걸린다. 각 가드레일이 자기 이슈를 갖고 따로 착지한다.
- **게시 확인을 로컬 `npm run ci` 에 넣는다** — 기각. `npm run ci` 는 지금 네트워크 없이 돈다.
  하루 한 번이면 충분한 검사를 개발 중 매 실행에 묶으면 비용만 늘어난다.
- **게시 확인을 `publish` job 안에만 둔다** — 불충분. 2026-08-27 의 실패는 **워크플로가 안 돈 것**
  이라 그 안의 어떤 스텝도 도달하지 않는다. 그래서 스케줄 워크플로를 **함께** 둔다.

## Consequences

- **G5 가 먼저 착지했다**(#367): `release-audit.yml`(스케줄) + `publish` job 의 registry 되묻기.
  판정 스크립트는 `npm run release:audit`.
- **판정 스크립트는 실데이터로 양방향 확인했다** — 장애가 만들어 준 실제 미게시 상태에서 red,
  면제 표식을 붙이자 해당 버전만 빠지고 오늘 것은 남았다. **스케줄 배선이 실제로 도는지는
  Actions 복구 전까지 미검증**이다.
- **남은 G1·G2·G3 는 각각 이슈로 열린다.** G2 가 최대 구멍이고 효과도 가장 크다.
- 비목표 선언에 따라 **기존 테스트 중 G1~G5 에 안 걸리는 것을 걷어낼 근거가 생겼다.** 다만
  걷어낸 자리가 새는지 먼저 확인한다 — 일괄 삭제는 이 저장소가 반복해서 다친 형태다.
- 이 ADR 은 검증 **경계**를 정한 것이지 시점별 정책을 대체하지 않는다. 시점별 SSOT 는
  `.claude/rules/test-policy.md`(ADR-056/057).
