# ADR-071: 룰은 4 CLI 전부에 도달한다 — 층은 도달이 아니라 역할로 가른다

- Status: Accepted
- Date: 2026-08-12
- PR: #304
- Supersedes: ADR-070 (도달 범위로 소유권을 가르는 판정 기준)
- 관련: ADR-067(룰 최소 판단) · ADR-068(앵커 7원칙) · 이슈 #300

## Context

ADR-070 은 상주 층의 소유권을 **도달 범위**로 갈랐다. 그 판정의 전제가 실측 표였다:

| 층 | Claude Code | Codex | OpenCode | Antigravity | 도달 |
|---|---|---|---|---|---|
| 앵커 | ✅ | ✅ | ✅ | ✅ | 4/4 |
| 룰 | ✅ | ❌ | 조건부 | ❌ | 1/4 + 조건부 1 |

그래서 "모든 설치자에게 도달해야 하는 사실은 앵커가 소유한다"가 따라 나왔다. **그 전제 자체가
검토 대상이 아니었다는 것이 이 ADR 의 출발점이다.**

사용자 판단(2026-08-12): *"어떤 CLI 툴을 쓰든 제공하는 룰과 스킬로 사용자를 지원해야지. 그게
제공하고자 하는 가치인데."* 그리고 층의 역할을 이렇게 정의했다 — **룰은 대원칙이고, AI 가 그
아래에서 프로젝트별로 지켜야 할 것을 스스로 세워갈 수 있게 하는 것이 정답. 훅은 결정론적으로
반드시 강제해야 하는 것만 — AI 작업의 걸림돌이 되어서는 안 된다.**

이 관점에서 다시 재니 도달 공백은 **CLI 능력의 한계가 아니라 우리 배선**이었다. 세 CLI 모두
룰을 받을 자리가 있다(공식 문서 확인, 2026-08-12):

| CLI | 룰을 놓을 자리 | 근거 |
|---|---|---|
| Codex | 전용 디렉터리 없음 — `AGENTS.md` 계층이 유일(32 KiB 상한) | developers.openai.com/codex/cli |
| OpenCode | `opencode.json` `instructions` 글롭 — 경로 자유 | opencode.ai/docs/plugins |
| Antigravity | `.agents/rules/*.md` 워크스페이스 룰(파일당 12,000자) | antigravity.google/docs/rules-workflows |

같은 실측에서 결함 하나가 더 나왔다. **룰이 호출 지점으로 지목하는 `.uzys-agent-harness/` 의
검사 스크립트 2종도 Claude 설치에만 도달했다** — manifest 전체가 `.claude/` baseline 안에서만
돌기 때문이다. 두 entry 의 주석은 이미 "CLI 중립 슬롯"이라 적고 있었다. **의도는 주석에 있는데
배선이 그러지 않은** 형태이고, 이 저장소가 같은 형태로 두 번 다쳤다(#283 배선 없는 훅, #300).

## Decision

**층은 도달 범위가 아니라 역할로 가른다. 도달은 어느 층이든 4/4 여야 한다.**

| 층 | 역할 | 도달 |
|---|---|---|
| 앵커 | 작업 방식의 대원칙(7원칙) | 4/4 |
| 룰 | **영역별 대원칙** — 테스트 · Git · 배포 · 문서 · 변경 · 셸 | **4/4** (이 ADR 이 바꾼 것) |
| 훅 | 결정론적으로 반드시 강제할 것만 | 4/4 (별도 사이클) |
| 프로젝트 컨텍스트 | AI 가 프로젝트별로 채우고 늘려 가는 자리 | 4/4 (fill 스캐폴드, 기존) |

목적지는 **각 CLI 의 네이티브 자리**다. 한 곳에 몰아 두고 나머지가 가리키게 하지 않는다 —
CLI 마다 읽는 자리가 정해져 있고, 우리가 고른 자리를 읽어 주는 CLI 는 없다.

- Claude Code → `.claude/rules/<name>.md` (기존)
- Antigravity → `.agents/rules/<name>.md` (앵커 `uzys-harness.md` 와 형제)
- Codex · OpenCode → **프로젝트 루트 `AGENTS.md` §Harness Rules 본문 embed**

Codex 는 룰 디렉터리가 없어 `AGENTS.md` 계층이 유일한 경로이고, OpenCode 는 그 `AGENTS.md` 를
**자동으로 읽는다** — 공식 문서(opencode.ai/docs/rules: 현재 디렉터리에서 위로 올라가며
`AGENTS.md`·`CLAUDE.md` 를 찾고, `instructions` 항목은 "그 위에 더한다")와 이 저장소의 호환 실측
(`docs/research/opencode-compat-matrix-2026-04-25.md`)이 같은 말을 한다. **이 전제가 이 결정의
단일 지지대다** — 틀리면 글롭을 지웠으므로 OpenCode 룰이 0종이 된다. 실 CLI 확인은 미검증이고
Docker 격리 검증 1건이 이 사이클에서 가장 값어치 큰 후속이다.

그리고 둘은 **같은 파일을 공유**하므로 두 렌더러가 같은
본문을 넣어야 한다 — 초안은 OpenCode 만 `.opencode/rules/` 로 보내고 `instructions` 글롭으로
읽게 했는데, 그러면 `codex+opencode` 를 함께 고른 설치에서 나중에 도는 transform 이 앞선 것을
덮어써 **Codex 룰이 0종**이 됐다(독립 검증 C-1 이 실설치로 적발. 위저드 2단계가 다중 선택이라
조합은 예외가 아니라 기본 시나리오다). 한 파일을 공유하는 CLI 쌍이 있으면 목적지를 갈라서는
안 된다.

**룰 목록의 SSOT 는 하나다** — `resolveRules(spec)`. 네 CLI 가 같은 결과를 받는다. 어디에 놓을지만
각 transform 이 정한다.

ADR-070 에서 살아남는 규칙(내용 기준이라 도달과 무관하다):

2. **룰에는 앵커가 담을 수 없는 것만 남긴다** — 그 영역 고유의 구체 수단, 이 저장소가 정하는
   임계값, 실패 사례에서 나온 트리거.
3. **추상↔구체는 중복이 아니다.** 앵커가 원칙을, 룰이 그 원칙을 어기는 구체적 방법들을 열거하는
   경우 둘 다 남긴다.
4. **가리키는 줄은 넣지 않는다.** 룰을 받는 CLI 는 앵커도 항상 같이 상주한다.

폐기되는 규칙:

1. ~~모든 설치자에게 도달해야 하는 사실은 앵커가 소유한다~~ — 룰도 모든 설치자에게 도달하므로
   이 판별자는 더 이상 아무것도 가르지 못한다. 앵커와 룰을 가르는 것은 이제 **일반 원칙이냐
   영역별이냐**다.

따라온 결정 셋:

- **룰이 가리키는 도구는 룰보다 먼저 도달해야 한다.** 안 그러면 룰을 넓히는 행위가 거짓 안내를
  함께 넓힌다. `.uzys-agent-harness/` 아래는 CLI 중립 슬롯으로 확정하고, claude 미선택 설치에도
  깐다. 판정은 경로 접두사에서 derive 한다(`isCliNeutralTarget`) — 목록을 두 번 적지 않는다.
- **CLI 마다 다른 사실은 네 개를 다 적거나, 안 적는다.** `cli-development` 의 훅 차단 계약이
  Claude Code 것만 적혀 있었고, 그대로 내보내면 나머지 세 CLI 에서 거짓이 된다. 네 계약을 다
  적었다(+24 tok). 한 CLI 것만 적고 나머지를 침묵하는 선택지는 없다.
- **`update` 도 같은 계약을 지킨다.** 도달은 fresh 설치에서만 성립하면 안 된다. 세 가지를 함께
  고쳤다(전부 독립 검증이 실측으로 적발): ⓐ 위의 공유 `AGENTS.md` 문제가 update 에서도 같은
  형태로 재현됐고, ⓑ 이 릴리즈 **이전 설치자**는 새 룰 파일을 영원히 못 받았다(`refreshOnly` 가
  없는 파일을 건너뛴다) — 그 CLI 의 설치 증거를 잡았을 때만 새로 만드는 예외(`createInRefresh`)를
  뒀다, ⓒ **비 Claude 단독 설치는 `update` 자체가 throw** 했다. 판정 기준을 `.claude/` 존재에서
  **설치 존재**(install log)로 바꿨다 — 명령 계층은 이미 그렇게 판정하고 있었고 파이프라인만
  거절하고 있었다.

## Alternatives

- **앵커에 룰을 통째로 흡수** — 앵커는 이미 4/4 라 배선 작업이 0 이다. 기각: ⓐ AI 가 프로젝트별
  룰을 추가할 **자리**가 사라진다(사용자 판단의 핵심). ⓑ `cli-development` 의 `paths:` 조건부
  로드가 불가능해져 상주가 늘어난다.
- **거짓 안내 문장만 고친다(#300 의 최소 수정)** — "Claude Code 와 함께 깔았을 때만 병합된다"로
  조건을 붙이면 거짓말은 사라진다. 기각: 사용자가 도달 공백 자체를 결함으로 판정했다. 정직해진
  안내가 여전히 "당신은 룰을 못 받는다"고 말한다면 제품이 고쳐진 게 아니다.
- **Antigravity 에 glob 활성 모드로 조건부 룰 배포** — 문서가 glob 활성 모드의 존재는 말하지만
  frontmatter 문법을 공개하지 않는다. 추측해서 쓰지 않는다(원칙 1). 비 Claude CLI 에는 `paths:`
  를 벗겨 상시 룰로 보내고, 문법이 확인되면 후속에서 조인다.


## 적용 범위

- **대상**: 배포되는 룰 `templates/rules/*.md` 와 그 배선(`src/manifest.ts` · 3개 transform ·
  `templates/opencode/opencode.json.template` · `templates/codex/AGENTS.md.template`).
- **비대상**: 훅의 4 CLI 배선 — 같은 원칙이 적용되지만 **별도 사이클**이다(현 실측: Claude 5 ·
  Codex 1 · OpenCode 0 · Antigravity 0, 그리고 Codex `config.toml` 이 설치되지 않는 훅 스크립트를
  가리키는 죽은 배선 1건). 개발 사본 `.claude/rules/`(이 저장소 전용).
- **미적용**: 이 결정이 실제 모델 준수를 바꾸는지는 측정하지 않았다. 배선·도달 판정이다. 실 CLI
  가 그 자리를 실제로 읽는지도 미검증 — 호스트 실행이 차단돼 있어 Docker 격리 검증이 필요하다.

## Consequences

- **Codex · OpenCode · Antigravity 설치자의 상주 룰이 0 → 6.** 그들에게는 상주 비용이 늘어난
  변경이다. `npm run cost:report` 는 Claude Code 설치자를 기준으로 재므로 이 증가가 그 표에
  나타나지 않는다 — 계측의 사각이고, NORTH_STAR 본문에 그 사실을 적었다.
- Claude Code 설치자 기준 상주는 ~4,944 → **~4,968 tok** (+24, 전부 훅 계약 네 벌 명시).
- `playwright-launch` 룰이 `ui-visual-review` 스킬로 흡수돼 **UI 트랙 전용 룰 축이 사라졌다**
  (사용자 결정). 룰이 상주했던 유일한 이유("위반은 작업 도중 일어나 스킬 발화를 기다리면 늦다")는
  스킬 description 의 "브라우저를 여는 어떤 방법이든 그 전에 읽어라" 트리거가 흡수한다. 금지문
  소실은 `tests/browser-prohibitions-owner.test.ts` 가 막는다.
- 도달은 **문서가 아니라 실설치 산출물**로 판정된다 — `tests/resident-reach-4cli.test.ts` 가
  단독 4종 + 조합 3종 + update 4종을 실제로 돌려 **그 CLI 가 읽는 자리에** 룰 본문 canary 가
  있는지 확인한다. "트리 어딘가에 있다"로 재면 CLI 가 읽지 않는 자리에 내보내도 통과한다
  (독립 검증 H-3 이 변이로 실증). 음성 대조 5종 전부 red 확인.

- **`update` 의 pre-flight 를 푸는 데는 대가가 있었다.** 비 Claude 단독 설치가 `runUpdateMode` 에
  **처음 도달**하면서, 무조건 돌던 앵커 동기화가 그 사용자에게 `CLAUDE-uzys-harness.md` 와 루트
  `CLAUDE.md` 를 만들었다(독립 재검증 HIGH-1 — install 은 절대 안 하는 일을 update 가 했다).
  앵커 동기화를 **디렉터리와 로그를 함께** 보고 게이팅했다 — `.claude/` 가 있고, 로그가 claude 를
  말하거나 로그가 아예 없을 때만 돈다. 디렉터리만 보면 비 Claude 설치에 어떤 이유로든 `.claude/`
  가 있을 때 같은 증상이 돌아오고, 로그만 보면 로그가 없는 레거시 설치본의 앵커 이행이 죽는다
  (그 이행이 그 함수의 원래 목적이다 — 로그 단독 판정은 update-mode 테스트 6건이 red 로 잡았다).
  같은 이유로 **claude 설치인데 `.claude/` 가 사라진 상태**는 여전히 막는다 — 그대로 진행하면
  룰만 복원되고 `settings.json`·훅이 없는 반쪽 `.claude/` 가 남는다(M-R2).

**남은 한계 (측정했고 이번 범위에서 안 고쳤다)**

- **Codex `AGENTS.md` 가 22,233 B — 32 KiB 합계 예산의 68%.** 그 상한은 전역·루트·하위 파일의
  **합계**이고 닿으면 뒤가 조용히 빠진다. 사용자 몫이 ~10 KB 뿐이다. 게이트는 안전 마진이 아니라
  **비증가 ratchet** 으로 뒀다 — 줄이는 것은 별건이다.
- **`uninstall` 이 `.agents/` 를 회수하지 않는다.** 이번에 룰 6종이 그 고아 집합에 더해졌다
  (스킬 10종·앵커는 이전부터 그랬다). 파괴적 명령의 삭제 범위를 넓히는 것은 별도 판단이라
  이 PR 에서 하지 않았다.
- **브라우저 금지문의 도달은 1/4 이다.** `playwright-launch` 를 흡수한 `ui-visual-review` 는
  비 Claude 로 포팅되는 스킬 목록에 없다. 이 ADR 이 "도달은 어느 층이든 4/4" 를 세웠으므로
  그 원칙과 어긋나는 자리이고, 흡수 결정 자체는 사용자 판단이었다.
- **`.opencode/rules/`·`.agents/rules/` 에는 prune 경로가 없다.** 다음에 룰을 없애면 Claude
  사용자는 update 로 지워지고 나머지는 폐기된 룰을 계속 상주시킨다. 현재 무증상.
