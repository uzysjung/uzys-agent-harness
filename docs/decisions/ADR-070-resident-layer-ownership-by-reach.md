# ADR-070: 상주 층의 소유권은 도달 범위가 정한다

- Status: Accepted
- Date: 2026-08-11
- PR: #299
- 관련: ADR-067(룰 최소 판단) · ADR-068(앵커 7원칙) · 이슈 #289

## Context

`doc-governance` 의 첫 줄은 **"한 사실은 한 곳에. 같은 내용을 두 문서에 쓰지 않는다 — 한 곳에
두고 나머지는 가리킨다"** 인데, 이 저장소가 파는 상주 문서가 스스로 그것을 어기고 있었다.
같은 사실 4건이 배포 앵커와 배포 룰 2종에 흩어져 있었고 하나는 3중이었다(#289).

그런데 "그럼 어느 쪽을 지우는가"에서 이슈 본문이 **자기모순**이었다. 본문의 소유권 제안은
두 건을 *"`test-policy` 가 소유"* — 즉 앵커에서 지우라는 뜻 — 라 적었는데, 같은 이슈의 §주의는
*"앵커 쪽을 지우는 방향은 어느 경우에도 안 된다"* 고 썼다. 판정 근거가 없으면 다음 사람이
반반 확률로 반대 방향을 고른다.

## Decision

**상주 층의 소유권은 도달 범위가 정한다.** 실측(2026-08-11):

| 층 | Claude Code | Codex | OpenCode | Antigravity | 도달 |
|---|---|---|---|---|---|
| 앵커 (`CLAUDE.md` 본문) | ✅ | ✅ | ✅ | ✅ | **4/4** |
| 룰 (`.claude/rules/*.md`) | ✅ | ❌ | **조건부** | ❌ | **1/4 + 조건부 1** |

OpenCode 칸이 조건부인 이유(독립 검증이 실설치로 적발): `.claude/rules/` 는 `spec.cli` 에 claude 가
있을 때만 생성된다(`src/installer.ts`). **OpenCode 단독 설치는 그 디렉터리 자체가 없어**
`opencode.json` 의 `instructions` 글롭 `".claude/rules/*.md"` 가 아무것도 매치하지 않는다. 즉 룰이
OpenCode 에 도달하는 것은 **Claude Code 와 함께 깔았을 때**뿐이다. 결정의 방향은 바뀌지 않는다 —
룰의 도달이 더 좁다는 뜻이라 아래 규칙 1 이 오히려 강해진다.

배선 근거 — 비 Claude CLI 의 `AGENTS.md` 는 템플릿의 `{PROJECT_RULES}` 자리에 **앵커 본문**을
끼워 만든다(`src/codex/agents-md.ts` · `src/opencode/agents-md.ts` · `src/antigravity/transform.ts`).
룰이 아니다. OpenCode 만 `templates/opencode/opencode.json.template` 의 `instructions` 글롭
`".claude/rules/*.md"` 로 룰을 따로 병합한다. Antigravity 가 쓰는 `.agents/rules/uzys-harness.md`
는 이름과 달리 **앵커**를 옮긴 파일이다.

따라온 규칙:

1. **모든 설치자에게 도달해야 하는 사실은 앵커가 소유한다.** 룰에서 지우는 것은 안전하고,
   앵커에서 지우는 것은 Codex·Antigravity 설치자에게서 그 지시를 통째로 없앤다.
2. **룰에는 앵커가 담을 수 없는 것만 남긴다** — 그 영역 고유의 구체 수단, 이 저장소가 정하는
   임계값, 실패 사례에서 나온 트리거.
3. **추상↔구체는 중복이 아니다.** 앵커가 원칙을, 룰이 그 원칙을 어기는 구체적 방법들을 열거하는
   경우 둘 다 남긴다. 예: 앵커 *"Do not weaken or silently omit criteria"* ↔ 룰 *"weakening
   assertions, deleting or skipping tests, excluding coverage, adding indiscriminate retries"*.
4. **가리키는 줄은 넣지 않는다.** 룰을 받는 2개 CLI 는 앵커도 항상 같이 상주하므로, "이건 앵커가
   소유한다"는 포인터는 읽는 사람 눈앞에 이미 있는 것을 한 번 더 적는 순수 중복이다.

## 적용 범위

- **대상**: 배포되는 상주 문서 — `templates/CLAUDE.md` 와 `templates/rules/*.md`.
- **비대상**: 개발 사본 `.claude/rules/`(이 저장소 전용) · 스킬 본문(발화 시에만 로드) ·
  루트 CLAUDE.md 스캐폴드(프로젝트 사실을 담는 층이라 축이 다르다).
- **미적용**: 이 결정이 실제 모델 준수를 바꾸는지는 측정하지 않았다. 문면·배선 판정이다.

## Alternatives

- **룰이 소유하고 앵커를 줄인다**(이슈 본문의 제안) — 기각. 도달 범위 실측이 정면으로 반대한다.
  룰은 절반의 설치자에게 존재하지 않는다.
- **양쪽에 두고 "의도된 중복"이라 적는다** — 기각. `doc-governance` 를 파는 저장소가 그것을
  면제받을 근거가 없고, 두 사본은 결국 갈라진다(이 저장소에 전례가 반복해서 있다).
- **룰에 포인터를 남긴다** — 기각(위 규칙 4). 상주 토큰만 늘고 읽는 사람이 얻는 게 없다.
- **룰을 4 CLI 전부에 배선한다** — 기각. Codex·Antigravity 의 상주 계약을 바꾸는 별개의 큰
  결정이고, #289 가 요구한 것이 아니다. 필요하면 별도 ADR 로 다룬다.

## Consequences

- 상주 비용 **4,968 → 4,908 tok/세션**(rules 1,092 → 1,032). tolerance 0 게이트가 문서 수치
  불일치를 잡아 `docs/NORTH_STAR.md` 를 함께 현행화했고, baseline 은 하향이라 ratchet 이 조여진다.
- **앵커는 한 글자도 줄지 않았다.** 이 결정은 총량 감축이 아니라 배치 규칙이다 — 줄어든 60 토큰은
  결과이지 목표가 아니다.
- 앞으로 상주 문장을 추가할 때 **"어느 층이 소유하는가"를 도달 범위로 먼저 가른다.** 넣기 전에
  나머지 층을 grep 하는 절차(ADR-067~069 사이클의 교훈)에 판정 기준이 붙었다.
- **한계**: 룰의 도달이 좁다는 사실 자체는 이 ADR 이 고치지 않는다. Codex·Antigravity 설치자는
  룰을 받지 않고, **OpenCode 단독 설치자도 받지 않는다.** 그것이 의도인지 결함인지는 별건이다.
  (부수: 한 설치가 받는 룰은 트랙에 따라 6종이다 — `playwright-launch` 는 UI 트랙 전용이라
  "7종"은 카탈로그 수이지 한 설치가 받는 수가 아니다.)
- **이 결정에는 자동 게이트가 없다.** 독립 검증이 실증했다 — 앵커가 담지 않은 지시문을 룰에서
  지우고 비용 수치만 갱신하면 전 스위트가 초록으로 나간다. 상주 비용 게이트가 무는 것은
  **수치 부기의 정합**이지 **의미 손실의 부재**가 아니다. 이 층의 판정은 사람 또는 독립 레인이
  한다는 것을 전제로 이 규칙을 쓴다.
