# ADR-084: audit-harness-fit 2판 — 판정 근거를 공식 체크리스트 인용에서 확정된 의도와 리포 실증으로

- Status: Accepted
- Date: 2026-09-13
- PR: #TBD
- Supersedes: ADR-066 (판정 루브릭 = 공식 체크리스트 우선). ADR-064 는 스킬 존재 · 전 트랙 기본 ·
  임의 프로젝트 동작 결정만 남고 판정 프레임(5단계 · 3근거)은 본 ADR 이 대체한다

## Context

1판은 상주 조종층이 "밥값을 하는지"를 **공식 문서 인용 · 차단 로그 · 계측**의 세 근거로 판정했다
(ADR-064 → ADR-066 에서 공식 체크리스트를 1순위로). 두 달 운용에서 드러난 것:

- 설치자가 실제로 겪는 문제는 "룰이 공식 5범주에 매핑되나"가 아니라 **지침끼리 충돌한다**는
  것이다 — 같은 사용자의 앞선 지시와 뒤 지시가 갈리고(2026-07-26 테스트 작성 분리 기각 vs
  앵커 잔존), 리뷰 게이트가 세 층에 다른 문턱으로 적혀 있다(#424: 모든 코드 변경 / 머지 전 /
  배포 전). 공식 체크리스트는 이런 충돌을 보지 않는다.
- 모델이 좋아지면서 **불필요해진 지침·스킬**과 **결정 이력이 상주 본문을 차지하는 것**이
  새 비용이 됐다(#425). 벤더도 같은 말을 한다 — OpenAI GPT-6 Astra 안내(2026-09-13 조회):
  *"unclear or conflicting guidance in a skill file may cause the model to pause and block work
  early"*, 그리고 스킬·`AGENTS.md` 에서 *"silent and conflicting guidance"* 를 찾으라는 프롬프트를
  제공한다.
- 1판의 인용 대조 게이트는 날조 인용을 잡은 실적이 있지만, 지키는 대상이 **인용 파일 하나**였다.
  2판에는 그 파일이 없다.

사용자가 2판 초안을 직접 작성해 첨부했다(#425, `audit-harness-fit.zip`). 본 ADR 은 그 초안을
**같은 자산 id 로 통합**하는 결정이다.

## Decision

1. **판정 근거 = 확정된 사용자 의도 + 리포 실증.** 감사 5영역: ⓐ 불필요한 질문·반복 검증을 만드는
   무조건 지시 ⓑ 지침 충돌·바뀐 결정·낡은 해석 ⓒ 증분 가치 없는 원칙·스킬 ⓓ 상주 본문의 긴
   결정 사유·이력 ⓔ 사용 장면 기준 구현·비례 검증·필요한 위임. 공식 문서 인용은 근거로 쓸 수
   있으나 **요구되지 않는다**.
2. **모드 4개를 SKILL.md 가 라우팅하고 본문은 `references/` 에 둔다**: audit(읽기 전용 제안) ·
   verification(장면 기준 검증 설계) · apply(승인된 변경만) · populate(`AGENTS.md`/`CLAUDE.md`
   프로젝트 맥락 채우기). 후보 수 상한 없음, 같은 원인은 묶어 영향도순.
3. **보존 경계는 그대로**: 필수 테스트 · 독립 리뷰 게이트 · 보안 · 데이터 보호 · 배포 승인은
   감사가 약화하지 않는다. 강한 낱말("항상"·"반드시")만으로 보호 대상이 되지 않는다.
4. `references/official-criteria.md` 와 그 **인용 원장 대조 게이트를 은퇴**한다. 남는 게이트는
   뜻을 읽지 않는 축뿐이다 — 라우터↔참조 양방향 도달 · 100줄 초과 참조의 TOC · 리포 전용 경로
   부재 · `.claude/` 미러 바이트 동일 · 카탈로그 배선.
5. 초안의 `README.md` · `evals/scenarios.yaml` 은 관리자용이라 **상주하지 않고** 디렉터리에 같이
   나간다(로드되지 않으므로 컨텍스트 비용 0).
6. 설치 후 안내(FILL 힌트)는 이 스킬이 **실제로 설치된 경우에만** populate 모드를 한 줄 덧붙인다.

## Alternatives

- 1판 유지 + 충돌 검출 절만 추가 — 기각: 판정 서열(공식 인용 1순위)이 충돌 판정과 맞지 않고,
  사용자가 "좀 이상했다"고 판정한 형태를 그대로 두는 것이다.
- 새 id 로 별도 스킬 신설 — 기각: 같은 슬롯(상주 조종층 감사)에 두 스킬이 생기고, 전 트랙
  기본 설치 결정을 두 번 내려야 한다. 초안 README 도 같은 id 통합을 권한다.
- 인용 원장 게이트를 2판 문안에 맞춰 개조 — 기각: 2판은 인용을 요구하지 않으므로 지킬 대상이
  없다. 없는 것을 지키는 게이트는 장식이다.

## 적용 범위

`templates/skills/audit-harness-fit/`(SKILL.md · references 4 · README · evals) +
`.claude/skills/` 미러 + `tests/audit-harness-fit-skill.test.ts` 재작성 + 카탈로그 description +
`docs/REFERENCE.md` · `docs/TRACKS.md` 행 + 설치 후 FILL 힌트.

**전제**: 비-Claude CLI 가 스킬 디렉터리 전체를 받는다(#431). 그 전에는 Codex · OpenCode ·
Antigravity 설치자가 라우터만 받는다 — 2판은 그 상태로 출하하지 않는다.

## Consequences

- 감사 산출물이 "범주 매핑표"에서 **"원문 양쪽 · 문제 상황 · 수정안 · 확인/미확인 경로"** 로 바뀐다.
  #426 이 첫 실전이다.
- 날조 인용을 잡던 게이트가 사라진다. 2판은 인용을 근거로 요구하지 않으므로 같은 사고의 표면이
  없다. 인용을 다시 넣는 개정이 오면 그때 게이트도 같이 돌아와야 한다 — 이 문장이 그 조건이다.
- descriptor 가 짧아진다(카탈로그 · SKILL.md). 발화 조건은 SKILL.md `description` 이 갖는다.
- `docs/research/rules-hooks-value-audit-2026-08-02/` 원장은 남는다 — 그 자체가 리서치 기록이고
  다른 문서가 가리킨다.
