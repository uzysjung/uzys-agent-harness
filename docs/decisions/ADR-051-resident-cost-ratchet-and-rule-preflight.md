# ADR-051: 상주 비용 ratchet + 룰 착지 전 pre-flight

- Status: Accepted
- Date: 2026-07-26
- PR: #255
- Related: ADR-032(비용 계측) · ADR-043/044(NSM 정의·굿하트 정정) · ADR-045(baseline 대조 절)

## Context

사용자 요청 4건 — ⓐ 재발방지가 룰을 만들 때 컨펌 ⓑ 스킬·훅의 토큰 비용 추적·정기 개선
ⓒ 배포 룰 재검증 후 불필요분 제거 ⓓ Opus 5 기준 비용대비 효과 검증.

착수 전 실측이 전제를 뒤집었다 (`docs/research/context_cost_audit_2026-07/analysis.md`):

- **달러는 제약이 아니다.** 룰은 안정 prefix 라 cache read(0.1×)로 청구된다 — tooling 트랙
  상주 ~5,877 토큰은 1,000 요청에 **$2.94**. 컨텍스트 점유도 1M 중 **0.59%**.
- 남는 비용 축은 **지시 준수율 희석**인데 **이 리포에서 측정된 적이 없다**. 그걸 재려던
  `Justified Asset Ratio`(ADR-043/044)가 미구현이다.
- 그런데 상주 비용은 **실제로 커지고 있었다** — `.claude/rules` 는 도입 이후 2.7배.

즉 ⓒ(제거)를 ⓑ(측정) 없이 하면 이 리포가 금지한 "직관적으로 별로 같다" 추정이 된다.
동시에, 기존 게이트 둘(`cost:report` 표시 · NORTH_STAR 수치 정합)은 **정확성만** 지켜서
늘어난 만큼 문서를 고치면 양쪽 다 초록불이었다 — **성장을 막는 것이 아무것도 없었다.**

## Decision

### 1. 상주 비용 ratchet (성장 게이트)

`context-cost-baseline.json` 을 커밋하고 `tests/context-cost-ratchet.test.ts` 가 트랙별 상주
비용이 baseline 을 넘지 않는지 검사한다. 올리려면 `npm run cost:baseline` 로 **같은 커밋에**
증가를 담아야 한다. 조용한 증가를 막는 것이 전부다.

- 트랙 목록은 `TRACKS` 에서 **derive** — 게이트가 커버 목록을 따로 들지 않는다.
- baseline 이 실측보다 10% 넘게 높으면 실패 — 여유를 미리 잡아 게이트를 무력화하는 것 차단.
- `harness-health-audit` §C1(economy)이 **rate(증가율)** 을 보도록 연결. 새 워크플로를 만들지 않는다.

> **정정 (v26.137.0)**: 위 문장을 처음 쓸 때 "정기 점검"이라고 적었는데 **거짓이었다** —
> economy 축은 **사람이 그 스킬을 부를 때만** 돈다. 자동 진입점은 0건이다(탐지기 canary 검증
> 완료). 연결한 것은 사실이고 주기는 없다. 겸사겸사 전제 하나도 틀렸다: "ratchet 은 per-PR"이
> 아니다 — `test.yml` 은 `on: push: tags` 뿐이라 **PR 에는 CI 가 안 돈다**. 실제 발동은
> per-release(강제) + 로컬 `npm run ci`(자발)다.

### 2. 룰 착지 전 pre-flight (`recurrence-prevention`)

2회 재발이 **자동으로 룰**이 되던 것을 관문으로 막는다. 사다리는 *강도*만 규정하고 **비용
비대칭**(룰 = 영구 상주 / 게이트 = 상주 0)을 반영하지 않고 있었다. 3질문:

1. 결정론적으로 검출 가능한가 → **가능하면 count 2 에서도 게이트로 간다.**
2. 실제로 행동이 달라지는가 → 아니면 Level 0.
3. 일반화된 것인가 → 프로젝트 사정이면 배포하지 않는다.

컨펌 시 **측정된 토큰 수와 갱신될 총합을 함께 제시**한다(추정 금지).

### 3. 배포 룰 감축 — "필요 없는 것"이 아니라 "틀린 것"만

준수율 데이터가 없으므로 필요성 판단은 하지 않는다. 대신 구조적으로 확인 가능한 3렌즈
(배포 적합성 · dangling 참조 · 중복)로 잘랐다. 결과 **−279 tokens/세션, 전 트랙 동일**.
최대 발견은 크기가 아니라 **해로움**이었다: 배포판 `git-policy` 가 이 리포의 CalVer 를
"절대 위반 금지"로 강제해, 설치자의 SemVer 프로젝트에서 에이전트가 버전 체계를 바꾸려 든다.

## 적용 범위

- **적용됨**: 트랙별 상주 총합 ratchet · 재발방지 스킬의 룰 착지 관문 · `templates/rules/` 의
  git-policy·doc-governance 감축 · Opus 5 비용 문서화.
- **적용 안 됨 (의도)**:
  - **발화(body) 비용에는 ratchet 을 걸지 않는다** — 상주와 단위가 달라 같은 상한을 쓸 수 없고,
    스킬 body 는 트리거될 때만 든다. 굿하트 구멍(ADR-044)을 다시 열지 않기 위해 판정 기준
    ("상주인가 발화인가")은 손대지 않았다.
  - **훅 stdout 비용** — 미측정. `context-cost.ts` 는 훅을 비대상으로 두는데, 훅 파일은 맞지만
    그 출력은 대화에 들어간다. 사용자의 "훅이 토큰 낭비" 전제는 **절반만 맞고**, 그 절반은 아직
    안 쟀다 (gap U-1).
  - **`MEMORY.md`** — 이 리포 상주의 약 20%인데 ratchet 밖이다 (gap U-3).
  - **룰의 필요성 판단** — `Justified Asset Ratio` 미구현이라 불가 (gap J-1).

## Alternatives

- **먼저 제거하고 나중에 측정** (사용자 원안 순서) — 기각. 근거 없는 제거는 방향만 반대인
  거짓출하다. 순서를 ⓐ→ⓑ→ⓓ→ⓒ 로 뒤집었고 사유를 사용자에게 보고했다.
- **토큰 상한을 절대값으로 고정** — 기각. 근거 없는 수치 고정 금지(NORTH_STAR §2). ratchet 은
  "지금보다 늘지 않는다"만 강제하므로 근거가 필요 없다.
- **룰 크기 순으로 자르기** — 기각. `benchmark-parity`(~936)는 UI 트랙만, `gates-taxonomy`(~173)는
  전원이 문다. 크기 ≠ 총비용.

## Consequences

- 룰을 늘리는 PR 은 **반드시 baseline 갱신을 동반**한다. 증가가 눈에 보인다.
- 재발방지 사이클이 게이트 쪽으로 기운다 — 결정론으로 표현 가능한 것은 상주 0으로 착지한다.
- 배포판과 `.claude/` 사본이 **의도적으로 갈라진다** (CalVer 는 우리 것). 기존 1:1 대조 게이트는
  doc-governance 에만 걸려 있어 영향 없다.
- ADR-045 가 공표한 "baseline 대조 절 ~246 토큰"이 상한으로 계속 작동한다 — 이 작업 중 실제로
  248·254 에서 두 번 막혀 문장을 깎았다.

## 검증

- `npm run ci` exit 0 — 1,012 tests, branches 88.37%.
- **음성 대조 3/3 사살** (ratchet): 룰에 산문 추가 → 11 실패 · baseline 에서 트랙 누락 → 실패 ·
  baseline 1.5배 부풀림 → 실패.
- **기존 게이트가 내 작업을 3회 반증했다**: NORTH_STAR 수치 정합(감축 직후) · doc-governance
  MECE 위임(H-2 수정안이 틀렸다) · 절 크기 상한(248·254 두 번). 상세 = gap.md.
