# ADR-058: 1차 지표를 하네스 경제성(양)에서 하네스 진실성으로

- Status: Accepted
- Date: 2026-07-27
- PR: (머지 시 기입)
- Supersedes: 없음 — ADR-053 의 1차 축을 **부수 축으로 강등**하되 정의·집행 게이트는 승계한다
- Amends: ADR-043(차별화 축) · ADR-053(개수 축) · ADR-054(입증 책임 방향)

## Context

메인테이너 지시 두 개가 이 결정을 열었다.

> *"uzys-agent-harness 를 만든 목적, CLAUDE.md 를 잘 작성해야 하는 목적은 개발하는 데 있어서
> 핵심 원칙을 잘 지키고 **과신해서 실수하지 않도록** 하는 룰과 원칙·절차를 **적정하게** 추가해서
> **개발 속도도 지키고 높은 품질을 안전하게 딜리버리**하기 위함이다."*
>
> *"전체적으로 너무 디테일하게 옥죄는 것만 존재한다. **뭐만 하면 다 안 된다고 하고 있다.**"*

착수 전 실측이 세 가지를 드러냈다.

**① 룰은 실수를 막은 적이 없다.** 전량 귀속 가능한 사고 기록에서 **주어가 룰·프로즈면 검출
0건**, 게이트·테스트·독립 레인·사용자면 7건이다. 반례가 결정적이다 — `cli-development` 가 세
가지를 이미 규정하고 있었는데 같은 세션에서 셋 다 깨졌고 3회차는 거짓 보고가 됐다. 룰이 실제로
바꾼 것은 예방이 아니라 **공시**였다("미검증" 22건 · "음성 대조" 21건 표기 증가). 벤더 문서도
같은 선을 긋는다 — *"Claude treats them as context, not enforced configuration."*

**② 차단 방향이 거꾸로다.** 되돌릴 수 없는 것(main 직접 커밋 · `push --force` · `reset --hard` ·
시크릿 커밋) 차단 **0건**, 되돌릴 수 있는 것 차단 3건 — 배선된 exit 2 훅은 `mcp-pre-exec`(조회) · `protect-files`(설정 파일) ·
`docker-only-realcli`(호스트 실 CLI) 셋이다. **문서 동기화(`spec-drift-check`)는 미배선이라 여기
포함되지 않는다** — 룰 문서는 그것을 차단 게이트로 적지만 실제로는 안 문다.
게다가 `permissions.defaultMode = bypassPermissions` 이고 `deny`/`ask` 규칙이 0건이다.
"짜증나는 건 다 막고 다치는 건 다 통과"가 사용자 체감의 기계적 실체다.

**③ 옛 1차 지표가 그 상태를 보상했다.** `Resident Item Count` 는 "hooks 는 컨텍스트에 안
올라가므로 제외"하는데, 같은 문서 Will 이 *"게이트/규칙/순서는 hook 으로 강제"* 를 상시 명령했다.
룰 1개를 exit 2 훅으로 옮기면 **개수·토큰 두 축이 동시에 초록**이 되면서 하네스는 더 차단적이
된다. ADR-053 의 굿하트 방어(합치기/쪼개기)는 상주 집합 *안*에서만 작동하고, 집합을 **빠져나가는**
경로는 두 축 다 못 본다.

부수로 확인된 것 — 앵커에 적힌 거짓 9건이 **1,190개 테스트 중 0건에 걸리지 않았다**. 그리고
Anthropic 공식 목표는 *"target under 200 lines per CLAUDE.md file"* 인데, `paths:` frontmatter 가
없는 룰은 같은 우선순위로 상주하므로 예산은 사실상 합계에 걸린다 — 우리 실측 **855줄**(루트 앵커 85 + `.claude/CLAUDE.md` 41 + `.claude/rules` 729), 목표의 4.3배.
야생 오픈소스 18개의 중앙값은 162줄이고, **우리 루트 `CLAUDE.md` 85줄은 정상**이다. 벗어난 것은
룰 계층이며 그중 **43%(310줄)가 프로세스 거버넌스**인데, 실측한 14개 리포에 그 범주는 grafana 의
3문장을 빼면 존재하지 않는다.

## Decision

**D1 — 1차 지표를 진실성으로 교체한다.** 무게이트 주장 수(→0) · 게이트에 물린 사실 수(→증가) ·
추출기 미파싱 토큰 수(공시). 정의와 굿하트 방어는 `docs/NORTH_STAR.md` §2 가 SSOT 다.

**D2 — 옛 축은 폐기가 아니라 부수 축으로 내리고 집행 게이트는 유지한다.**
`context-cost-baseline.json` · `context-cost-ratchet` · `north-star-cost-figures` 를 그대로 둔다.
지표를 바꾸면서 옛 지표의 처분을 안 정하면 **게이트가 옛 지표를 계속 집행한다.**

**D3 — Statement 를 메인테이너 확정 문안으로 교체한다** (2026-07-27, 후보 2 채택):

> **"필요한 틀만 남겨 AI 의 개발 생산성을 높인다."**
> 출발점 = AC 와 DOD 로 기준을 세운다 / 남기는 것 = ① 기준을 실행하는 스킬 ② 반복되는 실수를
> 줄이는 룰 ③ 심각한 실수를 막는 훅 ④ `CLAUDE.md`·`AGENTS.md` ⑤ 테스트 방법론·린트·깃 전략 틀 /
> 안 하는 것 = 생산성을 낮추는 세부 제약 / 기준선 = MCP 추가와 모델 발전을 반영해 움직인다

이로써 §3 이 2026-06-06 에 이미 *"설치 = table-stakes"* 로 판정하고 §1 만 안 고쳐 **1년 넘게
공존하던 모순**이 종결된다 — 설치는 다섯을 전달하는 수단으로 명시된다.

**②와 ③의 분리가 이 결정의 실행 축이다.** 반복되는 실수는 룰, 심각한 실수는 훅 — 위 Context ①
(룰 검출 0건 / 게이트·레인 7건)의 직접 대응물이고, D4(차단은 비가역에만)와 같은 방향이다.
되돌릴 수 없는 손상을 룰에 적는 것은 이 구분을 어기는 것이다.

그리고 **"정확"의 두 대상을 이름부터 분리**한다 — 우리 광고의 정확성(Promise=Implementation,
2차 지표) vs 사용자 산출물의 품질(1차 지표). 한 단어를 쓰면 전자의 100% 로 후자의 달성을
보고하게 된다.

*(초안 단계의 Statement — "사실을 알고 시작 + 만든 레인이 아닌 것이 잡음" — 는 **수단**을
서술한 것이라 목적 자리에 부적합했다. 그 내용은 §1 본문의 "②와 ③이 갈려 있는 것이 핵심"
문단으로 내려가 살아 있다.)*

**D4 — 차단(exit 2)은 비가역 손상에만.** 되돌릴 수 있는 것은 exit 1 경고다. 옛 Will 문안이
D1 의 굿하트 탈출구를 상시 명령했으므로 함께 고친다.

**D5 — 차단은 로그를 남긴다.** 차단 지점 7곳이 로그 0줄이라 "옥죈다"가 느낌 대 느낌으로 남는다.
이 로그가 다음 감축의 유일한 증거원이다.

**D6 — sunset 은 임계값 대신 입력부터 만든다.** 상주 항목 줄에 `근거 · 측정일 · 모델` 3필드.
없으면 게이트가 **"미측정"으로 표시**한다(차단 아님). "나중에 재평가"는 세 번 불발했다 —
HITO(3개월·판정 1회) · JAR(8일·0회) · §4.3 "분기 1회 재평가"(한 분기가 지나도록 숫자조차 미갱신).
현재 33개 룰 파일에 모델 좌표는 **0건**이다.

**D7 — §4.1 의 "감산이 기본값" 삭제.** §3 서두가 2026-07-26 에 ADR-054 로 이미 정정했는데
**판정 목록만 3개월 반대를 지시**했다. 기준은 필요성이고 방향이 아니다.

**D8 — 개수 상한(정원)은 걸지 않는다.** ADR-054 정정과 정면 충돌하고, 필요성 판정 없이 삭제를
강제하게 된다. 굿하트 방어는 상한이 아니라 **짝 지표의 절대값**으로 한다.

## Alternatives

| 안 | 기각 사유 |
|---|---|
| **옛 지표 유지 + 룰만 감축** | 지표가 감축을 **보상하지 않는다**. 룰을 훅으로 옮기면 두 축이 초록이 되면서 체감은 나빠진다 — 감축 작업이 상황을 악화시킬 수 있다 |
| **속도·품질을 직접 재기**(리드타임·hotfix 비율) | 2차 지표로는 채택. 1차로는 부적합 — 결과 지표라 *무엇을 고쳐야 하는지*를 안 가리킨다. 다만 `git tag` 에서 derive 되므로 측정 비용이 0이라 2차에 남긴다 |
| **개수 정원(예: 룰 7개 상한)** | D8. ADR-054 정정과 충돌 |
| **"게이트를 같은 PR 에 못 내면 룰을 넣지 않는다"** | 기각 — 사용자가 해소하라고 지목한 증상을 오히려 키운다. 게이트로 판정 불가능한 참(CR 분류·게이트 유형 선택 휴리스틱)이 구조적으로 배제된다. 대신 D6 의 "미측정 표시"로 대체 |

## 적대적 다면 리뷰 (2026-07-27, 5 페르소나 + 최종 검증 1)

**산출물 보존 상태 — 정직하게.** 패널은 워크플로 서브에이전트로 돌았고 각 페르소나의 전체
반환값은 실행 저널에 남아 있다(`~/.claude/projects/<session>/subagents/workflows/`).
**리포에는 커밋하지 않았다** — 다른 프로젝트 사실이 섞여 있어 배포물 위생 게이트
(`templates-distribution-hygiene`)가 잡는 유형이다. 따라서 아래 표는 **요약이며 1차 증거가
아니다.** 후속 검증 레인이 대조할 원본이 필요하면 저널을 열어야 한다.
표 안의 수치 중 재현 확인된 것 = 974줄(`templates/**/rules`) · 33개 룰의 모델 좌표 0건.
재현 실패한 것 = **자산 184개**(셈법 불명) · **12.7초**(실측 13.9~17.0초). 그 둘은 인용으로만
남기고 판정 근거로 쓰지 않는다.

| 페르소나 | 핵심 공격 | 처리 |
|---|---|---|
| 경쟁 진영 전략가 | 설치·4-CLI·큐레이션이 전부 1st-party/무료 표준에 있고, `vetted = star≥1000` 은 Snyk 가 *실패하는 방어*로 지목한 형태 | **채택** — Pillar 2 를 안전 축으로 축소하고 `vetted` 문구는 사용자 결정 대기. 4-CLI 축은 openDecision |
| 낯선 신규 사용자 | 974줄을 거절할 방법이 없는데 문서는 거절 가능하다고 말함. `session-start.sh` 가 무승인 `git pull --rebase` | **채택** — 배포판 4건 정리는 사용자 승인 완료, 별건 실행 |
| 헤비 사용자 | 속도를 죽이는 건 훅이 아니라 왕복. 12.7초 기계 검증 위에 서브에이전트 5회+. 레인 분리에 문턱 문장 없음 | **부분 채택** — 문턱은 적대 패널에만 있고 4레인 자체엔 없다. `.claude/CLAUDE.md` 개정은 ADR-055 범위라 별건 |
| 모델 발전 회의론자 | sunset 은 구현 0·임계값 0. 33개 룰에 모델 좌표 0건. "완화"는 3개월 0건이고 룰은 +144% | **채택 → D6** |
| 유지보수 관리자 | 자산 184개 중 89개(48%) 30일+ 방치. 릴리즈 하루 1.85회인데 체크리스트 12항목 = 산술적 불가 | **부분 채택** — 케이던스 vs 체크리스트는 openDecision |
| **최종 검증** | ⓐ 패널 증거 미첨부 ⓑ **ADR-055 를 인용 없이 되돌림** ⓒ 개수 정원 충돌 ⓓ "게이트 없으면 금지"가 옥죔 증가 ⓔ UCC 측정 타당도 구멍 | **전부 반영** — ⓐ 이 표 ⓑ 9절은 **루트 `CLAUDE.md`(ADR-055 범위 밖)** 에만 적용 ⓒ D8 ⓓ 위 Alternatives ⓔ 미파싱 토큰 공시 |

## Consequences

1. **감축이 지표에 보상된다.** 옛 축에서는 룰→훅 이동이 개선으로 보였으나, 새 축에서는 훅에 적힌
   주장도 주장이라 탈출구가 없다.
2. **새 축은 아직 미구현이다.** 추출기·게이트가 없으므로 현재 값은 **미측정**이다. 선언 ≠ 달성 —
   이 리포는 그 구분을 두 번 어겨 지표를 죽였다.
3. **문서가 짧아지지 않았다** (339 → 383줄). 이력 격리로 −60 줄, 새 지표 근거로 +104 줄. 감축은
   별건이며, 이 ADR 은 *무엇을 재는가*만 바꾼다.
6. **마찰 축은 이 커밋에서 0 이다** — 독립 검증 레인 판정: exit 2 차단 7곳 무변경 ·
   `permissions.deny`/`ask` 0건 무변경 · 룰 12개 729줄 무변경. 오히려 루트 앵커가 38 → 85줄로
   늘었다. **D4 는 선언 즉시 자기 위반 상태**다(되돌릴 수 있는 것 6곳이 여전히 exit 2). 후속을
   `docs/plans/harness-direction-2026-07-27-todo.md` 에 등재했다 — 등재하지 않으면 다음 세션이
   "선언했으니 됐다"로 읽는다(HITO·JAR·분기 1회 재평가가 그렇게 죽었다).
4. **차단 로그(D5)가 없으면 D6 의 sunset 증거가 만들어지지 않는다.** 순서상 로그가 먼저다.
5. **`Resident Justification Rate` 는 표에서 내려갔다.** sunset 3필드가 같은 일을 더 구체적으로
   한다. 옛 문단은 archive 로 보냈다 — 표에 없는 지표를 본문이 설명하면 죽은 참조가 된다.
