# ADR-113: 옛 기록 외부 스킬의 파일 목록은 덮은 폴더부터 잇고, 일부 폴더만 말한다는 표지를 둔다

- Status: Accepted
- Date: 2026-10-25
- PR: #916
- Issue: #912 (앞 PR #906 · #902)
- 설계 = `docs/plans/legacy-skill-list-coverage-912-design.md` (규칙 · AC · 검증 반영의 SSOT — 여기는 요약)

## Context

옛 판(v26.163.0 이하)으로 깐 외부 스킬은 설치 기록에 파일 목록(`files`)이 없다. 그래서 상류가 바뀔 때마다 update 가 바뀐 도구 파일을
"no file list on record" 백업으로 쌓았다. 실행이 일부 폴더만 새로 쓰고 목록을 적으면, 읽는 쪽이 `files` 를 "자산의 모든 폴더를 말한다"
로 읽어 덮지 못한 폴더의 옛 도구 사본을 설치자 파일(displaced)로 적고 `uninstall --only` 가 낡은 판을 되살렸다(#906 회차 0 · 1).
"모든 사본 자리를 덮었나"를 판정하는 길은 `uninstall --cli` 뒤에 남은 사본을 실행이 알 수 없어 깨졌다.

## Decision

1. `InstallLogAsset` 에 선택 표지 `filesPartial?: true` — `files` 는 **자기 항목이 든 스킬 폴더**(`<root>/<name>`)만 말하고 그 밖 폴더는
   "모름"(`files` 없음과 같은 처리)이다. 표지 없는 `files` 는 지금처럼 모든 폴더를 말한다. `INSTALL_LOG_VERSION` 은 올리지 않는다.
2. 쓰기(install · update 가 함께 쓰는 `buildAssetEntries`)는 폴더 단위다. 이미 목록이 말하는 폴더는 지금 병합(`mergeToolFiles`)을 그대로
   탄다. 모름인 폴더는 hold 가 호출 전에 그 폴더의 파일을 하나도 남기지 않고 비켜 두었고 도구가 이번에 그 폴더에 썼을 때만 "덮은
   폴더"로 목록에 든다(같은 바이트라 제자리로 돌린 파일 포함). 판정 근거는 hold 가 아는 사실이고 디스크 존재가 아니다(ADR-096).
3. 읽는 쪽(hold 의 모름 자리 · uninstall · 선택 화면 · 뺀 자산 판정)은 표지가 있으면 목록 밖 폴더를 지금의 "모름" 처리로 다룬다.

## Alternatives

- 모든 사본 자리를 덮었을 때만 목록(이슈 1안) — 실행은 "모든 사본 자리"를 알 수 없다(#906 회차 1).
- 디스크로 사본 자리를 세어 판정 — 디스크 존재를 근거로 쓰게 된다(ADR-096), 링크 · 대소문자 무시 볼륨에서 틀린다.
- 덮은 폴더 목록을 따로 적기(`filesSlots`) — `files` 에서 언제나 유도되는 값이라 동기화할 둘째 목록만 는다.
- 목록을 자리별 맵으로 바꾸기 — 읽는 쪽 전부와 옛 · 새 기록 두 갈래를 고쳐야 한다.

## Consequences

- 옛 기록 설치본은 도구가 한 번 새로 쓴 폴더부터 목록이 있는 설치본과 같이 동작한다(update 백업 잡음이 첫 회로 끝난다).
- 덮지 못한 폴더는 지금처럼 백업만 하고 되살리지 않으며 uninstall 이 남기고 알린다.
- 표지를 모르는 판(v26.176.0 이하)이 이 기록을 읽으면 `files` 를 모든 폴더로 읽어 덮지 못한 폴더의 옛 도구 파일을 displaced 로 적을 수
  있다(설치자 바이트 손실은 없다 — 남는 것은 낡은 도구 파일 한 벌). 현실 경로는 커밋된 기록(ADR-100)을 옛 판 팀원이 update 하는 것 —
  CHANGELOG 에 "팀원은 같은 판 이상으로" 한 줄을 둔다. 옛 판의 `install` 한 번은 표지를 지워, 그 뒤에는 새 판 update 도 같은 결과를 낸다
  (상한은 같다 — 설계 §남는 위험).
