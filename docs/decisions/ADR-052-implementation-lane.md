# ADR-052: 설치본에 구현 레인을 신설한다

- Status: Superseded
- Date: 2026-07-26
- PR: (이 브랜치)
- Superseded-by: ADR-054 (상위 원칙 "만든 레인은 자기 산출물을 판정하지 않는다")

> **자산·배선은 폐기되지 않았다.** `templates/agents/implementer.md` · `DEV_AGENTS` 배선 · 모델
> 선택 · 종료 조건 계약은 **유효하며 ADR-054 가 그 현행 소유자**다. 본 ADR 에서 폐기된 것은 위임
> 문안 3점뿐이다 — ⓐ 누가 종료 테스트를 쓰는지 미규정 ⓑ "Keep the Deciding" 이 설계와 검증을 같은
> 액터에 남김 ⓒ *"dev tracks ship an `implementer` agent"* 가 임베드를 타고 non-claude 앵커에
> 거짓으로 배송됨. 상세는 ADR-054 `## Decision`.

## Context

"같은 모델·같은 CLI 인데 어떤 프로젝트는 알아서 일을 잘한다"는 관찰을 설명하려고, 두 코퍼스의
세션 트랜스크립트를 실측 대조했다(20에이전트 포렌식, 84세션). **12개 가설 중 9개가 반증됐다** —
죽은 것들의 공통 사인은 "제품 앱 vs 설치 도구"라는 도메인 차이를 하네스 차이로 오독한 것이었다.

결정적 반전은 이것이다: 성과 프록시가 좋은 쪽의 하네스가 **더 얇고 여러 곳이 깨져 있었다**
(훅 0, evals 3.7개월 정지, 라우팅표가 실재하지 않는 스킬 3개를 지목, 같은 규약이 두 문서에서
정반대로 기재). 그런데 revert 0/673 커밋, 프로덕션 장애 기원 fix 2~3%. **"두꺼운 하네스 → 좋은
결과" 화살표를 이 코퍼스는 지지하지 않는다.** 위생도 마찬가지다 — 링크가 끊긴 채로도 성과가 났다.

반증을 통과한 차이는 둘뿐이었다.

| 차이 | 실측 | 이식 |
|---|---|---|
| 모델 밖 기준점 (배포된 화면을 사용자가 보고 말함) | 도메인 어휘 39 vs 2 · 프로세스 어휘 9 vs 71 | **불가** — 도메인의 정의 |
| **구현 레인** — 서브에이전트가 코드를 쓰고 테스트로 닫는다 | 서브 코드 Edit **433 vs 3** · 버스트 종결률 **98.3%** · 평균 종결 거리 **2.27** · 검증 없는 커밋 **0** | **가능** |

우리 쪽 13.2% 종결률은 규율 실패가 아니다 — 서브에이전트가 코드를 안 고치니 테스트가 안 붙는
것이라 **비교 대상이 아니라 빈 자리**다. 배포되는 `templates/agents/` 8종은 전부 검토·검증·도메인
특화라, 설치자는 **코드를 볼 사람 8명을 받고 쓸 사람은 0명**을 받는다.

## Decision

`templates/agents/implementer.md` 를 신설하고 `DEV_AGENTS`(dev 트랙)에 배선한다. 계약은 하나다 —
**종료 조건 = 이 변경을 무는 테스트가 green**(변경을 되돌리면 빨간불이 되는 테스트여야 한다).
테스트를 못 붙였으면 완료로 보고하지 않고 무엇이 풀리면 닫히는지를 적어 넘긴다.

`templates/CLAUDE.md` 에 위임 절을 추가한다. 파일만 두면 불리지 않는다 — 실측에서 전용 레인이
32%를 가져간 쪽과 `general-purpose` 가 75%를 가져간 쪽의 차이가 그것이다. 다만 **에이전트가 없는
트랙에서도 참인 문장**이어야 한다(아래 Consequences).

## Alternatives

- **룰에 "구현을 위임하라"만 넣는다** — 지목할 대상이 없으면 `general-purpose` 로 흘러가고, 그건
  이미 우리 현재 상태(75%)다. 레인의 계약(테스트로 닫기)이 어디에도 없다.
- **`CORE_AGENTS`(전 트랙)로 넣는다** — executive·project-management·growth-marketing 은 산출물이
  문서라 "테스트 green" 종료 조건이 성립하지 않는다. 지킬 수 없는 계약을 상주시키게 된다.
- **아무것도 하지 않는다** — 반증을 통과한 이식 가능 차이가 이것 하나뿐이라, 하지 않으면 이번
  포렌식에서 얻은 실행 가능한 결론이 0이 된다.
- **모델을 `sonnet` 으로 고정** — 이 레인은 반복 구현과 핵심 구현을 모두 받는다. 후자를 놓치지
  않도록 `opus` 로 두고, 조정은 호출 측 판단에 맡긴다.

## Consequences

- 상주 비용 **+235 tok/세션**(agent descriptor +109 · CLAUDE.md +126). `context-cost-baseline.json`
  ratchet 이 이 증가를 실제로 차단했고(첫 실전 발동), 규율대로 같은 커밋에서 baseline 을 갱신했다.
  같은 작업에서 룰 재배치로 −188 을 확보해 tooling 순증은 +47 이다.
- **ratchet 이 부수적으로 설계 결함을 드러냈다.** `executive` 트랙까지 실패한 것이 신호였다 —
  그 트랙엔 에이전트가 안 깔리는데 `CLAUDE.md` 는 전 트랙에 나가므로, 설치자가 **존재하지 않는
  대상에 위임하라는 지시**를 받게 된다. 같은 세션에 닫은 CRITICAL 과 동일한 실패 양식이라,
  문구를 "없으면 범용 서브에이전트에 같은 계약으로"로 고쳐 두 경우 모두 참이 되게 했다.
  교훈: **쪼갤 때 확인할 것은 파일 존재가 아니라 설치 조건이 같은 술어인가**다.
- **미측정**: 모델이 이 레인을 *자발적으로* 고르는 비율. 트랜스크립트에 스킬/에이전트 활성화 사유
  마커가 없어 포렌식에서도 미측정으로 남았다. 등록 경로(파일을 두면 에이전트 목록에 뜬다)는
  이 세션에서 확인했으나, 선택률은 배포 후 실사용 트랜스크립트로만 판정된다.
- 이 결정은 claude 트랙에만 적용된다 — codex/opencode/antigravity 는 에이전트 개념이 달라
  `templates/agents/` 가 변환 대상이 아니다. 그쪽 대응물은 별도 판단이 필요하다.
