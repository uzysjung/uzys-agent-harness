# ADR-056: 검증 실행을 시점별로 나눈다 — 커밋 없음 / 머지 영향 범위 + 독립 리뷰 / 배포 full + CI green 전제

- Status: Accepted
- Date: 2026-07-27
- PR: (머지 시 기재)
- Supersedes: — (없음. `test-policy.md` 의 *"ship/PR 전 반드시 전체 실행"* 한 줄을 정밀화)
- **개정 2026-07-27** — 초안(3단 티어: 작업 중 / **커밋 직전 full 1회** / 배포 전)을 사용자가
  머지 전에 확정 정책으로 교체했다. 아래 §Decision 이 확정본이고, 초안과의 차이·그로 인해
  약해진 축은 §개정 이력에 남긴다. **머지된 적 없는 결정의 개정이라 새 ADR 로 supersede 하지
  않고 본문을 갱신했다** — 40분 된 결정을 대체 ADR 로 남기면 어느 것이 현행인지만 흐려진다.

## Context

사용자 지시(2026-07-27):

> *"CI는 배포 전에만 돌게 해줄래? 리뷰할 때 꼭 full CI 돌 필요 없잖아. 코드 작성한 부분에 대해서만
> 테스트가 돌면 되지 않을까. 리뷰와 테스트는 다르잖아."*

기존 규약은 `ship/PR 전 반드시 전체 실행` 한 줄이라 **"작업 중"과 "배포 전"을 구분하지 않았다.**
실제로 이 세션에서 4개 레인이 각자 full CI 를 돌렸다 — 같은 사실을 4번 산 셈이다.

그러나 "그럼 항상 타깃만"으로 가면 안 되는 이유가 **실측으로** 있다:

| # | 실측 | 값 | 출처 |
|---|---|---|---|
| 1 | `npx vitest related src/manifest.ts` | **30개 파일 선택 · 4.5s** — 소스 변경엔 타깃이 유효 | 구현 레인 재실행 |
| 2 | `npx vitest related templates/CLAUDE.md` | **0개** (`No test files found`) — 문서/자산 변경엔 **도구가 못 고른다** | 구현 레인 재실행 |
| 3 | `readFileSync`/`readdirSync` 로 파일을 읽는 테스트 | **83개 중 46개 (55%)** — import 그래프 밖이라 vitest 가 연결을 못 본다 | 구현 레인 재실행 |
| 4 | 사고: `templates/CLAUDE.md` 의 `Rule 1~12` 삭제가 **건드리지 않은** `doc-governance-baseline-rule`·`resident-doc-asset-reachability` 를 깼다. full 에서만 잡혔다 | — | 설계·검증 레인 보고. **구현 레인이 재현하지 않음**(재현하려면 타 작업 단위의 미커밋 파일을 변경해야 함) |

> **정정**: 착수 지시의 *"테스트 154개 중 46개"* 에서 **분모 154 는 틀렸다.** `vitest.config.ts` 의
> `include: ["tests/**/*.test.ts"]` 기준 실제 스위트는 **83개**다(154 는 `.dev-references/` ·
> `.claude/local-plugins/**/node_modules/` 의 벤더 파일이 섞인 수로 추정). 분자 46 은 일치.
> **비율은 30% 가 아니라 55%** — 즉 근거는 약해진 게 아니라 **더 강해졌다**.

## Decision

검증 실행을 **시점(커밋 / 머지 / 배포)** 으로 나눈다. **사용자 확정 정책 (2026-07-27) 원문:**

| 시점 | 테스트 | 리뷰 |
|---|---|---|
| **커밋** | 없음 | — |
| **머지** | typecheck(전체) + 영향 범위 테스트 + 변경 파일 lint·format · 새 가드 도입 시 변이 테스트 | **독립 에이전트 리뷰 필수** |
| **배포(tag)** | 풀 테스트 + E2E + ship-checklist · **CI green 이 배포의 전제(`needs:`)** | **필수** |

축이 **테스트 하나에서 테스트 × 리뷰 둘로** 바뀐 것이 핵심이다. 초안은 "무엇을 돌리나"만 정했고
**누가 판정하는가**는 ADR-054 에 흩어져 있었다 — 확정본은 그 둘을 한 표에서 만나게 한다. 그리고
게이트가 커밋이 아니라 **머지·배포**에 선다: 커밋은 되돌리기 싸고 머지·배포는 비싸다.

**`변이 테스트` = 입력 변이** (이 리포 확정 어휘 — `docs/plans/resident-reduction-2026-07-26-todo.md` §③).
새 가드를 넣었으면 **그 가드가 읽는 입력**을 위반 상태로 만들어 빨간불을 본다. 검사 대상이 소스
코드면 그 소스를 되돌리는 **음성 대조**가 같은 자리를 맡는다. 둘은 대상이 다를 뿐 목적이 같다 —
*한 번도 실패해본 적 없는 검증은 증거가 아니다*.

**`needs:` 는 문서가 아니라 배선 요구다.** 착수 시점에는 `test.yml`(job `ci`)과 `publish.yml`(job
`publish`)이 **서로 다른 워크플로**라 `needs:` 가 성립하지 않았다 — 둘 다 `push: tags: ["v*"]` 로
독립 실행됐다. 이것이 v26.128.0~131.0 에서 `ci` 4연속 red 인데 `publish` 는 성공해 "npm 라이브"가
참이 됐던 구조적 원인이다. **이 ADR 에서 배선까지 마쳤다 — 형태와 대안 비교는 §`needs:` 배선.**

## 적용 범위

| 축 | 범위 |
|---|---|
| 파일 | `.claude/rules/test-policy.md`(근거 전문) · `templates/rules/test-policy.md`(표 + 근거 2줄) · 양 사본 `ship-checklist.md`(full 요구 지점 + `needs:` 확인 항목) |
| 레인 | 전 레인. **머지 단의 리뷰 주체는 산출물을 만들지 않은 레인**(구현 레인은 자기 산출물을 통과 선언하지 않는다 — ADR-054). 확정 정책의 "리뷰" 열이 그 의무를 이 표 안으로 끌어왔다 |
| 트랙 | **dev 트랙만** — `test-policy`·`ship-checklist` 는 `DEV_RULES`(`src/manifest.ts`)라 executive·project-management·growth-marketing 에는 **도달하지 않는다** |
| CLI | **claude 전용**(`.claude/rules/`). opencode 는 claude 를 함께 선택했을 때만 `instructions` 글롭으로 읽고, **codex·antigravity 에는 도달하지 않는다** — 룰 파일은 앵커와 달리 임베드되지 않는다 |
| 워크플로 | `.github/workflows/test.yml` 에 `publish` job 이식(`needs: ci` + 태그 가드) · `publish.yml` **삭제**. 릴리스 파이프라인은 공유 상태라 형태를 사용자에게 물어 결정했다 — §`needs:` 배선 |
| 범위 밖 | `install-matrix.yml` 트리거 조건 · 커버리지 threshold(branches 88) — **불변** |

## Alternatives

| 대안 | 왜 기각 |
|---|---|
| ⓐ 항상 full (현행) | 이번 세션에 4개 레인이 각자 돌린 낭비. 사용자가 명시적으로 기각(*"리뷰할 때 꼭 full CI 돌 필요 없잖아"*) |
| ⓑ 항상 타깃 | **문서·자산 변경에서 `related` 가 0건을 골라 오늘의 사고(실측 4)를 놓친다.** coverage gate 도 평가 불가 |
| ⓒ `related` 자체를 개선 | **원리적으로 불가.** 스위트의 55%가 `readFileSync` 로 경로를 문자열로 읽는다 — import 그래프에 간선이 없으므로 정적 분석으로 연결을 만들 수 없다. 테스트를 전부 import 기반으로 재작성하는 것은 비용이 편익을 넘고, 파일 배치 자체를 검사하는 게이트는 본래 파일을 읽어야 한다 |

## Consequences

1. **상주 순증 `+228 tok`** (tooling: 6,323 → **6,551**. **개수 축 29개 불변** — 새 파일 0).
   초안 시점이 6,439 였고 확정 정책 반영이 +112 를 더했다(배포판 문안 축약으로 -9 회수한 뒤 값).
   ratchet 이 요구하는 *"룰 대신 게이트/훅으로 착지시킬 수 있는지 먼저 확인"* 에 대한 답은
   **행마다 다르다** — 아래 2 참조.
2. **세 행 중 하나만 기계로 강제된다.** 이것이 초안과의 가장 큰 차이다.
   - **커밋 = 없음** — 강제할 것이 없다.
   - **머지** — 프로즈로만 산다. "영향 범위를 제대로 골랐나"·"독립 리뷰를 받았나"는 사후에만
     드러난다. `doc-governance` §검증 게이트의 *"안 지켜져도 아무도 안 막는다"* 와 같은 지위다.
   - **배포 `needs:`** — **유일하게 기계로 강제 가능하고, 그래서 유일하게 배선 의무가 있다.**
     "CI 를 안 봤다"를 사람이 기억하는 대신 red 면 게시가 못 일어나게 만드는 것이라, 프로즈로
     남겨 두면 v26.128.0~131.0 이 그대로 재현된다(그때도 규약은 이미 있었고 지켜지지 않았다).
     **이 ADR 에서 배선했고**(§`needs:` 배선), 회귀는 `tests/publish-needs-verification-gate.test.ts`
     가 막는다 — 워크플로를 글롭으로 훑어 `npm publish` job 을 찾고, 같은 파일 안 검증 job 에
     `needs` 로 묶였는지 + 태그 가드가 있는지를 본다. **커밋·머지 두 행은 여전히 프로즈뿐이다.**
3. **근거 서술의 `.claude/` ↔ `templates/` 비대칭은 의도된 것이다.** 배포판에는 표 + 1줄만 두고
   (설치자에게는 원칙만 필요하다), 실측 수치·사고 서사는 `.claude/` 사본이 소유한다 —
   `no-false-ship` §*"templates/ 는 배포물이다"*. 두 파일은 원래도 서로 달랐다(배포판에는
   `npm run ci`·v26.70.1·`install-matrix` 가 없다).
4. **이 ADR 을 쓰는 중에 티어의 한계가 실제로 발현됐다 — 기록해 둔다.** 구현 레인이 룰 변경 후
   *"룰 파일을 읽는 테스트"* 를 `grep -rln "rules/" tests/` 로 도출해 14개를 타깃 실행했고 전부
   green 이었다. 그러나 `npx vitest related src/manifest.ts`(30개)를 돌리자
   **`tests/north-star-cost-figures.test.ts` 가 red** 였다 — 상주 토큰이 변하면
   `docs/NORTH_STAR.md` 의 수기 수치와 어긋나는데, 그 테스트는 `rules/` 문자열을 안 써서
   grep 도출에서 빠졌다. **즉 "영향 범위"의 정확도는 도출하는 사람의 품질에 달려 있다.**
   초안에서는 이것이 *"커밋 직전 full 1회가 필요하다"* 는 근거였다. 확정 정책은 그 단을 없앴으므로
   **같은 사실이 이제는 잔여 위험**이다 — 머지 단의 "영향 범위 테스트"가 이 실패 모드를 그대로
   물려받는다. 완화책은 룰에 적었다(*문서·자산 변경의 영향 범위 = 파일을 읽는 게이트 전체,
   애매하면 전체*). **완화이지 제거가 아니라는 것을 명시해 둔다.**
5. **파생 의무**: 상주 토큰을 바꾸는 변경은 `context-cost-baseline.json`(ratchet)과
   `docs/NORTH_STAR.md` §현재 상태(수기 수치) **둘 다** 갱신해야 CI 가 green 이 된다. 전자는
   `npm run cost:baseline` 로 생성되지만 **후자는 자동 갱신되지 않는다**(스크립트는 baseline JSON
   만 쓴다). 이 비대칭이 다음 세션의 함정이 될 수 있어 명시한다.

## 개정 이력

| | 초안 (2026-07-27 오전) | **확정 (2026-07-27, 사용자)** |
|---|---|---|
| 축 | 테스트만 | **테스트 × 리뷰** |
| 커밋 | `npm run ci` **full 1회**(검증 레인) | **없음** |
| 머지 | *(단이 없었다)* | typecheck(전체) + 영향 범위 + **변경 파일** lint·format + 새 가드면 변이 테스트 · **독립 리뷰 필수** |
| 배포 | full + ship-checklist | + E2E + **CI green 이 전제(`needs:`)** · 리뷰 필수 |

**무엇이 강해졌나**: ⓐ 리뷰 주체가 표 안으로 들어와 "누가 판정하는가"가 시점마다 명시된다.
ⓑ 배포에 **기계 강제 가능한 조항**이 처음 생겼다(`needs:`) — 초안은 전부 프로즈였다.
ⓒ lint·format 범위가 "변경 파일"로 명시돼 전체 포맷 diff 가 섞이는 것을 막는다.

**무엇이 약해졌나 (정직하게)**: 커밋 단의 full 1회가 사라져 **Consequences 4 의 실패 모드가
머지 단으로 이월**됐다. 초안은 "도출이 틀려도 커밋 직전에 걸린다"였는데, 확정본에서는 도출이
틀리면 **머지까지 간다**. 룰의 완화 문구(*애매하면 전체*)와 독립 리뷰가 그 자리를 대신한다.

## `needs:` 배선 — 통합안 채택 (사용자 결정 2026-07-27)

**착수 시점 상태**: `test.yml`(job `ci`) · `publish.yml`(job `publish`) 이 **별개 워크플로**이고 둘 다
`push: tags: ["v*"]` 였다. `needs:` 는 **같은 워크플로 안의 job 사이에서만** 성립하므로 넣을 자리가
없었다. 릴리스 파이프라인은 공유 상태라 형태를 사용자에게 물었다(`CLAUDE.md` 원칙 6).

**결정**: `publish` job 을 `test.yml` 로 이식하고 `needs: ci` + `if: startsWith(github.ref, 'refs/tags/v')`.
`publish.yml` 삭제.

| 대안 | 왜 기각 |
|---|---|
| `publish.yml` 안에 `verify` job 을 두고 `needs: verify` | diff 는 최소지만 **게이트가 ubuntu 단일**이라 macOS 전용 실패가 게시를 못 막는다. v26.128.0~131.0 의 실제 원인이 **경로 파생 버그**였다 — 바로 그 부류다. 게다가 태그마다 CI 가 3회 실행된다 |
| `workflow_run` 트리거 | 태그 push 로 발생한 `workflow_run` 의 `github.ref` 가 태그가 아니게 되어 **`GITHUB_REF_NAME#v` 로 버전을 파생하는 현재 로직이 깨진다** |
| 문서만 남기고 배선 보류 | *"사람이 기억하기"* 가 유일한 방어선이 된다. v26.128.0~131.0 때도 규약은 이미 있었고 지켜지지 않았다 |

**`if:` 가드가 본질이다** — 이게 없으면 `workflow_dispatch` 수동 CI 실행이 npm 게시를 일으킨다.
통합의 가장 큰 신규 위험이고, 그래서 가드 자체가 회귀 게이트의 대상이다.

**부수 효과 (독립 검증 레인 지적)**: 옛 `publish.yml` 에는 `concurrency` 가 없었는데, 이제 publish 가
`test.yml` 의 `ci-${{ github.ref }}` + `cancel-in-progress: true` 그룹에 들어간다 — **같은 ref 를 다시
push 하면 진행 중이던 게시가 취소될 수 있다.** 태그는 보통 1회 push 라 실현 가능성이 낮고, 취소는
"잘못 게시" 보다 안전한 방향이라 그대로 뒀다. 기록만 남긴다.

**부수 효과**: `docs/plans/service-audit-roadmap.md` META-1(CalVer 태그 가드, P1)이 제안한
*"publish job 의 `needs:` 에 guard job 을 걸어 publish 전 차단"* 이 이 구조에서 한 줄로 가능해진다.
**이번 범위에 포함하지 않았다** — 별개 작업 단위다.
