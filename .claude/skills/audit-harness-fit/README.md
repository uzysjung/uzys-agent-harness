# audit-harness-fit

에이전트가 **자율적으로 방법을 선택하면서, 필요한 품질을 지키고, 적정한 시간·비용·
사람의 개입으로 사용자 목표를 달성하도록** 지침과 스킬을 정비합니다.
현재 합의와 리포의 근거를 기준으로 판단하며, `AGENTS.md` / `CLAUDE.md`의
프로젝트 맥락도 채우거나 갱신합니다.

> 달성할 결과와 지켜야 할 경계는 분명하게, 작업 방법은 상황에 맞게 선택합니다.

## 디렉터리

```text
audit-harness-fit/
├── SKILL.md
├── README.md
├── references/
│   ├── audit.md
│   ├── verification.md
│   ├── apply.md
│   └── populate.md
└── evals/
    └── scenarios.yaml
```

`SKILL.md`는 진입점입니다. 감사, 검증 설계, 승인된 적용, 맥락 채우기에 필요한
참조만 읽습니다. README와 evals는 관리·검토용이며 일반 실행의 필수 컨텍스트가
아닙니다. 별도 실행 스크립트·모델 API 키·훅은 없습니다.

## 하는 일

| 영역 | 결과 |
|---|---|
| 불필요한 질문·반복 검증 | 실제 마찰을 만드는 지시, 유용한 기본 행동과 추가 확인 조건, 유효한 근거 재사용 |
| 지침 충돌 | 양쪽 원문과 충돌 상황, 확정된 의도와 실제 구현, 적용 권한에 맞는 수정안 |
| 지침 가치·자율 선택·모델 적합성 | 유지·수정·조건 축소·보충·통합·이관·제거·보류 판단, 유용한 도구와 맥락 보존 |
| 긴 결정 사유·히스토리 | 본문과 메뉴에는 현재 지시, 긴 이력은 필요할 때 읽는 별도 문서 |
| 사용자 결과·검증·실행 경로 | 사용 장면과 핵심 계약별 충분한 증거, 상황에 맞는 검증 시점과 도구·모델·리뷰어 선택 |
| 프로젝트 맥락 | 실제 리포에 근거한 기존 스캐폴드 보완, 완료 기준과 검증 수단 연결, 미확정 정보 표시 |

전체 감사는 앞의 다섯 영역을 다룹니다. 특정 영역만 요청하면 그 범위를 유지합니다.
후보 수는 제한하지 않고 같은 원인을 묶습니다. 모든 중요한 발견을 보존하되,
설명의 깊이는 영향과 불확실성에 맞춥니다. 미확인 영역과 생략한 상세 내용은
구분해서 표시합니다.

정리만이 답은 아닙니다. 질문의 원인이 실행 위치·명령의 전제·완료 기준의 공백이면
근거 있는 맥락을 짧게 보충합니다. 지침의 길이나 검사 횟수보다 실제 결과와
총 작업 부담을 기준으로 개선안을 판단합니다.

## 사용

감사와 개선안만 요청:

```text
audit-harness-fit으로 현재 적용되는 지침과 스킬을 전체 점검해줘.
자율 선택·생산성·품질을 함께 평가하고, 제거할 절차와 보충할 맥락을 판단해줘.
후보 수를 제한하지 말고 원문·문제 상황·수정안·확인 범위를 보여줘. 파일은 수정하지 마.
```

확인한 제안 적용:

```text
audit-harness-fit의 F-02, F-04 수정안을 해당 로컬 지침 파일에 반영해줘.
기존 승인 범위와 필수 보호장치를 유지하고, 추가 권한이 필요한 변경은 분리해줘.
```

프로젝트 맥락 채우기:

```text
audit-harness-fit으로 AGENTS.md와 CLAUDE.md의 미완성 프로젝트 맥락을
현재 리포 기준으로 채워줘. 공통 원칙·import·기존 사용자 내용은 보존하고,
핵심 사용 장면과 검증 기준을 연결해줘. 확인되지 않은 내용은 미확정으로 남겨줘.
```

기존 맥락 갱신은 "프로젝트 맥락을 최신 리포와 확정된 결정에 맞춰 갱신해줘"로
요청합니다. 일반 개발 요청은 기존 개발 흐름을 유지하며, 이 스킬의 설치 자체가
전체 감사나 스캐폴드 갱신의 실행 조건은 아닙니다.

## 자율 선택과 모델 발전

검증 시점·묶음 크기·작업 분할·실행 경로는 불확실성, 영향, 피드백 속도와 비용에
맞춰 선택합니다. 빠르고 충분한 전체 테스트도, 계약 중심의 선별 검사도 적절한
선택이 될 수 있습니다. 여러 핵심 계약을 한 실행으로 입증할 수 있다면 그 증거를
재사용하며, 필수 독립 리뷰는 별도로 지킵니다.

모델이 바뀌어도 권한·보안·데이터 보호·정직한 결과 보고는 유지합니다. 프로젝트
지식은 사실이 바뀌었는지 확인하고, 특정 모델의 약점을 보완하던 절차는 현재
모델·도구와 대표 작업의 증거로 다시 판단합니다. 새 모델이라는 이유만으로
절차를 없애거나 전체 감사를 자동 실행하지 않습니다.

효과가 불확실하면 **제안 → 승인된 제한적 시험 → 채택·수정·복원**을 구분합니다.
시험은 허용된 격리 환경·도구·데이터·작업 범위에서만 진행합니다. 문서 수정 승인과
제품 과제 실행 승인은 다릅니다. 채택 조건까지 이미 승인됐다면 같은 승인을
반복해서 요청하지 않습니다. 명백한 중복 정리에는 별도 실험이 필요하지 않습니다.

상위 모델만이 대안은 아닙니다. 기존 경로를 기본값으로 재사용하되, 작업에 맞는
도구·전문 에이전트·충분한 저비용 모델·더 유능한 모델·허용된 사람 리뷰어를
선택할 수 있습니다. 위임의 이득에는 전달·검토 비용도 포함합니다.

## 배치와 기존 저장소 반영

ZIP 최상위는 `audit-harness-fit/` 하나입니다. 사용하는 클라이언트가 인식하는
스킬 디렉터리에 전체 폴더를 배치합니다. 로딩 경로는 실제 설정에서 확인하며,
압축 해제와 실제 로딩 확인은 구분합니다.

하네스 저장소에서는 기존 위치를 유지합니다.

```text
templates/skills/audit-harness-fit/SKILL.md
templates/skills/audit-harness-fit/references/...
```

기존 폴더와 먼저 비교하고 로컬 수정사항을 보존합니다. 덮어쓰기만으로 옛 파일이
삭제되는 것은 아닙니다. 예전 `references/official-criteria.md` 등 다른 문서는
참조·테스트·이력 보존 필요를 확인한 뒤 별도 판단합니다. 배포/로컬 사본이 있다면
저장소의 동기화 방식도 확인합니다.

기본 추천 설치는 기존 자산 ID를 사용하는 별도 통합 작업입니다. 이 패키지에는
설치기 코드 변경이 없습니다. 설치 후 맥락 채우기 안내는 실제 설치 여부에 맞춰
연결하고, 기존 FILL 지시와의 충돌은 통합 범위에서 정리합니다. 모든 개발 요청에
붙는 자동 감사 훅은 포함하지 않습니다.

## 검토와 제한

[행동 시나리오](evals/scenarios.yaml)는 개정한 동작을 점검할 때 선택하는 합성
사례입니다. 자동 실행기나 실행 결과가 아니며, 일반 개발 작업의 추가 게이트로
사용하지 않습니다. 권한 위반 방지뿐 아니라 유효한 다른 방법의 선택, 필요한
맥락 보충, 충분한 검증의 재사용, 제한적 시험과 품질 보존을 함께 평가합니다.

실제 비교에서는 같은 사용자 결과·완료 기준·필수 보호장치를 유지하고, 완료와
품질을 먼저 확인한 뒤 시간·비용·불필요한 질문·재작업을 비교합니다. 지침 분량이나
검사 횟수가 줄어도 필요한 증거가 사라졌다면 개선으로 인정하지 않습니다.

필수 테스트·독립 리뷰·보안·데이터 보호·배포 승인은 유지합니다. 감사는 읽기
전용이고, 적용은 명시된 로컬 범위에 한정합니다. 모델 판단은 테스트 실행 증거가
아니며, 사용 가능한 리뷰어가 없으면 필수 리뷰는 미완료로 남깁니다.

폴더·문서 형식 확인은 실제 클라이언트 로딩, 에이전트 행동, 설치기 연동 검증과
다릅니다. 이 패키지를 제공하는 것만으로 GitHub 저장소나 설치 환경이 바뀌지는
않습니다. `scenarios.yaml`의 상태는 실제 사례 실행 전까지 `not_executed`입니다.
