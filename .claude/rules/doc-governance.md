# Documentation Boundaries

- **한 사실의 기준 문서는 하나다.** 다른 문서는 같은 내용을 독립적으로 복제하지 말고 가리키거나 필요한 만큼만 요약한다.
- **그 변경을 추적하는 문서가 있으면** 코드와 추적 상태를 함께 동기화한다. 한쪽만 바꾸면 다음 세션이 완료분을 중복 작업하거나 미완분을 완료로 오인해 건너뛴다.
- 착수 시점의 미완 표기는 "안 된 것"이 아니라 **"모르는 것"**이다 — 현재 코드 상태의 증거로 쓰지 않는다. 코드를 먼저 확인하고 상태를 정정한다. 심볼이 있다는 것만으로 완료로 읽지 않는다. 못 찾았다고 착수를 보류하지는 않는다.

**이 하네스가 설치해 둔 검사기**가 있다(스스로는 존재를 알 수 없으므로 여기 적는다): `bash .uzys-agent-harness/spec-drift-check.sh` 가 추적 문서의 미완 잔존·상태 불일치를 검출한다 — 인자 없이 부르면 경고(exit 1), `ship` 인자면 차단(exit 2). **탐지 경로 밖의 문서 레이아웃은 못 본다** — 그 경우 이 룰은 프로즈로만 작동한다.
